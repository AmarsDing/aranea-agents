# 03 — 记忆演化机制

> **借鉴来源**：A-MEM（Agentic Memory, NeurIPS 2025）
> **优先级**：高
> **影响层**：L2 情景记忆、L3 语义记忆
> **最后更新**：2026-06-06

---

## 一、需求文档

### 1.1 背景

当前 L2/L3 记忆一旦写入基本静态：
- L2 Episode 写入后仅通过衰减降低权重，不会因新信息而更新内容
- L3 Fact 写入后通过 `memory_update` 整体替换，但不会自动因新记忆而更新旧记忆的上下文

A-MEM 的核心创新：**新记忆加入时，可触发已有记忆的上下文和属性更新**——即记忆网络持续精炼其理解。

### 1.2 A-MEM 的做法

A-MEM 借鉴 Zettelkasten 卡片盒笔记法：

1. **笔记构建**：每条记忆是一张"笔记卡"，包含上下文描述、关键词、标签等结构化属性
2. **链接生成**：新记忆加入时，自动分析历史记忆，建立语义链接
3. **记忆演化**：新记忆可触发旧记忆的上下文描述和属性更新

```
新记忆: "用户从 Python 转向 TypeScript"
  → 链接: 关联到旧记忆 "用户喜欢 Python"
  → 演化: 旧记忆的上下文更新为 "用户曾喜欢 Python，后转向 TypeScript"
```

### 1.3 目标

1. L3 Fact 写入时自动检测与已有 Fact 的语义关联
2. 关联的旧 Fact 自动更新上下文描述（非内容本身）
3. 建立 Fact 间的显式链接（`RELATED_TO`/`EVOLVED_FROM`）
4. 演化操作记录到 action_log（provenance）

### 1.4 功能需求

#### P0 — 必须实现

| ID | 需求 | 说明 |
|----|------|------|
| ME-P0-1 | 语义关联检测 | 新 Fact 写入时，自动检索语义相关的已有 Fact（相似度 >= 0.75） |
| ME-P0-2 | 上下文演化 | 关联的旧 Fact 自动追加上下文注释（如"后更新为..."） |
| ME-P0-3 | 显式链接 | 关联的 Fact 间创建 `RELATED_TO` 链接 |
| ME-P0-4 | 演化 provenance | 演化操作写入 action_log |

#### P1 — 应该实现

| ID | 需求 | 说明 |
|----|------|------|
| ME-P1-1 | L2 Episode 演化 | 新 Episode 可触发旧 Episode 的整合（与 Consolidator 协同） |
| ME-P1-2 | 演化链追踪 | 支持 `EVOLVED_FROM` 链接，追踪 Fact 的演化历史 |
| ME-P1-3 | 演化频率控制 | 限制单次写入触发的演化次数，避免级联爆炸 |
| ME-P1-4 | 演化开关 | MemoryRuntimePolicy 可配置是否启用演化 |

#### P2 — 可以实现

| ID | 需求 | 说明 |
|----|------|------|
| ME-P2-1 | 演化可视化 | 前端展示 Fact 的演化链 |
| ME-P2-2 | 演化回滚 | 支持撤销一次演化操作 |

### 1.5 验收标准

1. 新 Fact 写入后，语义相关的旧 Fact 自动获得上下文注释
2. Fact 间存在 `RELATED_TO` 链接，可通过 L4 图谱查询
3. 演化操作有 action_log 记录，可追溯到触发源
4. 演化不会修改 Fact 的核心内容（statement），仅更新上下文
5. 单次写入最多触发 N 次演化（可配置，默认 5）
6. `make wire && make build && make test` 全部通过

## 二、设计文档

### 2.1 数据模型

#### Fact 上下文字段

```sql
ALTER TABLE memory_facts ADD COLUMN context_note TEXT;
-- context_note: 演化追加的上下文注释，如 "后更新为: 用户转向 TypeScript"
```

#### 演化链接类型

```sql
INSERT INTO memory_relation_types (name) VALUES ('RELATED_TO');
INSERT INTO memory_relation_types (name) VALUES ('EVOLVED_FROM');
```

### 2.2 核心接口

```go
// MemoryEvolver 记忆演化器
type MemoryEvolver interface {
    // Evolve 新记忆写入后触发演化
    Evolve(ctx context.Context, newFact *Fact) ([]*EvolutionResult, error)
}

type EvolutionResult struct {
    OldFactID   string  // 被演化的旧 Fact ID
    LinkType    string  // RELATED_TO / EVOLVED_FROM
    ContextNote string  // 追加到旧 Fact 的上下文注释
    Score       float64 // 关联分数
}
```

### 2.3 演化流程

```
新 Fact 写入
  │
  ├─ 1. 向量检索语义相关的已有 Fact（top 10, score >= 0.75）
  │
  ├─ 2. LLM 判断关联类型：
  │     - 互补（RELATED_TO）：新旧信息不矛盾，互为补充
  │     - 演化（EVOLVED_FROM）：新信息是旧信息的更新/替代
  │     - 无关：跳过
  │
  ├─ 3. 对 EVOLVED_FROM 类型：
  │     - 旧 Fact.context_note += "后更新为: {新Fact摘要}"
  │     - 创建 EVOLVED_FROM 链接
  │
  ├─ 4. 对 RELATED_TO 类型：
  │     - 创建 RELATED_TO 链接
  │
  └─ 5. 写入 action_log（provenance）
```

### 2.4 与双时序模型的协同

当演化判断为 `EVOLVED_FROM` 时，应同时触发双时序模型的冲突解决：
- 旧 Fact 的 `invalid_at` 被设置
- 新 Fact 的 `valid_at` = 旧 Fact 的 `invalid_at`
