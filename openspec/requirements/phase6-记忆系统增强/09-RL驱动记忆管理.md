## 一、需求文档

### 1.1 背景

当前记忆管理策略（何时读、读多少、何时写、如何更新、如何遗忘）全部由启发式规则驱动：
- 衰减因子、半衰期、召回 topK、相似度阈值等均为手动配置
- 无法根据实际效果自动优化
- 不同用户/场景的最优策略不同

### 1.2 AgeMem 的做法

AgeMem 用三阶段 RL 训练记忆管理策略：
1. **LTM 构建**：休闲对话环境，训练识别关键信息与 ADD/UPDATE
2. **STM 控制**：重置上下文 + 干扰项，训练 FILTER/SUMMARY 保持上下文窗口纯净
3. **综合推理**：LTM 检索 + STM 管理，长程任务

### 1.3 theory.md 的观点

`theory.md` §10 明确指出：
> Rubrics-based（纯预定义规则）控制读写更新 → 思想禁锢；需要 model 驱动。
> 方案二：Prompt/SFT/RL 语言模型 + 记忆操作工具化。
> Memory Algorithm Protocol：policy 输出 Action 序列；UPDATE/DELETE 须受候选集合约束。

### 1.4 目标（长期）

1. 将记忆管理策略从硬编码规则转为可学习策略
2. 用 RL 训练记忆读写决策（ADD/UPDATE/DELETE/FILTER/SUMMARY）
3. 策略可评估、可 A/B 测试、可回滚

### 1.5 功能需求（研究阶段）

| ID | 需求 | 说明 |
|----|------|------|
| RL-R1 | 记忆操作 Action 空间定义 | 定义 ADD/UPDATE/DELETE/FILTER/SUMMARY 等 Action |
| RL-R2 | 奖励函数设计 | 基于最终答案准确率、Token 效率、记忆质量 |
| RL-R3 | 训练环境搭建 | 模拟对话环境 + 评估基准 |
| RL-R4 | SFT 基线 | 先用 SFT 训练基础策略，再用 RL 优化 |
| RL-R5 | 在线评估框架 | A/B 测试不同策略的效果 |

**纯研究阶段**，不进入开发计划。需要先完成 Phase 6A/6B 的工程化改进，积累足够的评估数据和基础设施。

## 二、研究方向

### 2.1 与 theory.md 的对齐

theory.md 提出的 **Memory Algorithm Protocol** 是 RL 训练的前提：
- policy 输出 **Action 序列**（ADD/UPDATE/DELETE/NONE...）
- UPDATE/DELETE 须受**候选集合**约束
- 召回须带 **provenance**
- 通过 **Commit** 落盘

这些约束确保 RL 策略的输出是可审计、可回滚的。

### 2.2 与 InfMem 的对齐

theory.md §11 提到的 InfMem 协议：
- **PreThink**：检索前评估内部知识是否够用 → 减少无谓检索
- **Adaptive Early Stop**：非固定 Top-K，策略网络在累积证据置信度达阈值时停止
- **SFT → RL**：直接优化检索与记忆更新决策
