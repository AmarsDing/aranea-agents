# 10 — 外挂记忆系统集成

> **借鉴来源**：Mem0（向量+图双存储）、Zep/Graphiti（双时序知识图谱）
> **优先级**：高
> **影响层**：L3 语义记忆、L4 知识图谱
> **最后更新**：2026-06-06

---

## 一、需求文档

### 1.1 背景

本项目框架层已有 `memory.Service` 接口和 8 种后端实现（含 Mem0 适配器），应用层有 L0-L4 五层模型。但：
- Mem0 适配器仅实现框架层 `memory.Service`，未与 L3/L4 应用层对接
- Zep/Graphiti 的双时序知识图谱能力无法直接使用
- 外挂系统与内置系统的数据同步和生命周期管理未解决

### 1.2 目标

1. L3 语义记忆可外挂 Mem0（向量+图双存储，生产级管线）
2. L4 知识图谱可外挂 Zep/Graphiti（双时序图谱，因果推理）
3. L0/L1/L2 保持内置实现（与 Agent 运行时紧密耦合）
4. 外挂系统与内置系统的数据可同步

### 1.3 外挂策略

```
┌─────────────────────────────────────────────────────┐
│                  Aranea-Agents 应用层                │
│  L0 审计 | L1 工作记忆 | L2 情景 | L3 语义 | L4 图谱  │
├─────────────────────────────────────────────────────┤
│              Memory Adapter Layer（适配层）           │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐            │
│  │ 内置后端  │ │ Mem0适配  │ │ Zep适配   │  ...       │
│  │SQLite+pg │ │ vector+g │ │ temporal │            │
│  └──────────┘ └──────────┘ └──────────┘            │
├─────────────────────────────────────────────────────┤
│           trpc-agent-go 框架层 memory.Service        │
└─────────────────────────────────────────────────────┘
```

**分层外挂原则**：
- L0/L1：保持内置（上下文组装和工作记忆与运行时紧耦合）
- L2：保持内置（Episode 与 Session 生命周期绑定）
- L3：可外挂 Mem0（向量+图双存储，生产级记忆管线）
- L4：可外挂 Zep/Graphiti（双时序图谱，因果推理）

### 1.4 功能需求

#### P0 — 必须实现

| ID | 需求 | 说明 |
|----|------|------|
| EX-P0-1 | L3 Mem0 适配器 | 实现 L3FactWriter/L3FactReader 接口，底层调用 Mem0 API |
| EX-P0-2 | 配置驱动后端选择 | `memory.l3_backend: internal | mem0` |
| EX-P0-3 | L3 双写模式 | 可选同时写入内置和 Mem0，内置负责实时搜索，Mem0 负责长期管理 |

#### P1 — 应该实现

| ID | 需求 | 说明 |
|----|------|------|
| EX-P1-1 | L4 Zep 适配器 | 实现 L4GraphWriter/L4EntityStore 接口，底层调用 Zep/Graphiti API |
| EX-P1-2 | 配置驱动 L4 后端 | `memory.l4_backend: internal | zep` |
| EX-P1-3 | 数据同步 | 内置与外挂系统间的数据同步机制 |

#### P2 — 可以实现

| ID | 需求 | 说明 |
|----|------|------|
| EX-P2-1 | 渐进式迁移 | 从内置到外挂的无停机数据迁移 |
| EX-P2-2 | 混合召回 | 同时从内置和外挂系统召回，融合排序 |

### 1.5 验收标准

1. `memory.l3_backend=mem0` 配置下，L3 Fact 写入和召回正常工作
2. `memory.l3_backend=internal` 配置下，行为与当前完全一致
3. 双写模式下，内置和 Mem0 数据一致
4. `memory.l4_backend=zep` 配置下，L4 图谱写入和查询正常工作
5. `make wire && make build && make test` 全部通过

```go
// L3Mem0Adapter 将 Mem0 API 适配为 L3FactWriter/L3FactReader
type L3Mem0Adapter struct {
    mem0Client *mem0.Client
    agentID    string
    userID     string
}

func (a *L3Mem0Adapter) WriteFact(ctx context.Context, fact *Fact) error {
    // 调用 Mem0 ADD/UPDATE API
    return a.mem0Client.Add(ctx, a.userID, fact.Statement, mem0.WithMetadata(map[string]any{
        "agent_id":    a.agentID,
        "fact_id":     fact.ID,
        "importance":  fact.Importance,
        "confidence":  fact.Confidence,
    }))
}

func (a *L3Mem0Adapter) ReadFacts(ctx context.Context, query string, topK int) ([]*Fact, error) {
```

```go
    ...
}
```

### 2.3 配置结构

```protobuf
message MemoryBackend {
  string l3_backend = 1;  // internal | mem0
  string l4_backend = 2;  // internal | zep
  bool l3_dual_write = 3; // 双写模式
  Mem0Config mem0 = 4;
  ZepConfig zep = 5;
}

message Mem0Config {
  string api_key = 1;
  string base_url = 2;
  string org_id = 3;
  string project_id = 4;
}

message ZepConfig {
  string api_key = 1;
  string base_url = 2;
}
```
