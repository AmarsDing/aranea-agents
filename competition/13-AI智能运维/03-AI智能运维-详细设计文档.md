## 1. 数据库设计

**全局约定**：
- 配置/治理表（1.1-1.8）位于 PostgreSQL `twinmonitor` 库；执行镜像/审计/分析表（1.9-1.16）位于 PostgreSQL `twinmonitor_log` 库。
- 各表字段表统一省略以下固定列（此处一次性声明，逐表不再重复）：主键 `id`（BIGINT 自增 / BIGSERIAL）；配置表的审计列 created_by/updated_by/deleted_by（UINT64，关联 users.id）、created_at/updated_at（TIMESTAMPTZ，默认 CURRENT_TIMESTAMP，updated_at 由触发器维护）、deleted_at（TIMESTAMPTZ，软删除）。
- 配置表遵循硬约束：软删除 deleted_at + 索引 `idx_<表名>_deleted_at`；索引名 schema 内全局唯一。
- 执行镜像/分析类表为追加型日志数据，不做软删除，保留 created_at（部分表含 updated_at），操作人以 created_by/operator_id 记录，表注释注明「执行镜像/审计，追加型」。
- 所有 ent schema 必须实现 Privacy() 数据权限与 Edge 关联（见 1.17 示例），并导入 `_ "…/ent/runtime"`；biz 层 Repo 接口以 WithTx 传播事务。
- 敏感字段（api_token_encrypted、webhook_secret_encrypted、secret_encrypted）一律 AES-256-GCM 加密落库；出参脱敏规则：`前3位 + "****" + 后4位`（长度 < 8 时全遮蔽）。

### 1.1 ai_aranea_instances（aranea 实例表 — twinmonitor）

**作用**：管理 aranea-agents 实例的接入配置与健康状态。**表注释**：aranea 实例表，服务凭据与 Webhook 密钥 AES-256-GCM 加密存储；多行设计，当前版本仅启用 1 个实例。

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| name | VARCHAR(128) | Y | -- | 实例名称 |
| base_url | VARCHAR(512) | Y | -- | aranea HTTP Base URL（如 http://aranea:8080） |
| api_token_encrypted | TEXT | Y | -- | 服务凭据密文（AES-256-GCM） |
| webhook_secret_encrypted | TEXT | Y | -- | Webhook 回调密钥密文（HMAC-SHA256 签名校验用） |
| status | VARCHAR(16) | Y | 'disabled' | 健康状态：healthy/degraded/disabled |
| version | VARCHAR(32) | N | NULL | aranea 版本（探测回写） |
| agent_count | INT | Y | 0 | aranea 侧 Agent 数（探测回写） |
| graph_count | INT | Y | 0 | aranea 侧 Graph 数（探测回写） |
| model_count | INT | Y | 0 | aranea 侧模型数（探测回写） |
| uptime_seconds | BIGINT | N | NULL | aranea 运行时长（秒，探测回写） |
| last_probe_at | TIMESTAMPTZ | N | NULL | 最近探测时间 |
| last_error | TEXT | N | NULL | 最近探测失败原因 |
| is_enabled | SMALLINT | Y | 0 | 启用标记：0-否，1-是（全表唯一，部分唯一索引约束） |

**索引**：PRIMARY KEY(id)；UNIQUE `uniq_ai_aranea_instances_name`(name)；UNIQUE `uniq_ai_aranea_instances_enabled`(is_enabled) WHERE is_enabled=1 AND deleted_at IS NULL（部分唯一索引，保证启用实例唯一）；`idx_ai_aranea_instances_status`(status)；`idx_ai_aranea_instances_deleted_at`(deleted_at)。

| avatar | VARCHAR(32) | Y | '🤖' | 头像 emoji |
| role | VARCHAR(255) | Y | -- | 角色描述（一句话） |
| category | VARCHAR(64) | Y | -- | 分类：alarm-告警处理/fault-故障处理/data_analysis-数据分析/inspection-巡检审计/server-服务器管理/operation-操作执行/document-文档报告 |
| description | TEXT | N | NULL | 详细描述 |
| system_prompt | TEXT | Y | -- | 系统提示词（种子源定义，同步至 aranea） |
| model_policy | VARCHAR(128) | N | NULL | 模型策略：aranea 模型 ID 引用（不存 LLM Key） |
| temperature | DECIMAL(2,1) | Y | 0.7 | 温度（0.0-2.0） |
| tool_whitelist | JSONB | N | '[]' | 允许调用的 MCP 工具名数组（同步至 aranea 工具装配） |
| risk_level | VARCHAR(16) | Y | 'low' | 风险等级：low/medium/high |
| tags | JSONB | N | '[]' | 标签数组 |

| is_enabled | SMALLINT | Y | 1 | 本地治理开关：1-启用，0-禁用（禁用后不可被场景/测试引用，aranea 侧不删） |
| use_count | BIGINT | Y | 0 | 使用次数（任务事件回写累计） |
| last_used_at | TIMESTAMPTZ | N | NULL | 最后使用时间 |

**关联关系**：被 `ai_agent_executions`、`ai_rca_records` 逻辑引用（agent_id）；`aranea_agent_id` → aranea Agent（经 AraneaClient 校验，Redis 缓存 5 分钟）。

### 2.2 核心组件设计

#### 2.2.1 AraneaClient（aranea 端口适配层，data 层）

biz 层依赖端口接口 `AraneaPort`（定义于 biz），data 层 `AraneaClient` 实现；aranea 具体端点路径以其 OpenAPI 契约为准，集中在该适配层，契约变更走版本化。

#### 2.2.2 WebhookReceiver（aranea 事件回写接收器）

- 端点：`POST /api/v1/monitor/aiops/webhooks/aranea`（不经网关 JWT，独立路由）。
- 处理链：HMAC-SHA256 签名校验（X-Signature 头，密钥自实例配置解密）→ event_id 幂等去重（Redis SET NX EX 24h）→ 事件路由。
- 事件类型与动作：

| 事件 | 动作 |
|------|------|
| run.started | 任务镜像 → running，写 started_at，发 `ai.task.events(started)` |
| run.node_started | upsert ai_task_nodes(running)，更新 current_node_id，发 node_started |
| run.node_output | 更新节点 output_summary（截断 2000 字），发 node_output |
| run.node_completed | 节点 → completed/failed/skipped，completed_nodes+1，发 node_completed |
| run.waiting_approval | 生成 ai_approvals(pending, aranea_interrupt_id)，任务 → waiting_approval，发 `ai.approval.pending` + waiting_approval |
| run.completed | 任务 → completed，写 result_summary/finished_at/duration_ms，发 completed |
| run.failed | 任务 → failed，写 error_message，发 failed |
| run.cancelled | 任务 → cancelled，发 cancelled |

- 处理 SLA ≤500ms；重活（如审批通知组装）异步；签名失败/未知事件写审计日志并 401/202。

#### 2.2.3 FallbackPoller（兜底轮询器）

- 30 秒周期扫描 ai_tasks 中 status ∈ (pending, running, waiting_approval) 且 aranea_run_id 非空的镜像，批量（≤10 并发）调 `GetRun` 比对状态：落后则按 §2.2.2 相同动作补齐（事件去重键 `poll:{run_id}:{status}` 防与 Webhook 重复推进）。
- 单任务连续 10 次轮询失败标记 failed（原因「aranea 状态不可达」）；服务重启后启动即扫一遍重新挂入。

#### 2.2.4 HealthProber（aranea 健康探测器）

- 30 秒周期调用启用实例 `Health`：成功回写 version/counts/uptime/last_probe_at 与 healthy；连续 3 次失败置 degraded、写 last_error、发布 `ai.aranea.health`；恢复首次成功即回 healthy 再发事件。
- biz 层执行类准入（创建任务/分析/测试）前置读取 `ai:aranea:health` 缓存：degraded 直接拒绝并提示。

#### 2.2.5 SeedSynchronizer（种子同步器）

- 触发：手动 `POST /agents/seed-sync`、实例登记后首次 healthy 自动触发一次。
- 流程：读取 is_preset=1 的 12 条本地定义 → 按 name 匹配 `ListAgents` 结果 → 缺失 `CreateAgent`、存在且定义漂移 `UpdateAgent` → 回写 aranea_agent_id/sync_status=synced/synced_at → 写 ai_sync_records(sync_type=seed)。
- 幂等可重入；单条失败不影响其余，sync_status=error 记录原因。
- 能力同步（`POST /aranea/instances/{id}/sync`）：拉取 Agent/Graph/模型清单 → 与本地镜像比对 → 新 aranea Agent 落本地目录（is_preset=0）、Graph 差异标注 sync_status=diff → 写 ai_sync_records。

#### 2.2.6 MCPServer（TwinMonitor-MCP-Server）

- 协议：MCP 2024-11-05，SSE 传输（`GET/POST /api/v1/monitor/aiops/mcp/sse`），client_id+secret 连接级认证（不解密比对，HMAC 派生校验），吊销凭证拒连并写审计。
- 工具注册：启动时将内置工具（需求 §5.9 清单，26 个静态工具）upsert 进 `ai_mcp_tools`（保留治理调整字段）；脚本启停/配置模板变更时同步注册/注销动态工具。
- 安全层（按 §9.5 顺序）：认证 → 调用方授权子集/风险上限 → 注册表启用与 grant_policy → 默认只读模式（readonly/low 放行；medium/high 需 allowed；approval 转审批中心挂起；destructive 默认拒）→ 参数 JSON Schema 校验 → 资产引用 02 HTTP 校验 → 命令类白/黑名单 → 执行（内置工具调对应模块 HTTP 客户端；script.execute_* 与 server.* 经 16）→ 写 ai_mcp_call_history（含 blocked）。
- 限流：按 client_id 60 QPS 令牌桶（Redis）；超限返回 MCP 标准错误并写历史。
- 高危工具前置审批：grant_policy=approval 的调用生成 ai_approvals(source=mcp_tool, context_summary=工具+参数摘要)，批准后异步执行并经 SSE 通知结果（或轮询取回）。

#### 2.2.7 ApprovalScanner（审批超时扫描器）

30 秒周期：Redis 有序集合 `ai:approval:expire`（score=expire_at）取到期 → DB 复核 status=pending → timeout_action=auto_reject 则置 timeout 并按拒绝路径流转（graph 来源调 aranea Resume decision=reject；mcp_tool 来源通知调用方；promotion 来源通知 14）；=continue_wait 仅发提醒事件。Redis 缺失时 DB `expire_at` 部分索引扫描兜底。

#### 2.2.8 ScheduleCron（定时任务调度器）

- robfig/cron v3 注册启用任务；到点：校验场景启用 + aranea 健康 → 幂等键 `schedule:{job_id}:{time_bucket(分钟)}` → 创建任务（trigger_type=schedule，trigger_ref_id=job_id）→ 回写 last_run_at/last_task_id/next_run_at。
- Cron 保存前校验（5 字段格式 + 可解析下次时间）；禁用即时移除注册。

#### 2.2.9 Crypto（加解密组件）

复用平台 `pkg/crypto` AES-256-GCM：加密落库字段（api_token/webhook_secret/mcp secret）写入前加密、读取后内存解密、出参一律脱敏（前3+****+后4，<8 全遮蔽）。密钥来自配置 `security.aes_key`（32 字节，环境变量注入）。

### 2.4 与其他模块对接接口细节

#### 2.4.1 14-自动修复 → 本模块（场景执行代理）

- 创建修复/验证/回滚任务：`POST /tasks`（契约见 2.3.4），trigger_type=remediation、trigger_ref_id=14 执行编号、idempotency_key=`remediation:{execution_no}:{phase}[:{attempt}]`（phase ∈ fix/verify/rollback，同阶段重复创建 attempt 从 2 起递增；本模块透明去重不解析格式）。
- 状态回流：本模块 `ai.task.events`（NATS）→ 14 消费推进其执行状态机；14 亦可 `GET /tasks/{id}` 主动查询。
- 审批承载：修复场景内 aranea 审批点经本模块审批中心处理（14 自愈工作台审批其自身执行单，两者分离见 14 文档）。
- Solution 晋升审批：14 晋升规则触发时经 `POST /approvals`（内部 gRPC/HTTP）生成 source=promotion 审批单，审批结果经 NATS `ai.task.events`（event_type=approval.promotion.result）回告 14。

#### 2.4.2 04-告警服务

- 订阅 `alarm.events`（统一信封）：级别过滤（默认 critical/emergency，可配）+ 设备类型过滤 → 触发 RCA + 自动诊断（§9.4）。
- 告警详情拉取：`GET /api/v1/monitor/alarm/events/{alarm_id}`（Redis 缓存 5 分钟）。
- 分析回流：发布 `ai.analysis.completed`，payload 含 analysis_type（rca/auto_diagnosis）/analysis_no/rca_record_id/alarm_id/severity/confidence/root_cause 摘要/aranea_run_id；04 自行回写告警字段，14 按 alarm_id + rca_record_id 关联其执行记录与 AI 修复记录。

#### 2.4.3 10-业务管理

- 知识检索（MCP `knowledge.search` 数据源）：`GET /api/v1/monitor/biz/knowledge/search?keyword=&top_k=5`；失败置 rag_degraded=1 继续。
- 沉淀写入：`POST /api/v1/monitor/biz/knowledge`（category=故障案例，tags=[AI沉淀]）→ 回写 ai_rca_records.knowledge_id。
- 工单创建（MCP `ticket.create`）/值班查询（MCP `ticket.get_oncall`）：按 10 模块既有接口契约。

#### 2.4.4 16-运维工具

- 命令执行统一入口：`POST /api/v1/monitor/opstool/exec`（同步，含超时）；调用方：脚本参数化执行、MCP server.*/script.execute_*/network.config_backup 工具、自动诊断命令集（经 MCP 安全层转发）。
- 本模块不持有任何设备凭据；命令白/黑名单本模块侧先过滤，16 侧护栏兜底（双端防护）。

#### 2.4.5 02/01/06

- 02 资产：`GET /api/v1/monitor/asset/devices/{id}`（校验+名称/IP/类型快照，缓存 5 分钟）；机柜树/别名解析供 MCP asset.* 工具。
- 01 用户：`GET /api/v1/monitor/base/users/{id}`（审批人/操作人展示名）。
- 06 数据管理：洞察看板 MTTR/降噪率/严重度分布统计接口；报告类场景产出经其导出落盘（D6 本地存储）。

| /aiops/rca/:id | RCA 详情 | 概要卡（置信度环图+严重度徽章）+ 症状/证据/时间线/建议/根因分区 + 引用列表（knowledge/memory 标记）+ aranea Trace 跳转 + 沉淀知识/执行修复入口 |
| /aiops/auto-analyses | 告警自动诊断 | 统计卡 3 张、类型分段、卡片展开（结论/命令/输出）、15s 轮询 |
| /aiops/insights | AI 洞察看板 | 业务卡 5 张 + AI 运行卡 3 张（离线标识）+ 严重度分布条形图 + 知识分类分布 + 最近洞察 |

### 3.2 关键页面交互要点

**aranea 接入管理（/aiops/aranea）**：实例卡片顶部状态徽章（healthy 绿/degraded 橙/disabled 灰）+ 版本与 Agent/Graph/模型计数；「探测」按钮 Toast 展示耗时与计数，失败展示具体原因（网络/鉴权/超时）；「同步」后打开同步记录抽屉：差异项按 direction 分色（remote_only 蓝=aranea 有本地无、local_only 紫、changed 橙），支持一键「纳管」（remote_only Agent 落本地目录）。

**智能体目录（/aiops/agents）**：卡片含头像/名称/角色/分类徽章/风险徽章/同步状态点（synced 绿、diff 橙、error 红、pending 灰）；预设 Agent 无删除入口；顶部「种子同步」按钮执行后 Toast 汇总（created/updated/failed）；禁用开关即时生效（本地治理，不删 aranea 侧）。

**Agent 测试面板**：数据库运维 Agent 显示数据库单选；其余显示服务器多选；输入框按 Agent 名预填测试语句；结果 Markdown 渲染 + 耗时 + Token + aranea run 跳转链接。

**场景模板（/aiops/scenarios）**：注册弹窗第一行「aranea Graph」下拉（数据来自同步缓存，显示 Graph 名称+节点数），选定后自动带入名称建议；参数 Schema 编辑表格（name/type/required/default/description 行内编辑）；「立即执行」弹窗按 Schema 渲染（boolean 开关/enum 下拉/number 数字/string 输入，含 server 类参数时目标服务器选择器），提交后跳转任务中心并定位新任务。

**任务中心（/aiops/tasks）**：节点进度条横向排列（completed 绿✓/running 蓝脉冲/failed 红✗/waiting_approval 橙/pending 灰）；经网关 WebSocket 订阅 `ai.task.events` 实时刷新；日志 Tab 分型着色（thinking 紫/output 蓝/success 绿/error 红/info 灰），cursor 增量加载；详情头部含 aranea Trace 外链；操作按钮按状态显隐（取消：running/waiting_approval）。

**审批中心（/aiops/approvals）**：卡片含标题/来源徽章（graph 蓝/mcp_tool 橙/promotion 紫）/风险徽章/上下文摘要（待执行命令 mono 展示）/超时倒计时（expire_at 倒计时，<5 分钟红色）；拒绝弹窗原因必填；处理完成即时移出待办 Tab。

**MCP 工具浏览器（/aiops/mcp/tools）**：行内「治理」弹窗可调整风险等级（五级下拉）、启停、放行策略（default/allowed/approval/disabled 四段选择器，approval 附说明「调用将转审批中心」）；destructive 工具默认禁用徽章。

**RCA 详情（/aiops/rca/:id）**：引用列表每项标来源（knowledge 蓝=知识库/memory 紫=aranea 记忆）；「沉淀知识」按钮成功后显示 knowledge_id 链接；「执行修复」跳转 14 模块并携带 rca_record_id；degraded 记录顶部橙色降级原因条。

**告警自动诊断（/aiops/auto-analyses）**：15 秒轮询；卡片展开四区：AI 诊断结论、已执行命令 mono 标签（退出码非 0 红色）、原始输出折叠（截断提示）、错误红块。

**AI 洞察看板（/aiops/insights）**：AI 运行卡（LLM 调用量/Token/成本/Agent 成功率）数据源离线时卡片置灰显示「数据源离线」不阻塞业务卡；全部卡片 3 秒内加载完成。
