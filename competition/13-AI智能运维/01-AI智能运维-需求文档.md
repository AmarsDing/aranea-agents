## 1. 模块概述

AI智能运维模块是 TwinMonitor 集中监控数字孪生平台的 **智能运维治理与接入层**。平台全部 AI 能力构建在外部多智能体编排底座 **aranea-agents** 之上：aranea 提供 LLM Provider 与模型目录、Agent 运行时、三层编排引擎（Team 六模式 / Graph 图编排 / Spirit 动态编排）、五层记忆（L0~L4）、全链路可观测与成本配额；本模块面向运维域提供四项核心价值：

1. **治理面**：运维智能体目录（12 个预设运维 Agent + 自定义）、场景模板（运维工作流的治理注册）、任务中心（执行镜像与审计）、人工审批（HITL）、定时调度、脚本库与配置模板等运维执行资产的全生命周期管理。
2. **能力开放**：TwinMonitor-MCP-Server 将平台 8 大领域能力（告警/资产/指标/数据/知识/运维工具/脚本/通知）以 MCP（Model Context Protocol）工具形式开放给 aranea 及第三方 MCP Host，风险五级分级、默认只读、全程审计。
3. **智能分析**：告警触发的 AI 根因分析（RCA）与设备自动诊断——分析执行在 aranea，触发、参数组装、结果落库、事件发布、误报治理在本模块；诊断过程经 MCP 检索知识库与平台数据增强结论。
4. **洞察与接入**：AI 洞察看板（聚合 TwinMonitor 业务指标与 aranea 运行/成本指标）、aranea 实例接入管理与健康治理。

模块目标是与 aranea 协同，把「告警 → 诊断 → 建议 → 审批 → 执行 → 验证 → 沉淀」的运维闭环交给 AI 与人协同完成，缩短 MTTR、提升运维标准化水平。

```

```

## 3. 模块边界

### 3.1 包含范围

- **aranea 接入管理**：aranea 实例端点与服务凭据配置（AES-256-GCM 加密）、连通性探测、版本与能力清单同步、健康状态监测与降级提示。
- **运维智能体目录**：12 个预设运维 Agent 的种子同步（注册到 aranea）与本地治理镜像（分类/风险/启停/审计）、自定义 Agent 登记、Agent 在线测试（代理调用 aranea）、执行历史。
- **场景模板管理**：运维场景（= aranea Graph 定义）的注册、参数 JSON Schema、风险等级、版本、启停、导入导出、复制、立即执行；场景与 aranea graph_id 的映射治理。
- **任务中心**：场景执行记录的创建（手动/定时/告警/14 修复触发）、状态镜像（经 aranea Webhook 回写）、节点进度与日志透传（代理 aranea Trace）、取消、关联报告、NATS 实时事件推送。
- **审批中心**：审批待办管理、通过、拒绝（必填原因）、超时自动拒绝；审批结果经 aranea Interrupt/Resume 机制恢复执行。
- **脚本库**：Shell/Python/PowerShell 脚本 CRUD、版本号、JSON Schema 参数化定义与执行（经 16 运维工具）；脚本以 MCP 工具暴露。
- **配置模板**：`{{variable}}` 占位符模板管理、变量定义、渲染预览；以 MCP 工具暴露。
- **定时任务**：Cron 调度场景模板执行，启用/禁用，上次/下次执行时间。
- **TwinMonitor-MCP-Server**：8 大领域内置工具、风险五级分级（readonly/low/medium/high/destructive）、默认只读模式、工具注册表治理、工具浏览器、调用测试与历史、第三方 MCP Host 接入凭证管理。
- **AI 根因分析**：告警触发的 RCA 记录管理（触发/落库/误报标记/执行修复入口/统计），分析执行委托 aranea。
- **告警自动诊断**：告警触发后由 aranea 诊断 Agent 经 MCP 执行只读诊断命令集并汇总，记录与展示在本模块。
- **AI 洞察看板**：MTTR、自动修复成功率、根因分析准确率、告警降噪率、知识库增长、告警严重度分布，以及 aranea 侧 LLM 成本/Token/Agent 成功率等运行指标聚合。
- **知识沉淀联动**：RCA 结论沉淀至 10 知识库（经其 HTTP 接口）与 aranea 记忆（L3 事实，经其 API），双通道可溯源。

### 3.2 不包含范围（由 aranea-agents 或他模块承载）

- **不管 LLM**：模型目录、Provider 接入、API Key 存储、成本配额、模型降级链由 aranea 承载；本模块仅维护"场景 → 模型策略"引用（aranea 模型 ID）。
- **不做 Agent 运行时**：Agent 加载、工具装配、上下文管理、流式输出由 aranea 承载。
- **不做编排引擎**：工作流 DAG 解析、节点调度、并行/循环/条件、Checkpoint、失败重试由 aranea Graph 承载；本模块不解析执行 nodes/edges。
- **不采集监控数据**：设备指标采集由 03 监控采集负责，本模块只消费采集结果与告警事件。
- **不存储知识库**：知识库文档主数据由 10 业务管理负责，本模块经 MCP/HTTP 检索与写入。
- **不直接 SSH/直连执行命令**：所有设备命令经 16 运维工具命令执行 API，本模块不持有设备凭据。
- **不发送通知**：审批待办、任务完成等通知由 05 通知服务负责，本模块发布 NATS 事件触发。
- **不定义修复策略**：「什么告警触发什么修复动作」的策略与自愈闭环由 14 自动修复模块负责，本模块为其提供场景执行代理与 AI 分析能力。

## 5. 功能需求

### 5.1 aranea 接入管理

- 支持配置 aranea 实例：名称、Base URL（HTTP）、服务凭据（API Token，AES-256-GCM 加密落库、出参脱敏）、Webhook 回调密钥（用于校验 aranea 事件签名）、启用状态。
- 连通性探测：调用 aranea 健康端点，返回版本、运行时长、已注册 Agent/Graph 数量、MCP Host 状态；失败返回明确原因。
- 能力清单同步：一键/定时拉取 aranea 侧 Agent 清单、Graph 清单、模型清单，刷新本地治理镜像；同步记录（时间/数量/差异数）可查询。
- 健康治理：周期性探测（默认 30 秒），连续失败进入 `degraded` 状态并发布 NATS 事件 `ai.aranea.health`；降级期间新建执行类操作给出明确提示，分析类业务按降级矩阵处理（见非功能需求）。
- 多实例预留：实例表按多行设计，当前版本仅启用 1 个实例。

**验收要点**：
- 配置正确端点与凭据后探测返回 aranea 版本与资源计数；故意填错凭据返回鉴权失败原因。
- aranea 进程停止后 90 秒内实例状态变为 degraded 且 NATS 事件可订阅；恢复后自动回到 healthy。
- 能力同步后本地智能体目录/场景模板与 aranea 侧清单一致，差异项高亮标注（本地有/aranea 无）。

### 5.2 运维智能体目录

- 内置 12 个预设运维 Agent（is_preset=1，不可删除）：告警处理 Agent、故障诊断 Agent、日志分析 Agent、系统巡检 Agent、变更执行 Agent、文档生成 Agent、合规检查 Agent、服务器命令执行 Agent、命令生成专家、自动巡检 Agent、网络巡检专家、数据库运维 Agent。
- 种子同步：首次接入 aranea 时，将 12 个预设 Agent 的定义（名称/角色/系统提示词/模型策略/温度/工具白名单）注册为 aranea Agent（组织归属：IT 运维行业 → 运维部门 → 岗位）；回写 `aranea_agent_id` 建立映射；重复执行幂等（按名称匹配更新）。
- 治理镜像字段：aranea_agent_id、分类（告警处理/故障处理/数据分析/巡检审计/服务器管理/操作执行/文档报告）、风险等级、启用开关（本地禁用后不可被场景/测试引用，aranea 侧不删）、标签、使用统计（由任务事件回写累计）。
- 自定义 Agent：在 aranea 侧创建后，经能力同步进入本地目录，可补充分类/风险/标签等治理元数据。
- 在线测试：输入测试内容 → 本模块组装 run 参数（含场景模型策略）→ 代理调用 aranea 执行 → 返回 Markdown 结果与耗时；数据库运维 Agent 测试需选择目标数据库，其余可选目标服务器集合（作为上下文注入，实际访问经 MCP 工具）。
- 执行历史：每次测试/场景引用生成调用记录（输入/输出摘要/实际模型/Token/耗时/状态/aranea run_id），详情页展示最近 30 条，可跳转 aranea Trace。

**12 个预设 Agent 一览**：

| # | 名称 | 头像 | 职责 | 默认温度 |
|---|------|:---:|------|:---:|
| 1 | 告警处理 Agent | 🚨 | 分析告警、评估严重程度、给出处理建议（摘要/评估/原因/建议/后续） | 0.7 |
| 2 | 故障诊断 Agent | 🔍 | 症状分析→根因定位→排查步骤→解决方案 | 0.7 |
| 3 | 日志分析 Agent | 📝 | 识别错误模式、异常事件、性能问题 | 0.7 |
| 4 | 系统巡检 Agent | 🔎 | 资源使用与服务状态评估，输出优化建议 | 0.7 |
| 5 | 变更执行 Agent | ⚙️ | 执行变更并验证结果，含回滚方案 | 0.7 |
| 6 | 文档生成 Agent | 📄 | 生成 Markdown 结构化运维报告 | 0.7 |
| 7 | 合规检查 Agent | 🛡️ | 安全基线/合规验证，输出不符合项与修复建议 | 0.7 |
| 8 | 服务器命令执行 Agent | 💻 | 在目标服务器执行命令并分析结果（经 MCP → 16） | 0.7 |
| 9 | 命令生成专家 | ⚡ | 按自然语言与目标 OS 生成命令，仅返回 JSON `{command, explanation}` | 0.3 |

| 11 | 网络巡检专家 | 🌐 | 华为/H3C/Cisco/锐捷/中兴设备适配；阈值（CPU<70/>70/>85；内存<75/>75/>90）；标准/自定义/全面三模式 | 0.3 |
| 12 | 数据库运维 Agent | 🗄️ | 健康检查、慢查询诊断、安全审计、死锁分析、SQL 审核 | 0.3 |

**验收要点**：
- aranea 就绪后执行种子同步，12 个预设 Agent 全部获得 `aranea_agent_id`；重复同步不产生重复 aranea Agent。
- 本地禁用某 Agent 后，场景模板引用该 Agent 保存时校验拦截。
- 对「告警处理 Agent」执行测试，60 秒内返回结构化分析（摘要/评估/原因/建议/后续），执行历史新增一条且含 aranea run_id。
- 预设 Agent 的删除操作被拦截并提示。

### 5.3 场景模板管理

- 场景模板 = aranea Graph 定义在本模块的治理注册项：名称、描述、分类（server/security/database/network/system/template）、aranea_graph_id、参数 JSON Schema（定义执行入参的键名/类型/必填/默认值/说明）、风险等级（low/medium/high）、版本、启用状态。
- 注册方式两种：① 引用已在 aranea 编排好的 Graph（能力同步后下拉选择，推荐——可视化编排在 aranea 完成）；② 导入 aranea Graph JSON（本模块转发 aranea 创建后注册）。
- 治理校验：保存时校验 aranea_graph_id 有效性（经 aranea API，5 分钟 Redis 缓存）；参数 Schema 与 Graph 声明的输入键比对，缺项/多项给出提示。
- 支持复制（生成「（副本）」）、导出（name/description/aranea graph JSON/params_schema）、启用/禁用；被定时任务或 14 策略引用的场景禁用/删除前给出引用清单提示。
- 「立即执行」：按参数 Schema 渲染表单（boolean→开关、enum→下拉、number→数字），含服务器类参数时提供目标服务器选择（经 02 资产接口）；确认后创建任务并跳转任务中心。
- 版本管理：aranea Graph 变更后执行同步可升级本地快照版本；历史版本保留执行记录关联。

**验收要点**：
- 引用 aranea 现有 Graph 注册场景后，「立即执行」按参数 Schema 正确渲染表单并成功创建任务。
- 导入合法 Graph JSON 后场景出现在列表且 aranea 侧可见同名 Graph；导入非法 JSON 被拦截并指明错误位置。
- 禁用中的场景不出现在定时任务与 14 策略的可选列表。

### 5.4 任务中心

- 四种触发方式：手动执行（manual）、定时任务（schedule）、告警触发（alert）、修复触发（remediation，来自 14）。
- 任务生命周期镜像 aranea 执行：pending（排队/创建中）→ running ⇄ paused（如 aranea 支持挂起）→ waiting_approval（审批挂起）→ completed/failed/cancelled。
- 状态回写：aranea 执行事件经 Webhook 回调本模块（签名校验），本模块更新镜像并发布 NATS 主题 `ai.task.events`（started/node_started/node_output/node_completed/completed/failed/cancelled/waiting_approval），前端实时刷新；Webhook 丢失时以 30 秒兜底轮询 aranea 执行状态补齐。
- 节点进度与日志：列表展示节点状态（completed 绿✓/running 蓝脉冲/failed 红✗/waiting_approval 橙/pending 灰）；日志分型着色（thinking/output/success/error/info）——数据经本模块代理查询 aranea Trace/事件流，不在本地重复存储明细（本地仅存状态与摘要）。
- 操作：取消（running/waiting_approval 可调，转发 aranea 取消语义）；重试由调用方（14/定时任务）发起新任务。
- 节点结果：每节点输入/输出（Markdown）/错误/耗时，经 aranea 执行详情接口获取。
- 报告关联：文档生成类场景产出的报告经 06 数据管理导出落盘（D6 本地存储），任务详情可预览/下载。
- 并发与队列：执行并发由 aranea 侧配额控制；本模块仅做创建准入（aranea 健康检查 + 场景启用校验 + 幂等键去重，幂等键格式 `{trigger_type}:{source_id}:{scene_id}`）。

**验收要点**：
- 手动执行一个 3 节点场景，任务中心可见节点依次 running→completed，最终 completed；全程 NATS 事件齐全。
- aranea Webhook 人为丢弃一条事件后，兜底轮询 60 秒内补齐状态，不出现永久 running。
- 运行中任务取消后 aranea 侧执行终止，本地状态 cancelled。
- 同一幂等键重复提交返回已存在任务，不重复创建 aranea 执行。

### 5.5 审批中心

- 场景执行到达审批点（aranea Graph InterruptBefore/InterruptAfter 或 MCP 高危工具调用前置审批）时，本模块生成审批记录（pending），执行挂起（waiting_approval）。
- 审批卡片：场景/节点名称、审批说明、风险等级、任务标识、发起人、发起时间、超时时间、上下文摘要（如待执行命令）。
- 通过：记录审批人与时间 → 调用 aranea Resume 恢复执行；拒绝：必填原因 → 按场景配置流转（failed 或回滚分支）。
- 超时处理：到达超时时间未处理按配置自动拒绝（status=timeout）或继续等待；超时扫描周期 30 秒。
- 待审批事件经 NATS `ai.approval.pending` 推送，由 05 通知服务提醒审批人；审批结果同步写入任务事件。
- 审批与 aranea interrupt_id 一一对应，防重复恢复；审批操作幂等（同一人重复点击返回已处理状态）。

**验收要点**：
- 含审批点的场景执行后审批中心出现待办，任务状态 waiting_approval，NATS 事件可订阅。
- 通过后 10 秒内 aranea 侧执行恢复推进；拒绝不填原因无法提交。
- 超时设为 60 秒且行为为自动拒绝，超时后审批状态 timeout，任务按拒绝路径流转。

### 5.6 脚本库

- 支持 Shell/Python/PowerShell 三类脚本的 CRUD 与分类管理；版本号管理（如 1.0.0），同名校验按「名称+版本」唯一。
- 参数化定义：JSON Schema 数组（name/description/type/required/default），执行时按 Schema 渲染表单并校验必填。
- 参数化执行：选择脚本与目标服务器、填写参数后发起执行；执行经 16 运维工具命令执行 API（同步），结果（输出/退出码/耗时）回传展示。
- MCP 暴露：每个启用脚本自动注册为 MCP 工具 `script.execute_{name}`（参数 Schema 透传），供 aranea 场景调用；风险等级默认 high（可治理调整），受 MCP 安全层管控。

**验收要点**：
- 新建带 2 个参数（1 必填 1 可选）的 Shell 脚本，执行弹窗正确渲染且必填项标红；缺必填参数提交被拦截。
- 启用脚本在 MCP 工具浏览器可见，经 aranea 调用（medium 及以上需放行）返回结构化结果并写入调用历史。
- 脚本内容更新并递增版本后，历史版本内容仍可追溯。

### 5.7 配置模板

- 管理带 `{{variable}}` 占位符的配置模板：名称、类型（generic/nginx/apache/docker/kubernetes/database/monitoring/system）、目标类型、描述、模板内容、变量列表（名称/描述/默认值/必填）、标签、版本。
- 渲染预览：输入变量值后返回替换后的完整配置文本；缺失必填变量返回明确错误与缺失清单。
- MCP 暴露：工具 `config.render`（参数：模板 ID + 变量键值），供 aranea 场景在变更类 playbook 中使用。

**验收要点**：
- 新建 nginx 模板含 `{{server_name}}` 与 `{{listen_port}}`，渲染预览正确替换；缺必填变量返回缺失清单。
- 经 MCP 调用 `config.render` 返回与页面预览一致的结果。

### 5.8 定时任务

- 以 5 字段标准 Cron 表达式（分 时 日 月 周）调度指定场景模板定时执行；支持为场景预填输入参数（JSON）。
- 启用/禁用切换；记录上次执行时间、上次生成的任务 ID 与下次执行时间；Cron 非法时保存前校验拦截。
- 到点触发：校验场景启用 + aranea 健康 → 创建任务（trigger_type=schedule，幂等键含计划时间桶防重复触发）。

**验收要点**：
- 配置「每天零点」Cron 并启用后到时自动创建 trigger_type=schedule 的任务；禁用后不再生成。
- 保存非法 Cron（如 `61 * * * *`）被拦截并提示格式错误。

### 5.10 AI 根因分析

- 支持以告警 ID 触发 RCA（手动新建或告警事件自动触发），状态机：pending → analyzing → completed/failed。
- 执行链路：组装上下文（告警详情 + 同时间窗关联告警 + 资产拓扑 + 变更记录）→ 创建 aranea RCA 场景 run（RCA Agent Team：关联告警分析/拓扑上卷/时序相关/变更关联/知识匹配）→ 回收结构化产出。
- 分析产出：问题描述、根本原因、症状列表、分析证据、事件时间线（time+event）、修复建议列表、置信度（%）、AI 评估告警严重度；附 aranea run_id 可跳转 Trace。
- 知识引用：RCA 过程经 MCP `knowledge.search` 检索 10 知识库，引用条目记录 knowledge_id 列表；同时可引用 aranea L3 记忆中的历史处置经验（标注来源=memory）。
- 支持标记误报（is_false_positive）与「执行修复」入口（跳转 14 模块并携带 rca_record_id）。
- 统计卡：今日分析数（含累计完成）、平均置信度、自动修复数、误报数。
- 完成事件：NATS `ai.analysis.completed`（含告警 ID、严重度、置信度、根因摘要），供 04 告警服务回写与 07 可视化消费。
- 降级：aranea 不可用或知识检索失败时，分析记录标记 failed/degraded 并注明原因（不伪造结论）；事件照常发布供上游感知。

**验收要点**：
- 输入有效告警 ID 创建分析，120 秒内产出含症状/证据/时间线/建议/置信度的完整结果，状态 completed 且含 aranea run_id。
- 结论引用的知识条目可在详情查看标题与来源（知识库/记忆）。
- 标记误报后统计卡误报数 +1；`ai.analysis.completed` 可被订阅。
- aranea 停机期间触发分析，记录明确标记 degraded 原因，不出现空结论的 completed。

### 5.11 告警自动诊断

- 订阅 `alarm.events`，对命中范围（级别/设备类型）的告警自动触发设备诊断：aranea 诊断 Agent 按设备类型（服务器/网络设备）经 MCP 逐条执行预置只读诊断命令集（MCP → 16 下发），再由 AI 汇总诊断结论。
- 分析记录：设备名、IP、设备类型徽章、状态（pending/running/completed/failed）、AI 诊断结论、已执行命令清单、原始输出（折叠展示、截断 5000 字）、错误信息、耗时、aranea run_id。
- 统计卡：总分析次数、服务器分析次数、网络设备分析次数；列表 15 秒轮询刷新。
- 预置诊断命令集（全部只读，执行前经 MCP 命令白名单校验）：

| 设备类型 | 命令类别 | 示例命令 |
|----------|----------|----------|
| 服务器（Linux） | CPU/负载 | `top -bn1 \| head -20`、`uptime` |
| 服务器（Linux） | 内存 | `free -h`、`vmstat 1 3` |
| 服务器（Linux） | 磁盘 | `df -h`、`iostat -x 1 3` |
| 服务器（Linux） | 网络 | `ss -s`、`ip addr` |
| 服务器（Linux） | 日志 | `dmesg \| tail -50`、`journalctl -p err -n 50` |
| 网络设备 | 设备概览 | `display version`、`display device`（按厂商适配） |
| 网络设备 | CPU/内存 | `display cpu-usage`、`display memory-usage` |
| 网络设备 | 接口 | `display interface brief`、`display ip interface brief` |
| 网络设备 | 日志/告警 | `display logbuffer \| include ERROR` |

诊断命令集支持在配置中扩展。

**验收要点**：
- 模拟一条服务器 critical 告警后自动生成诊断记录，逐条执行命令并产出 AI 结论（≤180 秒），含 aranea run_id。
- 原始输出超 5000 字被截断并保留截断标记；每条记录含命令清单与总耗时。

### 5.12 AI 洞察看板

- 业务统计卡 5 张：平均修复时间 MTTR（含周环比）、自动修复成功率、根因分析准确率、告警降噪率、知识库增长（总数+本周新增）。
- AI 运行卡 3 张（数据源 aranea）：今日 LLM 调用量与 Token 消耗、本月 LLM 成本（按配额口径）、Agent 调用成功率/P95 延迟。
- 告警严重程度分布横向条形图（严重/高/中/低/信息五色）；知识库分类分布条形图（Top5）。
- 最近洞察列表：已完成 RCA 前 10 条（标题+根因摘要+时间）。
- 数据来源约定：MTTR/降噪率/严重度分布经 HTTP 调 06 数据管理统计接口；RCA 指标由本模块库表聚合；知识库数据经 HTTP 调 10 业务管理；AI 运行指标经 aranea 可观测/配额 API 获取，aranea 不可用时该 3 张卡显示「数据源离线」不阻塞业务卡。

**验收要点**：
- 看板打开 3 秒内完成加载；各卡数值与来源接口一致。
- aranea 停机时业务卡正常渲染，AI 运行卡显示离线标识。

### 5.13 知识沉淀联动

- RCA/诊断完成后，支持「沉淀知识」一键将结论（症状/根因/处置步骤）经 10 业务管理接口写入知识库（category=故障案例，tags 含「AI沉淀」），回写 knowledge_id。
- 同时可将处置经验（结构化事实：告警模式→根因→有效动作）经 aranea 记忆 API 写入 L3 scope=global，供后续 RCA 召回；写入内容与 10 知识库条目互相关联引用。
- 沉淀操作记录操作人与时间，进入审计；重复沉淀按标题相似度提示。

**验收要点**：
- RCA 详情点击「沉淀知识」后 10 知识库出现对应条目，RCA 记录回写 knowledge_id。
- 后续同类告警 RCA 的引用列表中可召回该经验（来源标注 memory/knowledge）。

| MCP 单次调用超时 | 5-600 秒 | 60 秒 | 命令类工具按其自身超时 |
| 诊断原始输出截断 | 5000 字 | 5000 | 自动诊断 raw_output 上限 |

## 7. 非功能需求

- **安全性**：aranea 服务凭据、Webhook 密钥、MCP 接入凭证等敏感配置一律 AES-256-GCM 加密落库，接口出参脱敏；MCP 工具调用经风险分级安全层校验；AI 生成命令执行前经审批或风险校验，禁止未放行 destructive 操作；LLM Key 唯一落点为 aranea，本模块不存储、不透传。
- **性能**：任务状态 NATS 推送延迟 ≤ 1 秒（自 Webhook 接收起算）；aranea 连通性探测 10 秒内返回；场景保存校验 500ms 内（不含 aranea 校验，校验走缓存）；洞察看板 3 秒内返回。
- **可靠性**：任务、审批、分析记录全部持久化；Webhook 事件签名校验 + event_id 幂等去重；Webhook 丢失有兜底轮询；服务重启后 analyzing/running 记录按配置标记 failed（注明原因）或恢复轮询。
- **可追溯**：Agent 调用、任务执行、审批操作、MCP 工具调用、AI 分析全程留痕（操作人/耗时/模型/Token/aranea run_id/trace_id），与 aranea Trace 双向可跳转。
- **扩展性**：新增运维 Agent、场景模板、MCP 工具领域均可配置化扩展（JSONB 承载差异化配置）；MCP 工具契约变更走版本化（工具名带命名空间，向后兼容）。
- **降级矩阵**：

| 故障点 | 降级行为 |
|--------|----------|
| aranea 不可用 | 实例状态 degraded；新建任务/分析被拦截并明确提示；运行中任务进入兜底轮询直至超时标记；MCP Server 照常服务（第三方 Host 不受影响）；洞察看板 AI 运行卡显示离线 |
| 10 知识库不可用 | RCA 降级为不引用知识库继续（标注「知识库不可用」）；knowledge.search 工具返回明确错误 |
| 16 运维工具不可用 | 命令类 MCP 工具与脚本执行返回失败；自动诊断记录 failed 并注明 |
| NATS 不可用 | 事件发布重试 3 次后落库待补偿；前端轮询兜底 |

- **资源保护**：MCP 调用按调用方限流；诊断原始输出截断；任务创建幂等防重；aranea 侧并发/配额由其自身管控。
- **数据隔离**：配置/治理数据存 PostgreSQL twinmonitor 库，执行镜像/审计/分析记录存 PostgreSQL twinmonitor_log 库，读写分离互不影响。

## 8. 验收标准

1. 完成 aranea 实例接入：探测返回版本与资源计数；停机 90 秒内状态 degraded 且事件可订阅，恢复后自动 healthy。
2. 种子同步后 12 个预设 Agent 全部映射 aranea_agent_id 且不可删除；自定义 Agent 经同步进入目录；测试调用返回结构化结果并含 run_id。
3. 引用 aranea Graph 注册场景模板并立即执行：任务经 Webhook+兜底轮询推进至 completed，节点进度与 thinking 日志实时可见，NATS 事件完整。
4. 含审批点场景：审批待办出现 → 通过后 aranea 执行恢复 → 任务完成；拒绝必填原因；超时自动拒绝按配置生效。
5. 配置每天零点定时任务，到时自动创建 schedule 任务（幂等防重）。
6. 脚本库启用脚本自动注册为 MCP 工具，aranea 侧调用（放行后）返回结构化结果并写审计；缺必填参数被拦截。
7. 配置模板渲染预览与 MCP `config.render` 结果一致；缺必填变量返回缺失清单。
8. MCP 默认只读模式下 high/destructive 工具调用被拦截并记录 blocked；为第三方 Host 签发凭证后可按授权子集调用。
9. 模拟 critical 告警：自动生成 RCA 记录（症状/证据/时间线/建议/置信度/run_id）与自动诊断记录（命令清单+截断输出+耗时），`ai.analysis.completed` 被成功订阅；aranea 停机期间触发则明确降级标记。
10. 洞察看板业务卡与 06/10/本模块聚合一致，AI 运行卡与 aranea 配额/可观测数据一致；aranea 停机时业务卡正常、运行卡离线标识。
11. RCA「沉淀知识」后 10 知识库出现条目且 RCA 回写 knowledge_id；后续同类分析可召回该经验。
