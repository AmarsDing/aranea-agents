## 1. 模块定位

AI智能运维模块（服务名 aiops）是 TwinMonitor 集中监控数字孪生平台的 **智能运维治理与接入层**。平台全部 AI 能力构建在外部多智能体编排底座 **aranea-agents** 之上：aranea 提供 LLM Provider 与模型目录、Agent 运行时、三层编排引擎（Team 六模式 / Graph 图编排 / Spirit 动态编排）、五层记忆（L0~L4）、全链路可观测（Trace/Flow Log）与成本配额；本模块面向运维域提供治理面（aranea 接入管理、运维智能体目录、场景模板、任务中心、人工审批、定时调度、脚本库、配置模板）、能力开放（TwinMonitor-MCP-Server，将平台 8 大领域能力以 MCP 工具形式向 aranea 及第三方 MCP Host 开放）与智能分析业务（AI 根因分析、告警自动诊断、AI 洞察看板、知识沉淀联动）。

模块消费 04 告警事件触发 RCA 与自动诊断（分析执行在 aranea，触发、落库、事件发布在本模块），为 14 自动修复提供场景执行代理与审批承载，为 07 可视化与 05 通知提供任务/审批/分析三类实时事件。模块不管理 LLM、不做 Agent 运行时、不做编排引擎、不采集数据、不存储知识库、不直连设备执行命令、不发送通知、不定义修复策略，与 aranea 及周边模块通过 HTTPS API + Webhook + NATS 解耦协作。

## 2. 模块职责

- **aranea 接入管理**：实例端点与服务凭据配置（AES-256-GCM 加密）、连通性探测、能力清单同步（Agent/Graph/模型）、周期健康监测与 degraded 降级事件。
- **运维智能体目录**：12 个预设运维 Agent 种子同步（注册到 aranea 并回写映射）与本地治理镜像（分类/风险/启停/标签/使用统计）、自定义 Agent 登记、在线测试（代理调用 aranea）、执行历史。
- **场景模板管理**：运维场景（= aranea Graph 定义）的注册、参数 JSON Schema、风险等级、版本、启停、复制/导入/导出、立即执行；场景与 aranea graph_id 映射治理。
- **任务中心**：场景执行镜像的创建（手动/定时/告警/14 修复触发，幂等防重）、状态镜像（Webhook 回写 + 兜底轮询）、节点进度与日志透传（代理 aranea Trace）、取消、NATS 实时事件推送。
- **审批中心（HITL）**：审批待办、通过（aranea Resume 恢复执行）、拒绝（必填原因）、超时自动拒绝扫描、待审批事件推送。
- **脚本库**：Shell/Python/PowerShell 脚本 CRUD、版本、JSON Schema 参数化执行（经 16 运维工具）；启用脚本自动注册为 MCP 工具。
- **配置模板**：`{{variable}}` 占位符模板管理、渲染预览；以 MCP 工具 `config.render` 暴露。
- **定时任务**：Cron 调度场景模板执行，启用/禁用，上次/下次执行时间，幂等防重。
- **TwinMonitor-MCP-Server**：8 大领域内置工具（告警/资产/指标/服务器/网络/数据库/知识/通知工单）、风险五级分级、默认只读模式、命令白/黑名单二次防护、调用方凭证管理、工具浏览器、调用测试与历史、全程审计。
- **AI 根因分析（RCA）**：告警触发的 RCA 记录管理（触发/上下文组装/结果落库/误报标记/执行修复入口/统计），分析执行委托 aranea RCA 场景。
- **告警自动诊断**：告警触发后由 aranea 诊断 Agent 经 MCP 执行只读诊断命令集并汇总，记录与展示在本模块。
- **AI 洞察看板**：MTTR/自动修复成功率/RCA 准确率/告警降噪率/知识库增长等业务指标 + aranea 侧 LLM 成本/Token/Agent 成功率等运行指标聚合。
- **知识沉淀联动**：RCA 结论沉淀至 10 知识库（HTTP）与 aranea L3 记忆（API）双通道，可溯源。

## 3. 技术架构

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 后端框架 | Golang Kratos v2.9.2 | 独立 aiops 微服务，HTTP:8100 / gRPC:9100 |
| 分层架构 | service → biz → data | 禁止 service 直连 data；biz 层 Repo 接口 WithTx 传播事务 |
| 依赖注入 | Google Wire | 编译期注入 |
| ORM/实体 | Ent v0.11.1 | 所有 schema 实现 Privacy() 数据权限与 Edge 关联；导入 `ent/runtime` |
| 关系数据库 | PostgreSQL (twinmonitor) | 配置/治理数据：aranea 实例、智能体镜像、场景模板、脚本、模板、定时任务、MCP 工具注册表与调用方 |
| 关系数据库 | PostgreSQL (twinmonitor_log) | 执行镜像/审计/分析记录：任务、节点镜像、审批、Agent 执行、MCP 调用、RCA、自动诊断、同步记录 |
| 缓存 | Redis 6.0+ | 跨模块校验缓存（5 分钟）、aranea 资源校验缓存、任务幂等键、审批超时索引、策略/工具清单缓存 |
| 消息队列 | NATS | 发布 ai.task.events / ai.approval.pending / ai.analysis.completed / ai.aranea.health；订阅 alarm.events |
| 定时调度 | robfig/cron v3 | 5 字段标准 Cron，定时任务触发、审批超时扫描、aranea 健康探测、Webhook 兜底轮询 |
| aranea 集成 | HTTPS REST + Webhook | AraneaClient 端口适配层（Agent/Graph/Run/Interrupt/Resume/记忆/配额 API），Webhook 签名校验（HMAC-SHA256） |
| MCP 协议 | MCP 2024-11-05，SSE 传输 | TwinMonitor-MCP-Server 对外提供工具服务；go-sdk / 自研 SSE handler |
| 敏感数据加密 | AES-256-GCM | aranea 凭据、Webhook 密钥、MCP 调用方 secret 加密落库，出参脱敏 |
| 前端 | Vue 3 + TypeScript + Quasar v2 | 治理台页面族；aranea 编排画布以跳转/内嵌方式呈现（不自研图编辑器） |

**aranea 集成契约说明**：aranea 的具体端点路径以其 OpenAPI 契约为准，本模块在 data 层 `AraneaClient` 适配层收口全部调用（能力操作：Agent CRUD/清单、Graph CRUD/清单、Run 创建/查询/取消、Interrupt Resume、记忆写入、配额与可观测查询、健康端点）。biz 层只依赖能力接口，不感知 aranea 路径与版本差异；契约变更走适配层版本化。

| 项 | 值 | 说明 |

## 6. 核心数据模型

所有配置表遵循系统硬约束：主键 `id` bigint 自增；审计字段 created_at/updated_at/deleted_at + created_by/updated_by/deleted_by（uint64，关联 users.id）；软删除 deleted_at + 索引 `idx_<表名>_deleted_at`；索引名 schema 内全局唯一；ent schema 实现 Privacy() 与 Edge。执行镜像/审计/分析记录表为追加型日志数据，位于 twinmonitor_log，不做软删除（保留 created_at/updated_at），操作人以 created_by/operator_id 记录。

## 7. 接口设计概览

API 统一前缀 `/api/v1/monitor/aiops`，REST 风格，统一响应包 `{code, message, data}`，列表分页 page/page_size，时间 RFC3339。Webhook 回调端点不经网关鉴权，走 HMAC-SHA256 签名校验。全量 65 个端点：

### 7.1 aranea 接入（/aranea，7 个端点）

```
GET/POST           /api/v1/monitor/aiops/aranea/instances              # 实例列表/登记
GET/PUT/DELETE     /api/v1/monitor/aiops/aranea/instances/{id}         # 详情/更新/删除
POST               /api/v1/monitor/aiops/aranea/instances/{id}/test    # 连通性探测
POST               /api/v1/monitor/aiops/aranea/instances/{id}/sync    # 能力清单同步（Agent/Graph/模型）
GET                /api/v1/monitor/aiops/aranea/sync-records           # 同步记录查询
```

### 7.2 运维智能体目录（/agents，7 个端点）

```
GET                /api/v1/monitor/aiops/agents                        # 列表（分类/风险/状态筛选）
GET/PUT            /api/v1/monitor/aiops/agents/{id}                   # 详情/治理元数据更新（预设禁删，无 DELETE）
PUT                /api/v1/monitor/aiops/agents/{id}/status            # 启用/禁用（本地治理，不动 aranea 侧）
POST               /api/v1/monitor/aiops/agents/seed-sync              # 12 预设 Agent 种子同步（幂等）
POST               /api/v1/monitor/aiops/agents/{id}/test              # 在线测试（代理 aranea 执行）
GET                /api/v1/monitor/aiops/agents/{id}/executions        # 执行历史（默认最近30条）
GET                /api/v1/monitor/aiops/agents/categories             # 分类清单
```

### 7.3 场景模板（/scenarios，10 个端点）

```
GET/POST           /api/v1/monitor/aiops/scenarios                     # 列表/注册（引用 aranea Graph）
```

|------|------|--------|------|

| `ai.task.events` | 发布 | 07-可视化展示、14-自动修复 | 任务与节点状态事件（started/node_started/node_output/node_completed/completed/failed/cancelled/waiting_approval） |

## 9. 关键业务流程

### 9.1 aranea 接入与种子同步流程

1. 管理员登记 aranea 实例（Base URL + 服务凭据 + Webhook 密钥，AES-256-GCM 加密落库）。
2. 连通性探测：调用 aranea 健康端点，回写版本/运行时长/Agent/Graph 计数；失败返回明确原因。
3. 种子同步：将 12 个预设运维 Agent 定义（名称/角色/系统提示词/模型策略/温度/工具白名单）按"名称匹配、存在更新、缺失创建"注册到 aranea（组织归属：IT 运维行业 → 运维部门 → 岗位），回写 `aranea_agent_id`；全程幂等可重入。
4. 能力同步：拉取 aranea 侧 Agent/Graph/模型清单刷新本地治理镜像，差异项写入 `ai_sync_records` 并在列表高亮。
5. 健康探测协程（默认 30 秒）：连续 3 次失败置 degraded 并发布 `ai.aranea.health`；恢复自动回到 healthy。

### 9.2 场景执行与状态回写流程

1. 创建任务（手动/定时/告警/14 修复触发）：校验场景启用 + aranea 健康 → 幂等键（`{trigger_type}:{source_id}:{scene_id}`，Redis SET NX EX 6h）去重 → 组装 run 参数（含场景模型策略与目标上下文）→ 调用 aranea 创建执行 → 落任务镜像（pending，记录 aranea_run_id）。
2. 状态回写主链路：aranea 执行事件 POST 本模块 Webhook 端点 → HMAC 签名校验 + event_id 幂等去重 → 更新镜像（状态/节点进度/摘要）→ 发布 `ai.task.events`。
3. 兜底链路：running 状态任务由 FallbackPoller 每 30 秒轮询 aranea 执行状态补齐（Webhook 丢失时 60 秒内收敛）；终态后停止轮询。
4. 节点明细与日志不重复落库：前端经本模块代理查询 aranea Trace/事件流（本地仅存节点状态与输出摘要）。
5. 取消：running/waiting_approval 可调，转发 aranea 取消语义并等待终态回写。
6. 服务重启恢复：扫描 running 镜像重新挂入兜底轮询；超过配置时限未收敛标记 failed（注明原因）。

### 9.3 审批流程（HITL）

1. aranea Graph 到达审批点（InterruptBefore/InterruptAfter）或 MCP 高危工具调用前置审批 → Webhook 事件携带 interrupt_id → 本模块生成审批记录（pending，expire_at=now+timeout_seconds）→ 任务镜像置 waiting_approval。
2. 发布 `ai.approval.pending`（05 通知提醒审批人）。
3. 通过：记录审批人/时间 → 调用 aranea Resume（interrupt_id 一一对应，防重复恢复）→ 执行恢复。
4. 拒绝（必填原因）：按场景配置流转 failed 或回滚分支；审批操作幂等（重复点击返回已处理状态）。
5. 超时扫描（30 秒周期，Redis 有序集合 + DB 兜底）：超时行为=自动拒绝则置 timeout 并按拒绝流转；=继续等待则保持挂起。

### 9.4 告警触发智能分析流程

1. 订阅 `alarm.events`，过滤级别（默认 critical/emergency）与设备类型。
2. 生成 RCA 记录（pending）→ 异步：组装上下文（告警详情 + 同时间窗关联告警 + 资产拓扑 + 变更记录）→ 创建 aranea RCA 场景 run（RCA Agent Team：关联告警分析/拓扑上卷/时序相关/变更关联/知识匹配——RCA 过程经 MCP `knowledge.search` 检索 10 知识库，并可引用 aranea L3 记忆历史经验）→ Webhook 回收结构化产出（症状/证据/时间线/建议/置信度/严重度）→ completed。
3. 同步生成自动诊断记录：校验资产 → aranea 诊断 Agent 按设备类型选取只读诊断命令集 → 经 MCP（→16）逐条执行 → 汇总原始输出（截断 5000 字）→ AI 总结 → completed。
4. 两者完成后发布 `ai.analysis.completed`（04 回写、07 展示、14 消费）。
5. 降级：aranea 不可用或知识检索失败时记录标记 failed/degraded 并注明原因（不伪造结论），事件照常发布。

### 9.5 MCP 工具调用安全校验流程

1. client_id+secret 认证（SSE 连接建立时校验，吊销凭证拒绝并写审计）→ 按调用方授权子集过滤工具清单。
2. 解析工具名 → 查询 `ai_mcp_tools` 注册表获得领域、风险等级、只读标记、启用状态。
3. 安全模式校验：默认只读模式仅放行 readonly/low；medium/high 需命中放行策略（按工具或按调用方）；destructive 默认拒绝；高危工具可配置"前置审批"（挂起转审批中心，复用 §9.3）。
4. 参数校验：按工具 JSON Schema 校验；含资产标识的参数经 02 HTTP 校验（缓存 5 分钟）。
5. 命令类工具（server.exec_command/script.execute_*）再经命令白名单/黑名单过滤后转发 16（16 侧另有护栏，双端防护）。
6. 执行并记录调用历史（成功/失败/拦截及原因、耗时、调用方），全部写审计。

### 9.6 AI 洞察数据聚合流程

1. MTTR、告警降噪率、告警严重度分布 → HTTP 调 06 数据管理统计接口。
2. 自动修复成功率（经 14 仪表盘接口）、RCA 指标（今日分析数/平均置信度/误报数）→ 本模块与 14 库表聚合。
3. 知识库总量与本周新增、分类分布 → HTTP 调 10 业务管理。
4. AI 运行指标（今日 LLM 调用量/Token、本月成本、Agent 成功率/P95）→ aranea 可观测/配额 API；aranea 不可用时该 3 张卡显示「数据源离线」，不阻塞业务卡。
5. 聚合结果写 Redis（60 秒），看板接口命中缓存直接返回。

### 9.7 知识沉淀联动流程

1. RCA/诊断完成后「沉淀知识」：结论（症状/根因/处置步骤）经 10 HTTP 接口写入知识库（category=故障案例，tags 含「AI沉淀」），回写 knowledge_id。
2. 同步将结构化处置经验（告警模式→根因→有效动作）经 aranea 记忆 API 写入 L3 scope=global，与知识库条目互相关联引用。
3. 沉淀操作记录操作人与时间进入审计；重复沉淀按标题相似度提示。

## 11. 边界约定

- 本模块不管理 LLM：模型目录、Provider 接入、API Key 存储、成本配额、模型降级链由 aranea 承载；本模块仅维护"场景 → 模型策略"引用（aranea 模型 ID），不存储、不透传 LLM Key。
- 本模块不做 Agent 运行时与编排引擎：Agent 加载、工具装配、上下文管理、流式输出、DAG 解析、节点调度、Checkpoint、失败重试由 aranea 承载；本模块不解析执行 nodes/edges，不自研图编辑器画布（编排操作在 aranea 完成，本模块做治理注册）。
- 一切设备命令经 16 运维工具 API：本模块不直连设备、不持有设备凭据。
- 不发送通知：仅发布事件或经 MCP 工具调用 05 接口。
- 不存储知识库：知识检索/写入经 10 HTTP 接口。
- 修复策略本体在 14：本模块为其提供场景执行代理、审批承载与 AI 分析能力。
- 配置/治理数据与执行镜像严格分库（twinmonitor / twinmonitor_log），执行镜像表追加型、不软删除。
- 所有敏感配置（aranea 凭据、Webhook 密钥、MCP 调用方 secret）AES-256-GCM 加密落库、出参脱敏。
- MCP 默认只读模式：medium 及以上风险工具需显式放行，destructive 默认禁用。
- 告警事件只读消费，不回写告警状态；分析结论通过事件送达，由告警服务自行落库。
- 任务镜像与 aranea 执行的关系是"镜像"非"复制"：节点明细/日志以 aranea Trace 为准透传展示，本地仅存状态、摘要与审计必需字段。

## 12. 容量与性能设计

| 项 | 设计值 | 说明 |
|----|--------|------|
| 任务创建准入 | aranea 健康 + 场景启用 + 幂等键 | 执行并发由 aranea 侧配额控制，本模块不设信号量 |
| 任务幂等键 | TTL 6 小时 | Redis SET NX EX；重复提交返回已存在任务 |
| Webhook 处理 | ≤ 500ms | 签名校验+幂等+镜像更新+事件发布同步完成，重活异步 |
| 兜底轮询 | 30 秒周期 | 仅 running/waiting_approval 镜像；并发≤10 批次 |
| 任务事件推送 | ≤ 1 秒延迟（自 Webhook 接收起算） | NATS 发布订阅 |
| aranea 调用超时 | 60 秒（单次 API，不含长执行） | 健康探测 10 秒超时 |
| MCP 单次调用 | 60 秒（命令类按自身超时） | 按调用方限流（默认 60 QPS） |
| 诊断原始输出 | 截断 5000 字 | 控制单行存储与推送体积 |
| 洞察看板 | ≤ 3 秒 | 聚合结果 Redis 缓存 60 秒 |
| 跨模块校验 | 5 分钟缓存 | 资产/用户/知识条目/aranea 资源 |
| 数据增长估算 | 任务+审批+调用历史 ≈ 1.5 万行/日 | 按日均 500 任务 + 3000 次 MCP 调用估算；节点明细不落库后增长主要来自 MCP 历史，由系统运维统一制定归档策略 |

## 13. 可靠性设计

- **Webhook 不丢**：签名校验 + event_id 幂等去重；丢失由 FallbackPoller 30 秒兜底轮询收敛（≤60 秒）。
- **审批不丢失**：审批记录持久化于 twinmonitor_log，超时索引同时写 Redis 与数据库（expire_at 兜底，Redis 缺失时由 DB 扫描重建）。
- **事件不丢**：NATS 发布失败重试 3 次并记录错误日志，仍失败落库待补偿；消费侧幂等（event_id 去重）。
- **服务重启恢复**：启动扫描 running/waiting_approval 镜像重新挂入兜底轮询；analyzing/running 分析记录按配置标记 failed（注明原因）或恢复轮询。
- **aranea 故障隔离**：实例进入 degraded 后新建执行类操作被拦截并明确提示；运行中任务进入兜底轮询直至超时标记；MCP Server 照常服务（第三方 Host 不受影响）。
- **降级矩阵**：

| 故障点 | 降级行为 |
|--------|----------|
| aranea 不可用 | 实例 degraded + `ai.aranea.health` 事件；新建任务/分析拦截并明确提示；运行中任务兜底轮询至超时标记；MCP Server 照常；洞察 AI 运行卡显示离线 |
| 10 知识库不可用 | RCA 降级为不引用知识库继续（标注「知识库不可用」，rag_degraded=1）；knowledge.search 工具返回明确错误 |
| 16 运维工具不可用 | 命令类 MCP 工具与脚本执行返回失败；自动诊断记录 failed 并注明 |
| NATS 不可用 | 事件发布重试 3 次后落库待补偿；前端轮询兜底 |
| Redis 不可用 | 幂等/缓存类校验降级为直查 DB/aranea；审批超时扫描走 DB expire_at 兜底 |
