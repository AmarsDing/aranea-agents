## 1. 模块定位

平台自改进模块是 Aranea-Agents 的 Meta 级自我迭代能力：平台将自身全量代码（Go 后端 + 前端 + 配置 + Prompt）作为进化对象，由平台内运行的 Meta Team 完成「观察 → 归因 → 修补 → 验证 → 治理 → 应用 → 学习」七环自闭环。在竞赛方向一「零人工运维」中，本模块承担差异化能力——平台无人值守地修自己。

与 13/14 方向的关系一句话：13-AI智能运维是运维场景编排层，14-自动修复与自愈是修复执行中枢，15-平台自改进是平台自身的进化能力，三者互补。

本模块为 Aranea-Agents 平台**内建能力**（非独立微服务），以后台 worker + 平台内 Meta Team 会话形态运行于 admin 进程内，复用平台既有传输层（Kratos HTTP/gRPC/WebSocket）、运行时内核（trpc-agent-go Team 编排）与数据层（PostgreSQL + Ent）。

## 2. 模块职责

- **信号感知**：4 类 platform 触发器（错误聚类/性能瓶颈/评估退化/测试失败）周期性扫描平台自身运行数据，生成 platform 类自改进建议（复用统一进化建议存储与去重/冷却机制）。
- **归因诊断**：Analyst Agent 读取结构化错误、trace、指标快照与源码，输出根因/影响面/修复策略/置信度。
- **补丁生成**：Patcher Agent 在 git worktree 隔离副本上产出标准 unified diff，保护文件清单 fail-fast 拦截。
- **沙盒验证**：RepoSandboxRunner 执行五级 Gate（编译/单测/Lint/Critic/Eval 基线），失败回传重试 ≤3 次。
- **风险治理**：RiskClassifier（纯代码）按规则矩阵分级，路由低/中/高三通道，高风险走人工审批。
- **应用与回滚**：Applier 分热加载（配置/Prompt）与代码合并（重启生效）双通道；Watchdog 观察窗内指标退化自动回滚。
- **成效学习**：PatchOutcome 终态归因，FailurePattern KB 负面样本反哺，触发器自适应降频。
- **过程可视**：Meta Team 闭环作为特殊会话在聊天界面按事件树展示，支持用户介入指令。

模块不修改 V2 已有业务逻辑、不修改 trpc-agent-go 框架层、不做运行中二进制热替换、不做无人值守全自动高风险变更。

## 5. Meta Team 多 Agent 协同设计（AgentTeams 基点）

Meta Team 定义为平台内置 SpiritTeam（复用 53-team-graph-orchestration 图编排能力），映射赛题 AgentTeams 协同五要素：

### 5.1 角色编排（Agent Identity）

```
Observer(代码节点,非LLM) → Analyst(LLM) → Patcher(LLM) → Verifier(代码节点执行Gate+LLM总结)
    → Critic(LLM) → Governor(代码节点,非LLM) → [人工审批点] → Applier(代码节点)
```

| 成员 | 类型 | 职责 | 能力边界 |
|------|------|------|----------|
| Observer | 代码节点 | 汇总 4 触发器建议，打包 DiagnosisTask（建议+证据快照） | 只读信号源，不调用 LLM |
| Analyst | LLM Agent | 归因诊断，输出 Diagnosis | 仅源码只读工具，无写权限；confidence<0.5 降级 |
| Patcher | LLM Agent | worktree 内生成 unified diff | 工具限 worktree 作用域（fs_read/fs_write/git_diff）；禁碰保护清单 |
| Verifier | 代码+LLM | 执行 G1-G5 Gate，汇总 VerificationReport | Gate 命令白名单；沙盒无生产网络/数据 |
| Critic | LLM Agent | G4 语义回归审查，输出 CriticReport | 日配额 10 次；risk_level=high 一票否决 |
| Governor | 代码节点 | 风险分级与通道路由（纯代码，不走 LLM） | 规则矩阵 R1-R5；决策可解释（命中规则持久化） |
| Applier | 代码节点 | 热加载/代码合并/回滚执行 | 仅治理放行后动作；全量审计日志 |

### 5.2 任务拆解

统一进化建议（platform）即闭环任务输入；Observer 拆解为 DiagnosisTask → Analyst 产出 Diagnosis → Patcher 产出 Patch → Verifier 产出 VerificationReport → Critic 产出 CriticReport → Governor 产出 GovernanceDecision → Applier 产出 ApplyResult。每一环节产出是下一环节输入，职责单一、契约显式。

### 5.3 上下文传递

环节间全部以结构化 JSON 传递，经 TeamStage 事件树按父子关系挂载（遵循既有 team 活动挂载规范，ParentActivityID 用 resolveParentActivityID）；诊断、补丁、验证、治理、应用全过程在聊天界面可视、可追溯。

### 5.4 协同执行与异常处理

- **重试回路**：Verifier 失败 → 带 Gate 输出回 Patcher 修正（≤3 次，计数入 run.attempts），超限标记 verify_failed
- **置信度降级**：Analyst confidence < 0.5 时建议降级「仅记录」，不进入补丁环节
- **用户介入**：会话指令（暂停/跳过重试/强制回滚）经 chat 命令解析入 run 控制通道
- **冲突处理**：代码合并冲突转人工；同核心路径补丁经 governance 队列串行

### 5.5 状态追踪

建议状态机（复用 UnifiedEvolutionStateMachine）管「批不批」；运行状态机（新增 SelfImprovementRunStateMachine，13 状态）管「做到哪一步」；两机 1:1 绑定（suggestion_id 唯一），全程可查询。实现期增补两条恢复迁移：中途态陈旧恢复（diagnosing/patching/verifying 超时 → detected 重驱动）与合并冲突转人工（applying → awaiting_governance），保证后台 worker 驱动下无孤儿 run。

## 6. 核心设计决策

| 编号 | 决策 | 要点 |
|------|------|------|
| D1 | 建议载体复用统一进化建议 | 仅扩展枚举：target_type+platform、action_type+patch_code/tune_config/patch_prompt；复用 pending 去重/per-action 冷却/审批状态机，不建新建议表 |
| D2 | 四类触发器各司其职 | ErrorCluster（KB 聚类 7d≥5）/PerfBottleneck（P95 2× 或 token 1.5×）/EvalRegression（退化 10%）/TestFailure（连续 2 轮）；只感知不行动 |
| D3 | 运行状态机独立 | 建议状态机管审批生命周期；运行状态机管执行进度（detected→...→closed/rolled_back 等 13 态），满足 AS-FSM-01 |
| D4 | git worktree 沙盒 | RepoSandboxRunner：worktree 隔离 + G1-G3 执行 + 超时/截断/进程组杀绝 + 生产隔离（独立 PG schema、环境变量白名单） |
| D5 | Meta Team 图编排 | 见 §5；结构化 JSON 契约 + 事件树挂载 + 重试回路 + 用户介入 |
| D6 | 风险分级规则 | R1 低（config/prompt/docs/i18n/test 单文件 ≤100 行）/R2 中（单文件业务代码非核心 ≤300 行）/R3 高（多文件/核心路径/proto 新增/>300 行）/R4 Critic 强制升级/R5 保护清单直接拒绝；规则运行时可配置（system_settings 持久化，Get/UpdateRiskRules API，未配置继承代码默认） |
| D7 | 应用双通道 + 观察窗 | 配置/Prompt 热加载；代码 commit（self-improvement: true 标记）ff 合并重启生效；Watchdog 5min 扫描，错误率 +50%/P95 +30% 自动 revert |
| D8 | 成效学习 | verdict 判定（closed→effective、rolled_back→regressed、其余→neutral）；负面样本写 KB；触发器连续 3 次无效冷却 ×2 |
| D9 | 保护文件清单 | CI 工作流/Makefile/go.mod/sum/proto 已有消息/DDL 迁移历史/wire_gen.go/Ent 生成物；diff 路径 glob 匹配，Verify 前 fail-fast |
| D10 | 成本控制 | Critic 10 次/日、Patcher 20 次/日、自动应用 5 次/日、观察窗并发 ≤3 |

## 8. 数据模型概要

- **`self_improvement_runs`（新增）**：闭环运行主表。1:1 绑定 suggestion_id；承载运行状态机状态、触发源、补丁（diff/diff_stats/kind）、诊断/验证/Critic/治理四份 JSON 报告、attempts 重试计数、审批人、applied_commit、rollback_pointer、observe_until、metadata 证据。索引：suggestion_id 唯一、status、(trigger_source, created_at)、observe_until（observing 部分索引）。
- **`patch_outcomes`（新增）**：成效记录表。run_id 关联；verdict（effective/neutral/regressed）、metrics_before/after（1h 滑窗 error_rate/p95_ms/alert_count）、rollback_reason、pattern_hash。
- **复用表**：`unified_evolution_suggestions`（platform 行，枚举扩展）、`failure_patterns`（Learn 写入 source=self_improvement，negative=true）。

## 9. 接口概要（biz 层端口，窄接口 ≤5 方法）

| 端口 | 职责 | Stability |
|------|------|-----------|
| SelfImprovementRunReader/Writer | run 查询/创建/CAS 状态迁移/重试计数 | evolving |
| PatchOutcomeWriter | 成效记录创建/按 run 查询 | evolving |
| RepoSandbox | worktree 准备/清理、ApplyDiff、RunGate(G1-G3) | evolving |
| ErrorClusterReader / PerfMetricsReader / EvalBaselineReader / TestRunReader | 4 触发器信号源窄读接口 | evolving |
| RiskClassifier | Classify(patch, critic) → GovernanceDecision（纯代码无 IO） | evolving |
| Applier | ApplyHotReload / ApplyCodeMerge / Rollback | evolving |

`UpdateStatus` 采用 CAS（WHERE status=from）保证状态机迁移原子性，冲突返回 CodeConflict。

## 10. Worker 与配置设计

| Worker | 周期 | 职责 |
|--------|------|------|
| self_improve_observe | 15min | platform 目标 CheckAndCreate；为 pending 建议建 run(detected) 并启动 Meta Team 会话 |
| self_improve_drive | 1min（可配） | 全链驱动：detected 异步 pipeline、中途态陈旧恢复（默认 30m 超时 → detected 重驱动）、awaiting_governance 路由去重、applying 重驱动、applied 晋升 observing |
| self_improve_watchdog | 5min | 扫描 observing 到期 run：滑窗指标对比 → close 或自动 rollback |
| self_improve_outcome | 1h | 终态 run 生成 PatchOutcome + KB 反哺 + 触发器自适应降频 |

配置块 `self_improvement`（默认 `enabled: false` 灰度开启）：observe_interval、error_cluster 阈值、perf 因子、eval 退化阈值、patch 上限/配额/重试、sandbox 超时与 worktree 根/repo_root、observe_window 时长与退化因子/并发上限、drive/watchdog/outcome 周期与 stale_timeout。风险分级规则另经 `system_settings` 运行时持久化（DB > config > 代码默认三级回退）。

## 11. 评审维度映射

| 评审维度 | 权重 | 设计响应 |
|----------|------|----------|
| 场景价值与行业可复制性 | 25% | 「平台改自己」是零人工运维的通用范式；触发器/沙盒/治理三类组件与具体业务解耦，任何 Go 多 Agent 平台可复制该架构 |
| 多 Agent 协同与自主闭环能力 | 25% | §5 完整映射 AgentTeams 五要素；8 环节闭环见需求文档 §2.1；重试回路/置信度降级/用户介入/高风险审批覆盖异常与冲突处理 |
| Skill 工程体系与生态复用 | 25% | 补丁工具集（fs_read/fs_write/git_diff + RepoSandbox Gate）作为 Skill 能力抽象：输入输出 Schema 显式、调用条件由图编排驱动、失败处理为 Gate 证据回传 + 重试上限、安全边界为 worktree 作用域 + 命令白名单；版本（self-improve/<run_id> 分支 + commit 标记）、回滚（rollback_pointer）、质量评估（五级 Gate + verdict 归因）齐备 |
| 工程落地、运行验证与安全可审计 | 20% | 全部构建于已落地 V2 基础设施之上（§7）；证据链：suggestion 证据快照 → run 四份 JSON 报告 → patch_outcomes 指标 → 审计日志；trace/metrics/日志三类可观测数据齐备；保护清单 + 敏感信息检测 + 沙盒隔离 + 配额控制 |
| 开放/开源贡献 | 5% | 接口契约（EvolutionTrigger/RepoSandbox/RiskClassifier/Applier）开源可复用；设计文档公开 |

## 12. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 补丁引入隐性回归（测试未覆盖） | G4 Critic + 观察窗自动回滚 + 高风险人工审批三重兜底 |
| worktree 磁盘膨胀 | 终态即清理；启动扫描残留；单 run worktree 配额 |
| 多补丁观察窗指标互相污染 | 观察窗并发 ≤3；同核心路径补丁串行队列 |
| LLM 生成恶意/敏感内容补丁 | 保护文件清单 + 敏感信息检测（复用 V2 SEL-08）+ Critic 审查 |
| 沙盒命令逃逸 | Gate 命令白名单（仅 go/pnpm/golangci-lint 固定参数）；环境变量白名单；无网络（除 pnpm install） |
| Ent/Proto 生成物被手改 | 保护清单禁手改，仅允许 regenerate 流程 |
| 触发器风暴 | 编排器 pending 去重 + per-action 冷却 + Patcher 日配额 |
