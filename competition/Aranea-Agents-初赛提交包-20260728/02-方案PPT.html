01 · 场景与价值

真实问题：复杂任务需要一支队伍，而不是一个对话框

个人与中小团队的专业工作本质是「跨职能复杂任务」——市调、投研、研发、运营

目标用户

独立开发者、咨询/投研从业者、中小企业主、内容创作者——没有预算雇佣完整团队，但任务需要多种专业能力协同。

核心痛点

  • 单 Agent 天花板：一个对话窗口无法同时扮演研究员、分析师、财务、写手
  • 编排黑盒：多 Agent 过程不可观测、不可调试、不可回溯
  • 经验流失：每次任务从零开始，方法论无法沉淀复用
  • 成本与安全失控：Token 账单不透明，高风险动作无审批无审计

业务价值（可感知收益）

  • 效率：一份带竞品分析与成本估算的策略简报，从「数天人工」到「一次指令、分钟级闭环」
  • 质量：专人专事 + 生成-评审循环，产出经多角色交叉验证
  • 知识沉淀：方法论固化为 Skill，越用越强
  • 风险控制：高风险动作人工确认，全程留痕可审计

行业可复制性

「行业 → 部门 → 岗位」三级组织模板：内置金融（6 部门 / 30+ 岗位 / 8 团队）、自媒体、软件开发三大行业；同一套编排引擎 + Skill 体系可复制到医疗、电商、政务等任何知识密集型行业。

02 · 方案设计 · 设计哲学

设计哲学：让引擎管流程，让模型管执行

流程是制度，不是建议——制度不会偷懒，AI 会

裸循环的三个致命缺口

  • 无质量门控：AI 想跳过审查就能跳过，没人拦得住——如同工厂没有质检关卡
  • 无流程一致性：同样的任务，今天走五步明天走三步，全看 AI 心情
  • 无复用性：好的工作流无法沉淀、无法分享、无法替换

主流方案为什么不够

把"请先规划再动手"写进系统提示词 = 把交通规则写在纸条上递给司机。建议 ≠ 约束。AI 觉得任务简单就跳过规划，写完就说"完成了"没跑测试。我们在路上装红绿灯——把流程写在引擎的确定性逻辑里，而不是提示词里。

四大设计原则

原则实践
硬驱动流程推进由代码逻辑做出，不由 AI 决定。AI 输出的"完成了"只是屏幕上的一行字，不参与推进判定——AI 没有能力跳过任何一个阶段
声明式可插拔工作流即配置包。Team 六模式 / Graph 图编排 / Spirit 动态编排——换一套流程就是换一套配置，引擎不变
正交矩阵「执行者 × 门控」两个维度组合出全部工作流场景：self/delegate × auto/user/conditional
零侵入流程引擎挂载在执行内核之上，随时可拆退回裸循环；引擎 bug 不污染核心循环
与提示词驱动的根本差异：提示词是"建议"，引擎是"约束"。我们把流程交给制度保障，而不是交给 AI 的自觉。

03 · Skill 工程体系 · 必选项 H3

Skill 全生命周期：新生 → 成长 → 消亡 → 重生

Skill 是工程化沉淀单元，不是一次性提示词

新生

  • 自动检测：工具调用 Pattern → Proposal → 审批 → 注册
  • 手动创建：CRUD → Publish（major.minor.patch 版本）
  • 导入融合：六维相似度检测 → LLM 炼化合并

成长

  • 渐进加载：L0 清单 → L1 Body → L2 Refs，省 Token
  • 意图路由：嵌入向量评分自动匹配最相关 Skill
  • Skills Butler：健康度分析 + 优化建议

消亡

  • 30 天无调用 / 成功率 <60% → 消亡建议
  • 人工停用 ToggleEnabled；软删除 deleted_at
  • 磁盘缺失标记 filesystem_missing

重生

  • 版本回滚：历史版本恢复为 published
  • 文件恢复自动清除 missing 标记
  • 自动进化：运行数据中再次发现新模式

安全机制

注册拒绝路径穿越（..//\）；合并失败自动回滚 DB + 磁盘；所有进化必须人工审批。

开放/开源计划与合规披露

清晰披露协议、依赖、商业 API、闭源模型与数据边界

开源范围与协议

  • 运行时内核 trpc-agent-go 已开放（本方案以其为协同执行引擎）
  • 计划开源（Apache-2.0）：三层编排引擎、Skill 工程体系（含自动进化）、五层记忆、工具注册表契约
  • 可复用成果：Skill 包、Agent/团队/行业模板、评测报告与事故回放数据集

第三方依赖

Kratos v2（Apache-2.0）、Ent ORM（Apache-2.0）、Vue 3/Quasar（MIT）、SQLite、models.dev（模型目录数据源）、Playwright MCP——关键版本锁定于 go.mod / package.json，随代码包披露。

商业 API 与闭源模型

  • LLM 为可插拔 Provider（12+：DeepSeek / Qwen / OpenAI / OpenRouter…），按六维定价计量
  • 实跑使用 deepseek-v4-flash / gpt-4.1-mini（商业 API，按量付费，可替换为 Qwen 等开源模型，迁移成本=更换 Provider 配置）
  • 闭源模型仅用于推理，不沉淀私有数据；凭证加密存储

数据来源与授权

演示任务为公开行业信息调研与模拟数据，无企业私有数据；知识库文档由用户自主上传并隔离于自有实例；PII 审查面板支持人工标记审核。

可复现方式

代码包含运行入口 / 依赖说明 / 配置文件 / 样例输入输出；本地一键初始化（make all）+ 免登录开发模式；证据包含实跑会话 ID 与 API 记录可复核。
