## 目标场景与核心问题

零人工运维要求「告警聚合 → 根因定位 → 修复执行 → 恢复验证 → 事故复盘」全链路自主闭环。现实困境：告警风暴淹没根因、MTTR 小时级居高不下、排障经验只存在专家大脑、自动化脚本无法应对未知场景而 AI 直接操作生产又无人敢批。主流多 Agent 方案由 LLM 即兴生成子 Agent，角色边界模糊、约束随上下文稀释、行为不可审计，难以进入生产。

## 方案概述

以 trpc-agent-go 为运行时内核、Kratos v2 为传输层：**岗位化静态编组**（行业→部门→岗位三级科层，304 个职能 Agent，职责/权限/工具白名单先验定义）+ **三层确定性编排引擎**（Team 六模式 / Graph 状态机图 / Spirit 动态规划，任务编译为 DAG 由引擎硬驱动）+ **预规划硬门控**（复杂度评估 + plan confirm，AI 无权跳关）+ **Skill 自动进化**（历史活动观测 → 模式挖掘 → LLM 合成 → 审批注册）+ **五层记忆与团队共享黑板** + **Trace/Log/Metrics 全链路可观测与审批/回滚/审计**。

## 多 Agent 架构（AgentTeams 五要素映射）

角色编排（Orchestrator/Worker/Synthesizer + coordinator）· 任务拆解（plan_and_execute → DAG 拓扑）· 上下文传递（StateFields 共享黑板 + deliverable 产物引用 + 认知信封）· 协同执行（成员并行 + 流式活动树 + 失败降级）· 状态追踪（TeamRun/PlanBoard 状态机 + 会话参与者/运行记录）——五要素全部落地并有实跑实证。

## 关键 Skill 与工具链

- **Skill（必选）**：全生命周期管理（注册/版本/渐进加载/健康治理/消亡重生）+ **自动进化闭环**（观测→模式检测→Pattern Hash 去重→LLM 生成→人工审批→注册发布）。核心清单：alert-diagnosis（告警分诊，运维实跑调用）、InformationResearch（自动进化生成）、planning-and-task-breakdown、idea-refine（各 5100+ 次调用，100% 成功）。
- **工具/MCP**：65 个内置工具（统一注册表契约）+ shell_exec 受控命令执行（8 个运维实操岗位白名单授权）+ MCP Server（Playwright stdio，health=ok）。
- **RAG/上下文**：五层记忆（L0-L4）+ 知识库 RAG（pgvector）+ 团队共享黑板（4 项能力实现 3 项+）。

## Demo 运行结果（2026-07-29 实跑，TS-9）

任务：电商平台订单服务 P2 生产事故（502 错误率 23% + 慢查询 47s + IO 98% + 连接池耗尽，大促 19:00 峰值前必须恢复）。精灵先产出 3 个澄清问题 → plan_and_execute 规划 4 团队 DAG（告警分诊→根因定位→修复方案→恢复执行），plan draft **人工 confirm 硬门控**后执行 → 分诊确认 P2 定级（confidence=0.95）→ 根因链定位（未评审变更→缺复合索引→全表扫描→池耗尽→502，三层根因置信度 95/90/85%）→ 修复方案（首要回滚 + 后备 pt-osc 在线加索引）→ 恢复执行（**高危操作先审批**：回滚 v1.2.9→v1.2.8、pt-osc 128s 加索引 874 万行无锁表）→ 验证全部达标：**502 23%→0.03%、慢查询 187→2/min、HikariCP 198→85、QPS 45→320，人工介入 0 次** → 复盘文档专家产出 12K 字标准复盘报告。**9 大测试场景全通过，五维自评 90/100**，UI 截图 + API 记录 + 20+ 份运维闭环原始证据可复核。

## 开放/开源贡献

运行时内核 trpc-agent-go 已开放；计划 Apache-2.0 开源三层编排引擎、Skill 工程体系（含自动进化）、五层记忆与工具契约；可分发 Skill 包、行业岗位模板包（IT 运维/金融/自媒体/软件研发）与评测数据集。

## 业务价值与可复制性

P2 事故处置从「小时级人工排查」到「分钟级自主闭环」，MTTR 数量级下降；处置经验固化为 Skill 与复盘知识库，平台随事故处置持续进化；「行业→部门→岗位」模板 + 统一编排引擎可复制到金融、政务、能源等任何有运维闭环诉求的行业。

## 后续计划与对接需求
