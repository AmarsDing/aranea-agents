# Aranea-Agents · 初赛提交包

> 赛道：赛道一「新智基座丨Agent Infra」—— **方向一：零人工运维**
> 阶段：初赛（2026-07-16 ~ 2026-08-16）· 打包日期：2026-07-28（2026-07-29 更新运维叙事与 TS-9 证据）
> 项目名称：**Aranea-Agents —— 以社会分工规则组织 AI、以历史活动驱动自我进化的岗位化多 Agent 编排平台**

---

## 问题与痛点（运维行业共性 → 我们的解法）

| 痛点 | 行业现状 | Aranea-Agents 解法 |
|------|---------|-------------------|
| **告警风暴** | 一次故障触发上百条告警，真实根因被噪音淹没 | 告警处理专家聚合降噪 + P 级定级 + 根因方向初判（alert-diagnosis Skill） |
| **AI 无质量门控** | AI 想跳过审查就能跳过，没有人拦得住 | 预规划复杂度评估 + plan confirm 硬门控 + 三层编排引擎状态机推进，AI 输出的"完成了"不参与推进判定 |
| **子 Agent 即兴生成不可控** | LLM 临时生成子 Agent，角色边界模糊、约束随上下文稀释、行为不可审计 | 岗位化静态编组：行业→部门→岗位三级科层，职责/权限/工具白名单先验定义，方向约束不漂移 |
| **经验无法沉淀** | 排障方法论只在专家大脑里，复盘报告写完即归档 | Skill 自动进化（高频模式 → LLM 生成 → 审批注册）+ 复盘报告入知识库，平台随事故处置自我生长 |
| **自动化不敢放权** | 脚本无法应对未知场景，AI 操作生产无人敢批 | 岗位工具白名单 + 高危动作强制人工审批 + 版本回滚 + 全程审计；AutoHopState 连跳上限防全自动空转 |

> 上述痛点为零人工运维场景共性问题的提炼，与我们的架构设计形成完整映射。

## TS-9 零人工运维闭环速览（方向一·核心证据）

> 2026-07-29 实跑：电商平台订单服务 P2 生产事故（502 错误率 23% + 慢查询 47s + IO 98% + 连接池耗尽），大促 19:00 峰值前必须恢复。

```
事故输入 → Spirit 意图澄清（3 问）→ DAG 规划 4 团队（plan confirm 硬门控）
  → 团队1 告警分诊（P2 定级，confidence=0.95，39 活动）
  → 团队2 根因定位（未评审变更→缺索引→全表扫描→池耗尽→502，55 活动）
  → 团队3 修复方案（回滚首要 + pt-osc 后备，39 活动）
  → 团队4 恢复执行（高危审批→回滚 v1.2.9→v1.2.8→pt-osc 128s 加索引，91 活动）
  → 复盘文档专家 12K 字复盘报告
验证指标：502 23%→0.03% · 慢查询 187→2/min · HikariCP 198→85 · QPS 45→320 · 人工介入 0
```

实测中发现并修复 5 个缺陷（Plan 状态传播 / 权限语义 / 受控命令执行白名单 / deliverable topic / 会话树 root），均有回归测试——详见 06 报告 §5.4。
