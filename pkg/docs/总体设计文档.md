# 系统定位：
   明确这是一个“多智能体任务编排平台”，能让用户通过可视化界面，像搭乐高一样组装LLM、工具、子Agent，形成自动化工作流

  - 后端：golang
  - 前端：quasar
  - 数据库：sqlite


五层记忆架构设计与 ADK-Go 实现映射
设计原则：层次越往下，容量越大、访问越慢、持久性越强；层次越往上，容量越小、访问越快、时效性越强。这五个层次分别为：

L0：瞬时记忆

L1：工作记忆

L2：会话/事件记忆

L3：语义/知识记忆

L4：跨会话持久记忆（进化记忆）

以下是完整的分层需求定义：

层级	名称	定义与功能	处理机制	生命周期	容量与约束	检索方式	调用模式	ADK-Go 实现映射
L0	瞬时记忆 / 感知记忆	LLM 上下文窗口内的即时信息——当前对话轮次、最后 N 条消息、当前工具调用参数。参考认知心理学 Atkinson-Shiffrin 模型中的"感官记忆"	- 由 LLM 原生上下文窗口自动管理
- 采用 FIFO（先进先出）队列机制维护
- 超过窗口长度的部分自动溢出	单轮对话内	受限于模型上下文窗口（通常 128K-2M tokens）
- 建议保留最近 N 轮（可配置，默认 10-15 轮）
- 不持久化	LLM 原生注意力机制	直接访问	Session State + Context Compaction：ADK-Go 的 session.State 维护消息历史，搭配上下文压缩工具（adk-utils-go 中的 context compaction 功能）防止窗口溢出
L1	工作记忆 / 核心记忆	当前任务关键信息的结构化快照——任务目标、中间结果、活跃约束、当前子任务状态。参考认知心理学的工作记忆（Working Memory）模型，容量有限但访问极快	- 由编排 Agent 主动读写
- 支持结构化格式（JSON Schema）
- 任务切换时自动置换
- 关键信息从 L2 检索后注入	单次任务（多轮）	- 容量严格受限（建议 2K-8K tokens）
- 只保留当前任务最相关的信息
- 任务结束时归档到 L2
- 支持显式读写 API	结构化字段直接访问	读写 API	Session State + Structured Data：session.State 维护结构化键值对，作为任务级的工作记忆存储
L2	会话记忆 / 事件记忆	当前会话内所有交互历史的完整记录——消息流、工具调用记录（参数/返回）、决策依据、错误与修复记录、子任务完成情况。类似人类"情景记忆"（Episodic Memory），记录「发生了什么」	- 由 Runner 自动记录，无需 Agent 显式操作
- 支持按时间线结构化存储（含时间戳、Agent ID、事件类型）
- 关键事件由智力 Agent 标记为高价值后提取到 L3
- 支持按时间范围、事件类型、Agent ID 过滤	当前会话周期（可跨多小时）	- 全量记录，无容量硬限制（不进入上下文窗口）
- 存储格式：结构化 JSON/Protobuf
- 支持检查点与断线续传
- 会话关闭后根据策略归档或清理	时序过滤 + 向量语义检索	查询 API	Session History + Artifact Service：ADK-Go Runner 自动将事件存入 Session History，通过 ArtifactService 持久化大型二进制结果（如图片、文档）；session 包支持检查点，实现断线续传
L3	语义记忆 / 知识记忆	跨会话持久化的结构化知识——用户偏好、项目规范、编码风格、技术栈信息、领域知识片段、常见错误与修正方案。类似人类"语义记忆"（Semantic Memory），存储抽象的、事实性的知识。参考 Claude Code CLAUDE.md + Auto Memory 的组合思想，但引入向量语义检索和结构化存储	- 从 L2 中自动抽取高价值信息（LLM 驱动或规则驱动）
- 每条记忆附元数据：来源会话 ID、创建时间、置信度、最后使用时间、使用频率
- 支持记忆版本化（可追溯修改历史）
- 支持显式增删改查 API
- 引入用户反馈作为信号：确认（强化）、反驳（衰减）、长期未使用（归档或弱化）	跨会话持久化（数天到数月）	- 单条记忆建议 ≤ 500 tokens
- 总数上限可配置（建议 500-2000 条）
- 支持按 Agent 作用域隔离（用户级、项目级、组织级，参考 Claude Code 三级作用域）
- 存储后端：向量数据库（Milvus/Qdrant）或 PostgreSQL + pgvector	向量语义检索 + 元数据过滤（按 Agent ID、时间范围、知识领域）	查询 API	Memory Service：ADK-Go 内置的 memory.Service 提供语义存储与检索，支持向量/嵌入式检索；搭配 Vertex AI RAG Engine 或外部向量数据库（Milvus）实现生产级向量存储
L4	持久记忆 / 进化记忆	长期积累的结构化知识图谱与行为模式——跨项目经验、因果推理链路、Agent 协作模式、进化后的行为策略、多 Agent 协调规则。参考 Prism（进化记忆基底，熵门控分层+因果图谱）和 CraniMem（计划性巩固循环与效用标签驱动遗忘）的设计	- 从 L3 中通过后台 Job 异步提取高阶模式（抽象化）
- 构建并维护因果知识图谱（实体-关系-置信度-来源）
- 支持多 Agent 共享记忆区域（Global Memory Bus）
- 记忆生命周期管理：
  • 巩固（Consolidation）：定期从 L3 提取高阶模式写入 L4
  • 衰减（Decay）：基于使用频率的置信度衰减，低频记忆自动降级或归档
  • 遗忘（Forgetting）：明确过时或错误的信息主动标记为无效
  • 冲突解决：同事实存在多个版本时，按来源可信度和时间戳仲裁
- 支持记忆联邦，跨 Agent 社区共享	跨会话持久化（数月至数年）	- 以知识图谱为主、文档为辅的结构
- 实体数上限可配置（建议 1万-10万）
- 关系类型可扩展
- 支持 Schema 演化与向后兼容
- 附带完整审计轨迹（谁创建、何时修改、来源会话）	图遍历 + 语义检索 + 因果推理路径查询	高级查询 API（图查询语言或 DSL）	知识图谱 + 定期巩固 Job：通过 ADK 的向量化记忆存储能力实现语义层；知识图谱层可通过 Vertex AI Search / 外部图数据库（Neo4j）实现；巩固 Job 由后台 goroutine 定期执行（心跳驱动），实现计划性巩固循环
三、跨层协调机制与调度策略
机制	触发条件	执行动作	ADK-Go 实现方式
L0→L2 自动记录	每轮对话结束	消息和工具调用自动写入 L2 Session History	Runner 自动执行，无需 Agent 显式操作
L2→L3 提取	会话结束 / 关键事件标记 / 达到提取阈值	从 L2 会话记录中抽取高价值事实，去重后写入 L3	周期性 goroutine 调用 LLM 进行提取（类似 CraniMem 的巩固循环）
L3→L4 抽象化	定时触发（建议每 N 小时）或数据积累到阈值	从 L3 语义记忆中提取高阶模式、因果关系、跨项目经验，构建/更新图结构	后台 Job，基于图数据库批量处理（类似 Prism 的心跳驱动巩固控制器）
L3→L1 上下文注入	新任务开始时	基于任务描述，从 L3 语义检索最相关的知识注入 L1 工作记忆	编排 Agent 在任务初始化时调用 Memory Service 检索并写入 session.State
L4→L1 深层注入	复杂任务 / 跨域任务	从 L4 知识图谱进行图遍历 + 因果推理，提取相关因果链路和历史经验注入 L1	编排 Agent 按需调用图查询接口
L4 遗忘与衰减	定时触发（建议每 M 小时）	低频记忆置信度衰减，低于阈值的实体归档；过时信息标记为无效；冲突记忆按仲裁策略解决	后台 Job，基于使用频率和时效性的自动衰减（参考 Prism 的复制子-衰减动态和 CraniMem 的门控机制）
用户反馈信号	用户显式确认/反驳	确认→强化对应记忆置信度；反驳→衰减对应记忆置信度	Agent 调用 L3 Memory Service 更新置信度字段
冲突解决	同一事实多版本共存（如不同 Agent 或不同会话得出矛盾结论）	基于来源可信度权重和时间戳仲裁，或标记为"待确认"等待用户干预	编排 Agent 调用冲突检测模块，结合 MemArchitect 的策略驱动记忆治理机制进行裁决
四、多智能体共享记忆总线设计（Global Memory Bus）
在多 Agent 系统中，仅靠分层是不够的——还需要解决记忆共享与协调问题，参考 Mesh Memory Protocol 和 Token Coherence 协议的设计思想。

设计要素	具体需求	ADK-Go 实现映射
共享语义总线	所有 Agent 可向同一总线发布和读取记忆，支持细粒度权限控制（读/写/管理）	通过 memory.Service 的多租户实例或共享向量数据库实现。所有 Agent 通过同一 memory.Service 接口访问共享记忆空间
A2A 协议集成	标准化 Agent 间记忆传递协议，Agent 可通过"Agent Card"自动发现其他 Agent 的记忆能力并请求其记忆上下文	搭配 ADK 原生 A2A 协议实现跨 Agent 记忆请求与上下文共享
事件驱动同步	状态变更通过消息总线实时广播给所有订阅该类型事件的 Agent，减少冗余通信	基于 Blackboard/Event Bus 模式，中心化上下文管理，降低冗余通信，提升容错一致性
记忆隔离与联邦	Agent 级别记忆隔离（私有空间）+ 项目/组织级别记忆共享（共享空间），支持跨 Agent 社区的全局知识联邦	通过 AppName、UserID、SessionID 作用域机制天然支持记忆隔离
通过独立的"共享作用域"实例实现记忆联邦
一致性与冲突管理	多 Agent 同时更新同一知识时的版本控制与一致性保障，参考 Token Coherence 协议的 MESI 风格缓存一致性	乐观锁（基于时间戳的版本号）+ 冲突检测模块

六、MVP 实施建议
Phase 1（核心可用）：

在 ADK-Go 中实现 L0（Session State + 上下文压缩）、L1（结构化 Session State）和 L2（Runner 自动记录 + ArtifactService 持久化），确保单 Agent 具备基础的会话记忆能力。

这三层完全基于 ADK-Go 的原生能力，无需外部依赖。

Phase 2（跨会话记忆）：

引入 L3 语义记忆层——部署向量数据库（如 Milvus 或 Qdrant），集成 ADK 的 memory.Service。

实现 L2→L3 的自动提取管道和 L3→L1 的上下文注入机制。

引入用户反馈信号机制（确认/反驳）驱动记忆强化与衰减。

Phase 3（深度记忆与多 Agent 共享）：

接入图数据库（如 Neo4j），构建 L4 知识图谱层。

实现 L3→L4 的后台巩固 Job 和 L4→L1 的深层注入。

建设共享记忆总线（Global Memory Bus），实现多 Agent 记忆的同步、隔离与联邦。

实现记忆衰减与遗忘机制（基于 CraniMem 的门控 + 效用标签方案或 Prism 的复制子-衰减动态）。

接入 A2A 协议，实现跨 Agent 记忆传递与上下文共享。

Phase 4（自适应与进化）：

引入自适应触发机制：当检索准确率低于阈值或数据分布发生显著变化时，自动触发 L3/L4 的记忆重组（参考 EVOLVE-MEM 的自适应触发思路）。

实现多 Agent 记忆冲突的自动仲裁与治理（参考 MemArchitect 的策略驱动记忆治理机制）。
