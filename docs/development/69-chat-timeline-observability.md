## 1. 背景与问题

当前 Chat UI 界面与需求存在严重差距：

| # | 问题 | 用户影响 | 严重度 |
|---|------|----------|--------|
| P0-1 | 左侧面板团队列表无数据（`loadSpiritTeams` 从未被调用） | 用户看不到任何进行中/已完成的团队 | 致命 |
| P0-2 | WS 重连后团队数据丢失（无 reload 逻辑） | 网络波动后团队列表清空 | 致命 |
| P1-1 | 消息展示不按思考→动作→思考→动作→总结→结束的时间线脉络 | 用户无法清晰理解 Agent 执行进展 | 高 |
| P1-2 | Team 会话禁用 TurnBlock 模式，消息逐条展示 | Team 执行过程缺乏结构化展示 | 高 |
| P2-1 | TaskExecutionPanel 未集成三区布局组件（ParallelTeamOverview/TeamProgressCard/SynthesisResultCard） | 团队执行面板信息不完整 | 高 |
| P2-2 | 左侧面板仍显示完整 Agent 列表（需求要求仅显示精灵+团队树） | 违反精灵为唯一入口的设计原则 | 高 |
| P3-1 | 三阶段编排（Plan→Allocate→Orchestrate）前端无可视化 | 用户无法感知编排过程 | 中 |
| P3-2 | DAG 编排图和并行团队概览组件孤立未引用 | 组件已编写但未集成 | 中 |

## 2. 用户故事

### US-01 团队列表数据正常显示

**作为** 用户
**我希望** 在 Chat 左侧面板看到进行中和已完成的团队列表
**以便** 我能一目了然了解当前任务进展

**验收**：
- 选择 Spirit Agent 的 session 后，自动调用 `loadSpiritTeams` 加载团队数据
- 进行中团队显示在"进行中"分组下，包含团队名称、任务摘要、状态标签、进度条、成员头像
- 已完成团队显示在"已完成"分组下，可折叠查看
- WS 重连后自动调用 `reloadTeams` 恢复团队数据
- 切换 session 时调用 `spiritStore.reset()` 清理旧数据

### US-02 思考-动作时间线展示

**作为** 用户
**我希望** 每轮对话按时间线展示 Agent 的思考-动作交替过程
**以便** 我能清晰理解事情进展的脉络

**验收**：
- 每轮对话按以下时间线结构展示：

```
┌─ Turn 1 ──────────────────────────────────────────────┐
│ 👤 用户消息                                            │
│                                                        │
│ 🧠 思考：分析用户需求...                               │  ← reasoning 折叠展示
│ ⚡ 动作：read_file("main.go")                          │  ← 工具执行卡片（折叠态）
│ 🧠 思考：根据文件内容...                               │  ← reasoning 折叠展示
│ ⚡ 动作：save_file("main.go", ...)                     │  ← 工具执行卡片（折叠态）
│ 🧠 思考：验证修改结果...                               │  ← reasoning 折叠展示
│ 📋 总结：已完成代码修改，主要变更...                     │  ← 最终回复（展开态）
│ ✅ 结束                                                │  ← Turn 完成标记
└────────────────────────────────────────────────────────┘
```

- 时间线元素类型与展示规则：

| 元素类型 | 图标 | 展示方式 | 折叠策略 |
|----------|------|----------|----------|
| 用户消息 | 👤 | 始终展开，markdown 渲染 | 不折叠 |
| 思考（reasoning） | 🧠 | 折叠态显示最后 2 行，展开显示完整思考 | 完成后自动折叠 |
| 动作（tool_call） | ⚡ | 折叠态显示工具名+状态+耗时，展开显示参数和结果 | 完成后自动折叠 |
| 总结（final answer） | 📋 | 始终展开 | 不折叠 |
| 结束（turn end） | ✅ | 状态标记 | 不折叠 |
| 错误（error） | ❌ | 错误摘要 | 不折叠 |

- Team 会话同样支持时间线模式
- 左侧显示时间线连接线（竖线 + 节点圆点）

### US-03 任务执行面板三区布局

**作为** 用户
**我希望** 点击团队后看到完整的三区布局执行面板
**以便** 我能实时观察团队的工作进展

**验收**：
- TaskExecutionPanel 集成已编写的三区布局组件：
  - 并行团队概览区（ParallelTeamOverview）
  - 团队进度卡片（TeamProgressCard）
  - 综合结果区（SynthesisResultCard）
  - 中断恢复提示（InterruptedTeamCard）
- 执行时间线使用新的时间线展示模型

### US-04 左侧面板简化为精灵+团队树

**作为** 用户
**我希望** 左侧面板仅显示精灵入口和团队列表
**以便** 我不需要理解系统中有哪些 Agent

**验收**：
- 隐藏 Agent 分组列表（保留 SpiritEntry）
- 仅显示：精灵入口 + 进行中团队 + 已完成团队
- 搜索框搜索范围限定为团队名称
- 符合 US-01（精灵为唯一对话入口）的设计原则
