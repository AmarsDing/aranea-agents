## 1. 用户故事

### US-1 评估数据集管理

**作为** Agent 开发者，**我希望** 创建和管理评估数据集（包含输入/期望输出对），**以便** 为 Agent 质量评估提供标准化的测试用例。

**验收标准**：
- 可创建评估数据集（名称、描述）
- 可上传评估用例（JSON 数组，每条包含 input + expected_output）
- 可查看、更新、删除数据集
- 数据集显示用例数量

### US-2 运行评估

**作为** Agent 开发者，**我希望** 对指定 Agent 运行评估，**以便** 获取 Agent 在评估数据集上的质量分数。

**验收标准**：
- 可选择数据集和 Agent 启动评估
- 评估异步执行，不阻塞调用方
- 可查看评估运行状态（pending → running → completed/failed）
- 可查看评估运行进度（已完成用例数/总用例数）
- 可选择运行的评估指标子集
- 可删除评估运行（级联删除结果）

### US-3 评估指标

**作为** Agent 开发者，**我希望** 通过多种指标评估 Agent 输出质量，**以便** 从不同维度了解 Agent 表现。

**验收标准**：
- 精确匹配（exact_match）：不区分大小写的字符串相等判定
- 包含匹配（contains_match）：期望输出出现在实际输出中
- LLM-as-Judge（llm_as_judge）：LLM 评判模型打分 [0,1]
- 工具调用准确率（tool_call_accuracy）：期望工具在输出中被提及的比例
- 可按需选择指标子集运行

### US-4 评估结果查看

**作为** Agent 开发者，**我希望** 查看评估运行的详细结果，**以便** 了解每个用例的具体表现。

**验收标准**：
- 可查看运行汇总分数（各指标平均分）
- 可查看逐用例结果（输入、期望输出、实际输出、各指标得分）
- 可按数据集/Agent/状态筛选运行列表

### US-5 自动评估触发

**作为** Agent 开发者，**我希望** Agent 运行后自动触发评估，**以便** 无需手动操作即可持续监控 Agent 质量。

**验收标准**：
- Agent 完成对话 turn 后可自动触发关联的评估
- 可配置自动评估的触发条件和关联数据集

### US-6 人工评估标注

**作为** Agent 开发者，**我希望** 对自动评估结果进行人工标注，**以便** 纠正自动评估的偏差并积累高质量标注数据。

**验收标准**：
- 可对评估结果进行人工通过/不通过标注，也可清除已有标注恢复未标注状态
- 可添加人工评语
- 人工标注结果与自动评估结果并存展示

### US-7 评估报告与趋势

**作为** Agent 开发者，**我希望** 查看评估报告和趋势，**以便** 了解 Agent 质量的变化趋势和对比不同版本的表现。

**验收标准**：
- 可生成评估报告（汇总分数、用例分布）
- 可查看同一 Agent 不同时间运行的分数趋势
- 可导出评估报告

### US-8 高级评估能力（超越层）

**作为** Agent 开发者，**我希望** 使用更高级的评估能力，**以便** 更全面地评估复杂 Agent 行为。

**验收标准**：
- 支持多轮对话评估（UserSimulation）
- 支持多次运行取平均（MultiRun），减少随机性
- 支持 Tool Trajectory 评估（工具调用序列匹配）
- 支持 Final Response 多维度评估（文本/JSON/ROUGE/XML）
- 支持 pass@k / pass^k 指标
- 支持 A/B 对比不同 Agent 版本

### US-9 对话沉淀为用例（评估飞轮）

**作为** Agent 开发者，**我希望** 把真实对话一键转为评估用例，**以便** 回归集来自生产沉淀而非手写。

**验收标准**：
- 对话任务卡片可一键发起「加入评估」，预填用户问题与 Agent 回答
- 可选择已有数据集或内联新建数据集
- 用例携带溯源元数据（来源任务/会话），可回溯
- 移动端任务页同样可发起并弹出转化对话框

### US-10 负反馈采集与转化

**作为** Agent 开发者，**我希望** 用户对回答的点踩自动进入待审查列表并可一键转为用例，**以便** 失败样本快速进入回归集。

**验收标准**：
- 任务卡片提供 👍/👎 反馈按钮，提交含上下文快照（任务删除后审查列表仍自包含）
- 负反馈在评估页「待审查」列表可见（时间/问题/回答/备注）
- 待审查条目可一键转为评估用例

### US-11 Judge 校准（分歧统计）

**作为** Agent 开发者，**我希望** 看到 LLM 评判与人工标注的一致性统计与分歧明细，**以便** 识别 judge 的失败模式并迭代评分标准。

**验收标准**：
- 可按数据集（可选 Agent）查看一致率、false_pass/false_fail 计数
- 可查看分歧用例明细（输入/期望/实际/judge 分/人工判定/评语）

### US-12 用例级评分标准（rubric）

**作为** Agent 开发者，**我希望** 为单条用例指定评分标准文本，**以便** LLM 评判按用例语境打分会比默认准则更准确。

**验收标准**：
- 转用例/上传用例时可填写 rubric（可选）
- 运行勾选 llm_as_judge 时 judge 评语体现该评分标准；未勾选时不影响运行

### US-13 发布质量门禁

**作为** Agent 开发者，**我希望** 为 Agent 配置发布质量门禁（关联数据集、指标、最低分与最大跌幅），**以便** skill 发布与 pack 安装时自动触发回归评估，分数不达标时收到告警通知。

**验收标准**：
- 可配置门禁：开关、关联 Agent、关联数据集、指标、最低分、最大跌幅
- skill 发布与 pack 安装时自动对配置的数据集后台异步触发一次回归（in-flight 去重，不阻塞发布主流程）
- 分数低于最低分，或相对最近一次已完成运行的基线跌幅超过阈值时，发出 advisory 告警通知（不阻断发布）
- 唯一硬阻断：配置了最大跌幅但无任何已完成基线运行时，返回冲突提示并自动启动基线评估
- 门禁未启用或不可用时不影响正常发布流程

### US-14 在线评估看板

**作为** Agent 开发者，**我希望** 在线自动评估支持采样率配置、趋势按触发来源拆分、分数连跌触发告警，**以便** 以可控成本持续监控生产质量并第一时间发现质量退化。

**验收标准**：
- after_turn 自动评估可配置采样率（0,1]，越界值自动归一为全量（向后兼容既有配置）
- 趋势面板可按触发来源（手动/自动/门禁）筛选，拆分在线与离线序列
- 在线运行分数连续 N 次严格下跌时触发系统通知（N 可配，0 为关闭）
- 告警关注的指标可配置（默认 llm_as_judge）

### US-15 失败归组

**作为** Agent 开发者，**我希望** 失败用例按错误信息聚合展示，**以便** 快速定位高发失败模式而非逐条翻看失败记录。

**验收标准**：
- 可按数据集查看失败归组：错误信息、出现次数、涉及运行数、最近发生时间
- 归组结果按出现次数降序排列
- 数据集下运行全部到达终态后，看板自动刷新归组数据

### US-16 Pairwise 偏好裁决

**作为** Agent 开发者，**我希望** 在 A/B 对比结果上人工裁决「哪个更好」并沉淀偏好记录，**以便** 为版本选择积累可追溯的人工偏好数据。

**验收标准**：
- A/B 对比结果行可标记「更优」并附评语
- 偏好记录持久化，可按数据集查询历史偏好列表
- 胜者必须是参与对比的两个运行之一，否则提交被拒绝

### US-17 红队用例包

**作为** Agent 开发者，**我希望** 导入预制对抗用例集（prompt 注入/越权/数据泄漏）并获得攻击成功率指标，**以便** 对 Agent 做安全回归。

**验收标准**：
- 预制红队用例集可经既有用例 JSON 导入通道入库
- 用例元数据携带攻击类别标记
- 运行后输出攻击成功率指标，两种评估执行路径（legacy 与 framework）均支持

### US-18 数据集版本快照

**作为** Agent 开发者，**我希望** 每次评估运行记录所基于的数据集版本快照，**以便** 在对比历史运行时识别数据集已变更、分数不可直接比较的情况。

**验收标准**：
- 运行启动时自动记录数据集内容 hash
- 对比接口返回每个运行的数据集 hash
- 参与对比的运行间 hash 不一致时，对比界面给出「数据集已变更，分数不可直接比较」的明确提示

## 2. 功能规格

### 2.1 评估数据集

| 属性 | 说明 |
|------|------|
| 名称 | 必填，数据集标识 |
| 描述 | 选填，数据集说明 |
| 用例数 | 自动统计 |
| 用例格式 | JSON 数组，每条包含 input + expected_output，可选 metadata（多轮对话、用户模拟、期望工具调用等高级配置，详见设计文档） |

### 2.2 评估运行

| 属性 | 说明 |
|------|------|
| 关联数据集 | 必填 |
| 关联 Agent | 必填 |
| 运行状态 | pending → running → completed / failed |
| 指标选择 | 逗号分隔的指标键名，空值运行 4 种核心指标；扩展指标 opt-in（见 §2.3） |
| 重复次数 | MultiRun 重复次数（默认 1）；>1 时计算 pass@k / pass^k |
| 用户模拟 | 启用 UserSimulation（脚本或 LLM，见用例 metadata） |
| 执行方式 | 异步，创建后立即返回，后台执行 |

### 2.3 评估指标

#### 核心指标（metrics 为空时默认全开）

| 指标 | 键 | 计算方式 |
|------|-----|----------|
| 精确匹配 | `exact_match` | FinalResponse 精确文本匹配 |
| 包含匹配 | `contains_match` | FinalResponse 包含期望文本 |
| LLM-as-Judge | `llm_as_judge` | Judge 模型对 (input, expected, actual) 打分 [0,1] |
| 工具调用准确率 | `tool_call_accuracy` | 期望工具在输出中被提及的比例（legacy）；或 ToolTrajectory 简化版 |

#### 扩展指标（opt-in，逗号加入 metrics）

| 指标 | 键 | 说明 |
|------|-----|------|
| JSON 匹配 | `json_match` | FinalResponse JSON 结构匹配 |
| XML 匹配 | `xml_match` | FinalResponse XML 结构匹配 |
| ROUGE-L | `rouge_l` | FinalResponse ROUGE-L（阈值 0.5） |
| 工具轨迹 | `tool_trajectory` | 顺序敏感完整 ToolTrajectory 匹配 |

### 2.4 Eval LLM 模型配置

UserSim 与 LLM-as-Judge 共用 Provider 目录凭证；模型解析优先级：环境变量 > 系统设置 > 目录 mini/flash。

| 来源 | 说明 |
|------|------|
| 环境变量 | UserSim 与 Judge 专用变量，优先级最高 |
| 系统设置 | Settings 页持久化；前端默认 UserSim 为 openai / gpt-4o-mini |
| 目录回退 | Provider 目录首 mini/flash 模型 |

### 2.5 评估结果

| 属性 | 说明 |
|------|------|
| 汇总分数 | 各指标在全部用例上的平均分 |
| 逐用例结果 | 每条用例的 actual_output + 各指标得分/判定 |
| 执行耗时 | 运行开始到结束的时间 |

## 3. 验收标准总览

1. 可创建评估数据集并上传用例
2. 可对指定 Agent 运行评估（异步）
3. 四种内置指标可按需选择运行
4. 可查看运行汇总分数和逐用例结果
5. Agent 运行后可自动触发评估（US-5）
6. 评估结果可人工标注（US-6）
7. 可查看评估报告和趋势（US-7）— 客户端导出 + 趋势/A/B API
8. 高级评估：多轮/UserSim/扩展指标/pass@k/趋势对比（US-8）
9. Eval LLM 可在系统设置页配置并持久化
10. 可更新数据集名称/描述、删除评估运行（级联）
11. 对话可一键转为评估用例（US-9）
12. 点踩反馈进入待审查列表并可转用例（US-10）
13. judge/人工分歧统计可查（US-11）
14. 用例级 rubric 可录入并注入 judge 准则（US-12）
15. 发布质量门禁可配置，skill 发布 / pack 安装时异步触发回归，低于阈值 advisory 告警（无基线时硬阻断）（US-13）
16. 在线评估采样率可配、趋势按触发来源拆分、分数连跌触发系统通知（US-14）
17. 失败用例按错误信息归组可查（US-15）
18. A/B 对比可人工裁决更优并沉淀偏好记录（US-16）
19. 红队用例包可导入并输出攻击成功率（US-17）
20. 运行记录数据集 hash，对比时数据集变更给出提示（US-18）

> 实现进度与状态追踪见 [开发计划文档](./33-evaluation-development.md)

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 性能 | 100 用例数据集在 5 分钟内完成评估 |
| 可观测 | 评估运行次数和用例执行耗时通过 Prometheus 暴露 |
| 成本 | LLM-as-Judge 消耗 LLM Token，需支持按需启用/禁用 |
| 可靠性 | 评估运行失败不影响正常 Chat 流程 |
