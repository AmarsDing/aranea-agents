# Overview 指挥中心 — 需求文档

## 1. 背景与动机

### 1.1 现状

当前 OverviewPage（`/overview`）定位为**用量/成本仪表盘**，首屏内容为筛选栏 + 用量指标卡片，侧重于 LLM 调用量、Token 消耗、费用、Provider 健康等运营指标。用户登录后进入首页，第一眼看到的是"模型消耗概览"标题和筛选控件，缺少系统全局状态的即时感知和快捷操作入口。

### 1.2 行业对标

调研了 GoClaw、OpenClaw-Admin、OpenClaw Dashboard-v2、OpenClaw Mission Control、OpenClaw Command Center 等开源 AI Agent 平台的 Dashboard 首页设计，提炼出三种主流模式：

| 模式 | 代表系统 | 核心特点 |
|------|----------|----------|
| 驾驶舱模式 | Mission Control / Dashboard-v2 | 多面板网格、实时推送、信息密度高 |
| 数据仪表盘模式 | OpenClaw-Admin / 当前 Aranea | 筛选+趋势+分布+排行、分析驱动 |
| 工作台模式 | OpenClaw Control UI | Chat 为主、监控为辅 |

### 1.3 问题

1. **首屏缺乏全局感知**：用户无法一眼掌握 Agent 状态、会话活跃度、系统健康等核心信息
2. **缺少快捷操作**：进入首页后无法快速跳转到常用功能（新建对话、创建 Agent 等）
3. **实时性不足**：当前数据依赖手动刷新或轮询，无法做到零刷新实时更新
4. **Hero 区域信息量低**：当前 Hero 仅展示"模型消耗概览"标题，未利用首屏黄金位置

## 2. 需求目标

将 OverviewPage 从**用量仪表盘**升级为**智能体指挥中心**，融合驾驶舱的实时感 + 数据仪表盘的分析力 + 工作台的快捷入口。

### 2.1 核心目标

| # | 目标 | 衡量标准 |
|---|------|----------|
| G1 | 首屏即可感知系统全局状态 | 无需滚动即可看到 Agent/会话/Provider/系统 4 大维度状态 |
| G2 | 提供快捷操作入口 | 从首页 1 次点击即可进入新建对话/创建 Agent/查看告警 |
| G3 | 保留现有用量分析能力 | 现有筛选/趋势/分布/排行/告警功能不丢失 |
| G4 | 提升实时性 | 关键状态面板通过 WebSocket 或短轮询自动更新 |

## 4. 非功能需求

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| NFR-1 | 首屏加载时间 < 2s（不含趋势图异步组件） | P1 |
| NFR-2 | 所有新组件支持 Dark mode | P1 |
| NFR-3 | 响应式布局：桌面 4 列 / 平板 2 列 / 手机 1 列 | P1 |
| NFR-4 | 遵循前端数据流铁律：展示组件仅 props/emits，状态收敛在 Store | P1 |
| NFR-5 | 新组件 CSS 遵循 UX 规范（`--color-accent` 主色调，backdrop-filter 成对） | P1 |

## 5. 不在范围内

| 排除项 | 原因 |
|--------|------|
| WebSocket 实时推送（本次仅用短轮询） | 需要后端配合，本次聚焦前端展示层 |
| 命令面板（Cmd+K） | 独立功能，不在本次范围 |
| 像素风/虚拟办公室等创意 UI | 与项目风格不符 |
| 后端新增 API | 本次复用现有 API，不新增后端接口 |

## 6. 用户故事

### US-1：运维人员快速感知系统状态

> 作为运维人员，我登录后第一眼就能看到 Agent 状态、会话活跃度、Provider 健康和系统负载，无需逐个页面查看。

### US-2：开发者快速开始对话

> 作为开发者，我在首页点击"开始对话"按钮即可进入 Chat 页面，无需通过侧边栏导航。

### US-3：管理者查看用量趋势

> 作为管理者，我在首页向下滚动即可查看 Token 趋势、模型分布和 Top Agent 排行，与现有体验一致。
