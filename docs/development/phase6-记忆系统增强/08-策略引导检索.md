> **借鉴来源**：MAGMA（Policy-Guided Graph Traversal）
> **优先级**：中
> **影响层**：L2 情景记忆、L3 语义记忆、L4 知识图谱
> **最后更新**：2026-06-06

## 一、需求文档

### 1.1 背景

当前召回使用统一评分公式：
- L2：`keyword * w + vector * w + importance * decay * w + sessionBoost * w`
- L3：`keyword * w + vector * w + importance * decay * w + recency * w + qualityScore * w`

这种统一公式无法适应不同查询意图：
- "用户现在住哪里？" → 需要实体图遍历 + 时间过滤
- "为什么用户从 A 转向 B？" → 需要因果图遍历
- "用户的技术栈是什么？" → 需要语义搜索

### 1.2 MAGMA 的做法

MAGMA 将检索建模为**策略引导的图遍历**：
1. **查询分类**：LLM 判断查询意图（语义/时序/因果/实体）
2. **路径选择**：根据意图选择遍历哪些子图
3. **自适应截断**：根据证据累积置信度决定何时停止检索

### 1.3 目标

1. 召回前增加查询意图分类
2. 根据意图自适应调整各维度的权重
3. 支持证据累积的早停机制

### 1.4 功能需求

#### P1 — 应该实现

| ID | 需求 | 说明 |
|----|------|------|
| PR-P1-1 | 查询意图分类 | LLM 判断查询属于语义/时序/因果/实体哪类 |
| PR-P1-2 | 权重自适应 | 根据意图调整 keyword/vector/importance 等权重 |
| PR-P1-3 | 早停机制 | 证据累积置信度达阈值时停止检索 |

#### P2 — 可以实现

| ID | 需求 | 说明 |
|----|------|------|
| PR-P2-1 | 检索路径可视化 | 前端展示检索路径和决策过程 |
| PR-P2-2 | A/B 测试框架 | 不同检索策略的对比测试 |

### 1.5 验收标准

1. 不同意图的查询使用不同的权重组合
2. 时序类查询优先使用时间过滤
3. 因果类查询优先遍历因果图
4. 早停机制减少不必要的检索
5. `make wire && make build && make test` 全部通过

## 二、设计文档

### 2.1 查询意图分类

```go
type QueryIntent string

const (
    IntentSemantic  QueryIntent = "semantic"   // 语义搜索
    IntentTemporal  QueryIntent = "temporal"   // 时序查询
    IntentCausal    QueryIntent = "causal"     // 因果推理
    IntentEntity    QueryIntent = "entity"     // 实体属性查询
)

type IntentClassifier interface {
    Classify(ctx context.Context, query string) (QueryIntent, float64, error)
}
```

### 2.2 权重自适应

```go
var intentWeights = map[QueryIntent]RecallWeights{
    IntentSemantic: {Keyword: 0.25, Vector: 0.40, Importance: 0.15, Recency: 0.10, Quality: 0.10},
    IntentTemporal: {Keyword: 0.15, Vector: 0.20, Importance: 0.10, Recency: 0.40, Quality: 0.15},
    IntentCausal:   {Keyword: 0.15, Vector: 0.25, Importance: 0.20, Recency: 0.15, Quality: 0.25},
    IntentEntity:   {Keyword: 0.30, Vector: 0.30, Importance: 0.20, Recency: 0.10, Quality: 0.10},
}
```
