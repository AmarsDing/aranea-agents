## 一、需求文档

### 1.1 背景

当前 L4 图谱存储实体和关系，但缺少高层抽象：
- 大量 Fact 和 Entity 难以形成宏观理解
- 无法回答"这个用户的主要兴趣领域是什么？"
- 召回时只能返回具体事实，无法提供领域级概览

### 1.2 Zep 的做法

Zep 的三层子图架构：
1. **Episode 子图**：原始对话数据
2. **Semantic Entity 子图**：提取的实体和关系
3. **Community 子图**：高层领域摘要，通过社区检测算法自动生成

Community 子图将相关实体聚类为"社区"，每个社区有一个 LLM 生成的摘要。

### 1.3 目标

1. L4 增加社区检测：自动将相关实体聚类为社区
2. 每个社区生成 LLM 摘要
3. 召回时可返回社区级概览
4. 社区随新实体/关系动态更新

## 二、设计文档

### 2.1 数据模型

```sql
CREATE TABLE memory_communities (
    id          TEXT PRIMARY KEY,
    agent_id    TEXT NOT NULL,
    user_id     TEXT NOT NULL,
    name        TEXT NOT NULL,       -- 社区名称
    summary     TEXT NOT NULL,       -- LLM 生成的摘要
    entity_ids  TEXT NOT NULL,       -- JSON 数组，包含的实体 ID
    entity_count INTEGER NOT NULL,  -- 实体数量
    created_at  TIMESTAMP NOT NULL,
    updated_at  TIMESTAMP NOT NULL
);
```

### 2.2 社区检测算法

采用轻量级连通分量检测：
1. 构建 L4 实体-关系图
2. 使用 Louvain/Label-Propagation 算法检测社区
3. 每个社区包含 3-20 个实体
4. 过小（<3 实体）或过大（>20 实体）的社区合并或拆分
