# 04 — 递归摘要与上下文压缩

> **借鉴来源**：Letta（Recursive Summarization）、Claude Code（/compact）
> **优先级**：高
> **影响层**：L0 上下文窗口、L1 工作记忆
> **最后更新**：2026-07-20
>
> **⚠️ 架构变更（2026-07-20，ADR-07 双压缩系统统一）**：系统 A（BeforeModel Hook）已从「LLM 递归摘要」降级为「**确定性紧急截断**」——不再调用 LLM，超过硬阈值（0.90）时机械删除最旧消息并插入 `<context_truncated>` 标记（tool-pair 安全切分）。`ContextCompressor` 接口、`LLMContextCompressor` 实现、`MEMORY_COMPRESSOR_*` 环境变量已全部删除。LLM 压缩路径统一收口到系统 B（`internal/session` 轮间持久化压缩）。详见 [ADR-07](../../reports/2026-07-20-review-adr-dual-compression-unification.md)。下文中被取代的设计以删除线标注。

## 一、需求文档

### 1.1 背景

当前系统在长对话中面临上下文窗口溢出问题：
- L0 Assembly Snapshot 仅记录审计信息，不执行压缩
- 无递归摘要机制：对话历史持续增长直到超出上下文窗口
- 无 /compact 命令：用户无法主动压缩上下文
- L1 工作记忆无自动清理：过期字段持续占用 token 预算

### 1.2 Letta 的做法

Letta 在上下文窗口满时：
1. **Eviction**：淘汰约 70% 的旧消息（保留 30% 确保连续性）
2. **Recursive Summarization**：被淘汰的消息与已有摘要合并，生成新的递归摘要
3. **摘要作为 Memory Block**：摘要存储为 Core Memory Block，始终在上下文中

### 1.3 Claude Code 的做法

Claude Code 的 `/compact` 命令：
1. 将当前会话历史压缩为摘要
2. 压缩后从磁盘重新读取 CLAUDE.md
3. 摘要保留关键决策、代码变更、未完成任务

### 1.4 目标

1. L0 增加递归摘要能力：上下文窗口接近满时自动压缩
2. 新增 `/compact` 命令：用户/Agent 可主动触发压缩
3. L1 工作记忆自动清理：过期字段归档到 L2
4. 压缩质量可观测：记录压缩前后的 token 数和关键信息保留率

### 1.5 功能需求

#### P0 — 必须实现

| ID | 需求 | 说明 |
|----|------|------|
| RC-P0-1 | 自动压缩触发 | 上下文 token 使用率 >= 阈值（默认 80%）时自动触发 |
| RC-P0-2 | 递归摘要 | 被淘汰的消息与已有摘要合并，生成新摘要 |
| RC-P0-3 | 摘要注入 | 压缩后的摘要作为 system message 的一部分注入上下文 |
| RC-P0-4 | L0 Assembly Snapshot 记录压缩事件 | 记录压缩前后的 token 数、保留的关键信息 |

#### P1 — 应该实现

| ID | 需求 | 说明 |
|----|------|------|
| RC-P1-1 | /compact 命令 | Agent 可主动触发上下文压缩 |
| RC-P1-2 | L1 过期字段自动归档 | 超过 TTL 的 L1 字段自动归档到 L2 Episode |
| RC-P1-3 | 压缩策略可配置 | MemoryRuntimePolicy 可配置压缩阈值和保留比例 |
| RC-P1-4 | 关键信息保护 | 压缩时保护 system prompt、工具定义等不可淘汰内容 |

#### P2 — 可以实现

| ID | 需求 | 说明 |
|----|------|------|
| RC-P2-1 | 压缩质量评估 | LLM 评估压缩后关键信息保留率 |
| RC-P2-2 | 分层压缩 | 不同层级的消息使用不同的压缩策略 |

### 1.6 验收标准

1. 上下文 token 使用率 >= 80% 时自动触发压缩
2. 压缩后上下文 token 数减少至 50% 以下
3. 压缩后的摘要保留关键决策、用户偏好、未完成任务
4. L0 Assembly Snapshot 记录完整的压缩事件
5. 连续压缩（递归）后摘要仍保持信息密度
6. `make wire && make build && make test` 全部通过

## 二、设计文档

### 2.1 压缩流程

> ⚠️ 2026-07-20 起：步骤 2 阈值改为 0.90（`HardTriggerRatio`），步骤 4「递归摘要」替换为「确定性截断 + `<context_truncated>` 标记」，步骤 5 不再注入摘要 Memory Block。以下为历史设计。

```
BeforeModel Hook
  │
  ├─ 1. 计算 token 使用率
  │     token_usage = current_tokens / max_tokens
  │
  ├─ 2. 判断是否需要压缩
  │     if token_usage >= threshold (default 0.80):  ← 现 0.90（HardTriggerRatio）
  │       trigger compression
  │
  ├─ 3. 选择淘汰范围
  │     - 保留：system prompt + 工具定义 + 最近 30% 消息
  │     - 淘汰：中间 70% 消息
  │     - 2026-07-20 起增加：tool-call/tool-result 对安全切分
  │
  ├─ 4. 递归摘要  ← 2026-07-20 起改为：确定性截断 + <context_truncated> 标记（无 LLM）
  │     - 读取已有摘要（如果有）
  │     - 将淘汰消息 + 已有摘要 输入 LLM
  │     - 生成新摘要
  │
  ├─ 5. 重构上下文  ← 2026-07-20 起：不再注入摘要块，仅保留截断标记
  │     - system prompt
  │     - [摘要 Memory Block]
  │     - L1 工作记忆
  │     - L2/L3/L4 召回结果
  │     - 最近 30% 消息
  │
  └─ 6. 记录 L0 Assembly Snapshot（TruncateStrategy="emergency_truncation"）
```

**2026-07-20 起 LLM 压缩路径（系统 B，`internal/session/compressor.go`）**：轮间触发，读取历史消息 → L2 MemoryCompact（确定性吸收）→ L3 LLM 滚动摘要（PriorSummary 递归合并、质量门、失败抑制、LRU 缓存）→ 摘要持久化 `session_summaries` 表 → 下次轮次注入。

### 2.2 核心接口

> ⚠️ 2026-07-20 起：`ContextCompressor` 接口与 `ContextCompressionResult` 已删除（ADR-07）。系统 A 为无接口的确定性 hook（`internal/agent/context_compression_inject.go`）；LLM 压缩接口收口在 `internal/compress`（`compress.Compressor`，系统 B 使用）。以下为历史设计。

```go
// ~~ContextCompressor 上下文压缩器~~（2026-07-20 已删除，ADR-07）
type ContextCompressor interface {
    // ShouldCompress 判断是否需要压缩
    ShouldCompress(ctx context.Context, session *Session) (bool, error)
    // Compress 执行压缩，返回摘要
    Compress(ctx context.Context, session *Session, existingSummary string, evictedMessages []Message) (string, error)
}

// CompactResult 压缩结果
type CompactResult struct {
    BeforeTokens int      // 压缩前 token 数
    AfterTokens  int      // 压缩后 token 数
    Summary      string   // 生成的摘要
    EvictedCount int      // 淘汰的消息数
    KeyInfoKept  []string // 保留的关键信息列表
}
```
