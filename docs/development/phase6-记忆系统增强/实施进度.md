## 04 - 递归摘要与上下文压缩

### 整体状态：🟡 P0 已完成，P1 大部分完成（2026-07-11）

> **实现方案**：
> - **自动压缩（T1-T4）**：`ContextCompressor` 接口定义在 `internal/biz/`（纯 Go，不依赖 trpcmodel），`LLMContextCompressor` 实现在 `internal/memory/`（依赖 trpcmodel 调 LLM）。BeforeModel Hook（priority 3）在 token 使用率 >= 阈值时触发，分区消息（保留 system + 最近 keepRatio 比例对话，淘汰其余），调用 LLM 生成递归摘要，存储到 invocation state 供下次合并。压缩元数据通过 `CompressionMeta` 传递给 L0 快照 hook（priority 10）记录到 `l0_assembly_snapshots` 表。
> - **/compact 工具（T5）**：Agent 可主动触发上下文压缩。工具通过 BeforeToolHook 注入 `ManualCompressor` + `sessionID`，调用现有 `session.Compressor.CompactSession` 执行 DB 级压缩（三级级联：MicroCompact → MemoryCompact → LLM）。
> - **Wire DI**：LLM 通过 `MEMORY_COMPRESSOR_PROVIDER`/`MEMORY_COMPRESSOR_MODEL` 环境变量配置，未配置时压缩 hook 为 no-op。`ManualCompressor` 通过 `biz.ManualCompressorFromNative(td.Compress)` 类型断言从 `NativeTurnCompressor` 获取。
> - **RuntimePolicy 配置（T7）**：压缩阈值（`CompressionThreshold`，默认 0.80）和保留比例（`CompressionKeepRatio`，默认 0.30）通过 `MemoryRuntimePolicy` 配置，在 `ResolveMemoryRuntimePolicy` 中设置默认值。Hook 创建时解析 policy，用 `ratio >= threshold` 替代 `ShouldCompress()` 调用，用 `policy.CompressionKeepRatio` 替代硬编码常量。默认值始终填充（即使 memory 未启用），确保平台级 hook 有有效阈值。
