## 03 - 记忆演化机制

### 整体状态：🟡 P0 已完成（2026-07-12）

> **实现方案**：A-MEM 风格记忆演化。基于现有 `LinkEvolutionService`（LLM 驱动关键词提取 + 链接判断 + 异步队列 + 事务支持），扩展链接类型分类（`RELATED_TO`/`EVOLVED_FROM`）和上下文注释（`context_note`）。新 Fact 写入时，LLM 分析语义关联，对 `EVOLVED_FROM` 链接自动失效旧 Fact（设置 `valid_until`）并创建 L4 关系图边 + action_log 审计记录。对 `RELATED_TO` 链接，在旧 Fact 的 `context_note` 字段追加 LLM 生成的演化注释（仅在为空时写入，避免覆盖）。
>
> **关键设计**：
> - **窄接口注入**：新增 `L4RelationWriter`（仅 `UpsertRelation`）和复用 `MemoryActionLogWriter`，通过 setter 方法注入，避免破坏现有 12+ 测试调用
> - **双时序协同**：`EVOLVED_FROM` 链接触发旧 Fact 的 `valid_until` 设置，与新 Fact 的 `valid_from` 形成时间链
> - **context_note 语义**：LLM 生成的上下文注释，解释 Fact 之间的演化关系，空字符串表示无演化上下文

## 06 - Sleep-Time 智能整理

### 整体状态：🟡 P0 已完成（2026-07-12）

> **实现方案**：Letta 风格 Sleep-Time Agent。`SleepTimeService` 已有 trpcmemory 整合（merge/reflect/update_core），新增 `EpisodeConsolidator` 实现 L2 Episode → L3 Fact 提取。`Consolidate` 方法重构为双阶段：(1) trpcmemory 整合（读失败可重试，写失败不可重试）；(2) L2→L3 Fact 提取（best-effort，永不返回 error）。Phase 2 独立于 Phase 1 运行——即使 trpcmemory 为空，Episode 整合仍会执行。读失败时跳过 Phase 2 以防止重试产生重复 facts。
>
> **关键设计**：
> - **双阶段 Consolidate**：Phase 1（trpcmemory）+ Phase 2（Episode→Fact），通过 setter 注入 `EpisodeConsolidator`，向后兼容（未注入时仅运行 Phase 1）
> - **LLM 解析（P1-1，2026-07-31 更新）**：consolidator LLM 改为按 target 从 ModelCatalog 解析（`service.SleepTimeLLMResolver`，优先级与 `MemoryLLMExtractor` 一致：MemoryWorker → L0Compress → agent 默认模型）；`MEMORY_SLEEP_TIME_PROVIDER`/`MEMORY_SLEEP_TIME_MODEL` 环境变量方案已淘汰。`SleepTimeService`/`EpisodeConsolidator` 通过 `SetLLMResolver` 注入，resolver 返回 nil 时回退构造期静态模型
> - **action_log 审计**：每条提取的 Fact 写入 `episode_extract_fact` action_log 记录
> - **重要性过滤**：`importance < 0.3` 的 facts 被跳过，避免低价值提取
> - **L2RecallStore 导出**：新增 `data.NewL2RecallStore` 导出构造函数，返回 `biz.L2RecallStore`（包含 `ListEpisodeRowsForRecall`）
