## 1. 背景与问题

M59 精灵模式 P0/P0.5 已完成核心骨架和三阶段编排，但存在以下可观测性体验问题：

| 问题 | 用户影响 |
|------|----------|
| 工具调用卡片全部展开，长对话时占据大量空间 | 用户需大量滚动才能找到当前活跃内容 |
| 精灵思考/执行时显示通用 spinner | 用户不知道 Agent 在做什么，等待体验差 |
| 团队成员状态仅在展开后才能看到 | 用户无法一眼感知团队执行进度 |
| 已完成步骤与活跃步骤平铺展示 | 视觉焦点分散，无法快速定位当前工作 |
| 团队状态变化无即时视觉反馈 | 用户需主动切换查看，打断阅读流 |
| 中断团队无恢复提示 | 用户不知道可以恢复执行 |

**竞品调研结论**（详见 [调研报告](../reports/2026-06-08-research-chat-observability-ux.md) 第二部分）：

- Claude Code / Cursor / Trae 等竞品已形成"环境可观测性"共识：L1 环境层（零干扰）→ L2 结构层（按需查看）→ L3 证据层（主动展开）
- "折叠"是解决可观测性 vs 可读性矛盾的核心模式
- Trae 的对话流自动折叠和 Claude Code 的可折叠工具输出是最有效的"可观测性强但不影响主要内容"的模式

**核心原则**：可观测性强，但不影响主要内容的显示。

## 2. 用户故事

### OBS-01 对话流自动折叠

**作为** 用户
**我希望** 已完成的步骤/工具调用自动折叠为单行摘要，仅当前活跃步骤展开
**以便** 我能快速定位当前工作，不被历史步骤干扰

**验收**：

- 已完成的工具调用卡片自动折叠为单行摘要（工具名 + 状态图标 + 耗时）
- 已完成的团队组建/完成卡片自动折叠为单行摘要
- 当前活跃步骤始终展开显示
- 精灵直接回复的消息不折叠
- 新消息到达时，前一个活跃步骤自动折叠
- 折叠态点击可展开查看完整内容
- 提供"展开全部"按钮，方便回溯
- interrupted 状态的步骤视为"已完成"并折叠，但显示中断标记（⏸）而非 ✓

### OBS-02 语境加载消息

**作为** 用户
**我希望** 精灵思考/执行时显示与当前动作相关的描述性文案，而非通用 spinner
**以便** 我在等待时就知道 Agent 在做什么

**验收**：

- 三阶段编排过程中，按事件顺序展示语境加载消息：
  - `butler.orchestration.started` → "正在处理任务…"
  - `spirit_plan_created` → "正在分析任务复杂度…"
  - `spirit_allocation_created` → "正在分配 Agent 角色…"
  - `spirit_orchestration_started` → "正在编排执行流程…"
- 团队执行过程中，按 `tool_call`/`tool_result` 事件展示 Agent 级语境消息：
  - `tool_call`（`activity_kind=tool`）→ "{agent_name} 正在{display_label}…"
  - `tool_call`（`activity_kind=skill`）→ "{agent_name} 正在运行 Skill {summary}…"
  - `tool_result` → "{agent_name} 完成，耗时 {duration_ms}"
- 语境加载消息以流式方式替换（非追加），保持 1 行
- 消息样式：浅色背景 + 左侧彩色竖线（颜色按阶段区分）
- WS 重连事件回放期间，语境加载消息静默（避免闪烁）

### OBS-03 Agent 状态标签

**作为** 用户
**我希望** 团队卡片和任务执行面板中每个 Agent 显示状态标签
**以便** 我能一眼感知团队执行进度

**验收**：

- 后端 `AgentNodeStatus` 17 种状态聚合为 7 种展示标签：

| 聚合标签 | 文案 | 颜色 | 图标 | 动画 |
|---------|------|------|------|------|
| Queued | "排队中" | 灰色 | ○ | 无 |
| Active | "执行中" | 蓝色 | ⚡ | 左边框呼吸动画 |
| Suspended | "等待中" | 橙色 | ⏸ | 无 |
| Done | "已完成" | 绿色 | ✓ | 无 |
| Failed | "失败" | 红色 | ✗ | 无 |
| Skipped | "已跳过" | 灰色 | ⊘ | 无 |
| Cancelled | "已取消" | 灰色 | ⊘ | 无 |

- 侧边栏团队卡片使用 `SpiritMember.status`（简单 3 值：idle/running/error）
- 任务执行面板使用 `AgentNodeStatus`（17 值聚合为 7 种标签）
- 标签宽度固定（~80px），避免布局抖动
- 团队卡片折叠态也可见（紧凑模式：头像+状态色点）

### OBS-04 底部状态栏

**作为** 用户
**我希望** 聊天面板底部固定显示全局并行状态
**以便** 我不需要切换到左侧栏就能感知整体进度

**验收**：

- 聊天面板底部固定一行状态栏（24px），包含：
  - 活跃团队数："⚡ N teams running"
  - 中断团队数："⏸ N interrupted"（有中断团队时显示）
  - 并行配额："📊 N/M quota"
  - Token 消耗："🔵 X.Xk tokens"（需后端扩展事件 payload）
  - 最近事件："✅/❌ 最近完成的团队"
- 状态栏不随内容滚动
- 窄屏时自动隐藏低优先级字段
- 仅在精灵模式激活时显示
- 点击字段可跳转到对应内容

### OBS-05 侧边栏状态脉冲

**作为** 用户
**我希望** 左侧团队卡片在状态变化时短暂高亮
**以便** 我在阅读精灵对话时也能感知到团队状态变化

**验收**：

- 团队状态变化时卡片短暂脉冲高亮：

| 状态变化 | 脉冲颜色 | 持续时间 |
|---------|---------|---------|
| → running | 蓝色 | 1.0s |
| → completed | 绿色 | 1.5s |
| → failed | 红色 | 2.0s |
| → interrupted | 橙色 | 1.5s |

- 脉冲结束后自动恢复正常
- 多个团队同时变化时，脉冲独立触发
- 脉冲期间卡片左侧边框加粗 2px（颜色同脉冲色）
- WS 回放期间禁用脉冲动画

### OBS-06 可折叠工具输出

**作为** 用户
**我希望** 已完成的工具调用自动折叠，只显示工具名和耗时
**以便** 多个工具调用连续展示时不影响对话可读性

**验收**：

- 工具调用卡片（`ChatExecutionCard`）完成后自动折叠
- 折叠态显示：工具名 + 状态图标 + 耗时（1 行，~32px）
- running 状态的工具调用始终展开
- failed 状态的工具调用折叠但红色高亮
- 点击折叠态可展开查看完整输入/输出
- 提供"展开全部工具调用"按钮
- 加载历史消息时，已完成的工具卡片默认折叠（从 `OptionsJSON.tool_event` 恢复状态）

### OBS-07 中断恢复提示

**作为** 用户
**我希望** 中断的团队显示恢复提示卡片
**以便** 我知道可以恢复执行，而不是以为任务丢失了

**验收**：

- interrupted 状态的团队在任务执行面板中显示恢复提示卡片：
  - 团队名称 + 中断原因（"因服务器重启而中断"）
  - 已完成步骤 / 总步骤
  - "恢复执行"按钮（调用 `ResumeTeamRunExecution` API）
  - "取消团队"按钮
- 如果团队无 `graph_execution_id`，显示"此团队不支持断点恢复"
- 恢复成功后团队状态更新为 running
- 仅 interrupted 状态时显示，正常执行时不可见

## 3. 功能规格

### 3.1 三层可观测性架构

```
┌─────────────────────────────────────────────────────┐
│ L1 环境层 (Ambient) — 始终可见，零干扰              │
│ OBS-02 语境加载消息  OBS-03 Agent 状态标签           │
│ OBS-05 侧边栏脉冲    OBS-04 底部状态栏              │
├─────────────────────────────────────────────────────┤
│ L2 结构层 (Structural) — 按需查看，不遮挡            │
│ OBS-01 对话流自动折叠  OBS-06 可折叠工具输出         │
│ OBS-07 中断恢复提示                                   │
├─────────────────────────────────────────────────────┤
│ L3 证据层 (Evidential) — 主动展开才可见              │
│ ChatExecutionCard 展开态  ChatDiffViewer             │
│ TeamRunObservatory Timeline                          │
└─────────────────────────────────────────────────────┘
```

### 3.2 设计原则

| # | 原则 | 说明 |
|---|------|------|
| DP-1 | 环境可观测性优先 | 状态信息以颜色、图标、微动画呈现，不占用主内容区空间 |
| DP-2 | 渐进式信息披露 | 默认只展示 L1，用户主动交互才展开 L2/L3 |
| DP-3 | 完成即折叠 | 已完成的步骤/团队/工具调用自动收起，保持视觉焦点在活跃内容 |
| DP-4 | 状态即视觉 | 颜色、图标、动画三位一体传达状态 |
| DP-5 | 证据后置 | 过程信息轻量展示，详细证据仅在用户主动查看时展开 |

### 3.3 中间面板状态机（扩展）

在 M59 原有三种面板状态基础上，增加折叠/展开维度：

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  精灵对话面板  │     │  任务执行面板  │     │ 成员只读面板   │
│              │     │              │     │              │
│ L1: 语境消息  │     │ L1: Agent标签 │     │ L1: 状态标签  │
│ L2: 自动折叠  │     │ L2: 进度卡片  │     │ L2: 工具折叠  │
│ L2: 工具折叠  │     │ L2: 恢复提示  │     │              │
│ L1: 底部状态栏│     │ L1: 底部状态栏│     │ L1: 底部状态栏│
└──────────────┘     └──────────────┘     └──────────────┘
```

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 性能 | 折叠/展开操作 < 16ms（单帧）；语境加载消息替换 < 100ms |
| 兼容 | 不破坏现有 `ChatExecutionCard` / `SessionStatusBadge` 组件 API |
| 前端 | 遵循 UX 规范 token；复用现有组件的样式体系 |
| WS 回放 | 语境消息和脉冲动画在回放期间静默 |
| 历史恢复 | 加载历史消息时正确恢复折叠态 |

## 5. 模块边界

| 模块 | 本需求中的职责 |
|------|----------------|
| Chat (1) | 对话流自动折叠、语境加载消息、底部状态栏 |
| Spirit (59) | Agent 状态标签、侧边栏脉冲、中断恢复提示 |
| Team (11) | 中断团队恢复 API（`ResumeTeamRunExecution`） |
| Event (34) | Token 统计事件扩展（`spirit_team_completed` 增加 token 字段） |

**不在范围**：Observatory 页面重构、成员只读面板（SP-06）、面包屑导航（SP-09）。
