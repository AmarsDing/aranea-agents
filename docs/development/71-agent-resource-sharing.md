# M71: Agent 资源共享 — 产品需求

> 关联模块：M67（公司架构重塑）、M23（工具系统）、M10（会话）、M53（Team Graph 编排）

## 1. 背景与问题

当前系统中每个 Agent 拥有独立工作目录（`{base}/workspace/{workspaceID}/{agentKey}`），文件/Shell 工具严格沙箱隔离，**不存在任何跨 Agent 文件访问机制**。跨实体共享仅有一条通道：DAG 编排中的交付物引用（DeliverableRef + `read_upstream_deliverable`）。

| # | 问题 | 影响 |
|---|------|------|
| 1 | 部门主管无法查看本部门员工的工作目录 | 主管审批只能看最终交付物，无法抽查过程文件，质量把关流于形式 |
| 2 | 借调成员的工作状态对主管不透明 | M67 US-03b 要求"来源部门主管可查看被借调成员工作状态"，无落地机制 |
| 3 | 部门主管之间没有信息交互通道 | 跨部门协作中主管无法作为"纽带"直接协商（澄清需求、协调变更、同步进度），只能走审批单 |
| 4 | 精灵无法访问 session 会话内容 | 用户问精灵"上周量化部分析了什么"时无法回答；精灵编排时无法参考各部门历史工作 |

**目标**：建立统一的**受控资源访问层**，以工具化方式为部门主管和精灵提供跨 Agent 只读访问与主管间消息通道，全程权限校验 + 审计，不破坏现有 per-agent 沙箱模型。

**核心原则——传递与监管分离**：跨部门**信息传递**只走显式通道（交付物契约 + 主管信箱），目录/会话访问仅为**监管手段**（只读、审计），保证"谈论的东西"与"实际交付的东西"永远一致。

## 2. 用户故事

### US-01 部门主管查阅员工工作文件

**作为** 部门主管
**我希望** 列出并阅读本部门员工工作目录下的文件
**以便** 抽查工作过程、审批前核对产物依据

**验收标准**：
- 主管可列出本部门任一员工工作目录的目录树（可指定子路径与深度）
- 主管可读取指定文件内容（文本文件；超限截断；二进制文件拒绝并提示）
- 主管**不能**访问非本部门员工（且非借入本部门 Team 成员）的目录，访问被拒时有明确提示
- 主管**不能**修改/删除/写入员工目录中的任何文件
- 每次访问（含被拒）均记录审计日志

### US-02 部门主管搜索员工文件

**作为** 部门主管
**我希望** 按文件名模式在本部门员工工作目录中搜索
**以便** 快速定位产物文件（如"找到所有 .md 报告"）

**验收标准**：
- 支持 glob 模式搜索文件名，返回匹配文件的相对路径清单
- 搜索范围同样受部门权限约束
- 搜索行为记录审计日志

### US-03 借调成员的双主管可见

**作为** 借调成员的来源部门主管 / 所在 Team 主归属部门主管
**我希望** 双方都能只读查看借调成员的工作目录
**以便** 来源主管掌握成员外派状态，主归属主管审批其 Team 内产出时不盲审

**验收标准**：
- 借调成员目录对"组织归属主管"与"所在 Team 主归属主管"同时开放只读
- 审计日志区分访问关系类型（`org_home` / `team_owner`）
- 其余任何部门主管对该成员目录无访问权
- 借调关系结束后，主归属主管的访问权自动失效

### US-04 主管向其他部门主管发送消息

**作为** 部门主管
**我希望** 给另一个部门的主管发送结构化消息（主题、正文、可引用交付物）
**以便** 跨部门协作中直接协商需求、澄清疑问、同步进度

**验收标准**：
- 可指定目标部门发送消息，消息持久化到对方收件箱
- 消息可附带交付物引用（DeliverableRef），保证讨论对象与正式交付物一致
- 消息状态可追踪（未读/已读/已回复），发送方可看到对方是否已读
- 支持对消息进行回复，形成线程
- 不能发送给不存在的部门或本部门自己（提示改用内部沟通）

### US-05 接收方主管及时获知新消息

**作为** 接收消息的部门主管
**我希望** 消息到达时被及时唤醒处理
**以便** 跨部门协商不被长时间搁置

**验收标准**：
- 消息到达后触发接收方主管的一次轻量处理（系统提示其查收收件箱）
- 同一发送方短时间内的多条消息合并为一次唤醒（防抖，默认 5 分钟窗口）
- 主管可自主选择立即处理或稍后处理，未读消息在下次激活时仍可见
- 唤醒行为不干扰主管正在执行的任务（作为新 Turn 排队，不打断当前 Turn）

### US-06 精灵检索全工作区会话内容

**作为** 使用精灵助手的用户
**我希望** 精灵能检索工作区内任意 Agent 的历史会话内容
**以便** 回答"上周量化部分析了什么""设计部和研发部之前讨论过什么方案"类问题

**验收标准**：
- 精灵可按关键词全文检索消息内容，返回命中片段及所属会话指针
- 精灵可按 Agent/时间范围列出会话清单（标题、消息数、更新时间）
- 精灵可阅读指定会话的消息历史（分页 + 字符上限截断）
- 检索/阅读有频率限制，防止循环刷库
- 每次检索/阅读记录审计日志
- 精灵只能读取，不能修改/删除任何会话内容

### US-07 管理员审计跨 Agent 资源访问

**作为** 系统管理员
**我希望** 查询所有跨 Agent 资源访问的审计记录
**以便** 追溯"谁在什么时候访问了谁的什么资源"，支撑安全合规

**验收标准**：
- 文件访问、会话检索、信箱收发全部记录统一审计表
- 审计记录包含：访问者、角色、动作、目标 Agent/部门、资源标识、结果（允许/拒绝）、拒绝原因、时间
- 被拒绝的访问同样记录
- 审计记录只增不改

## 3. 功能需求清单

| # | 需求 | 说明 |
|---|------|------|
| FR-01 | 员工目录列举 | 部门主管列本部门员工（含借入成员）工作目录树 |
| FR-02 | 员工文件读取 | 只读，文本文件，默认上限 200KB，超限截断提示，二进制拒绝 |
| FR-03 | 员工文件搜索 | glob 文件名模式搜索 |
| FR-04 | 部门权限校验 | 组织归属（org_home）与 Team 主归属（team_owner）双关系判定，其余拒绝 |
| FR-05 | 主管信箱发送 | 主题 + 正文 + 可选 DeliverableRef 引用列表，持久化 |
| FR-06 | 主管信箱收件箱 | 列表（按状态过滤）、读取（自动标已读）、回复（线程化） |
| FR-07 | 信箱唤醒 | 消息到达触发接收方主管轻量 Turn，同发送方 5 分钟防抖合并 |
| FR-08 | 消息全文检索 | 精灵按关键词检索消息（复用 messages_fts FTS5），返回片段 + 会话指针 |
| FR-09 | 会话清单列举 | 精灵按 Agent/时间范围列会话元数据 |
| FR-10 | 会话历史阅读 | 精灵读指定会话消息历史，分页 + 单次 200K 字符上限 |
| FR-11 | 精灵访问限流 | 按 Agent 令牌桶限流（默认 20 次/分钟） |
| FR-12 | 统一审计 | 三个通道的所有访问（含拒绝）落统一审计表，只增不改 |

## 4. 权限矩阵（产品视角）

| 角色 | 员工工作目录 | session 会话内容 | 主管信箱 |
|------|------------|-----------------|---------|
| 普通员工 Agent | 仅自己（现有沙箱，不变） | ❌ | ❌ |
| 部门主管 | 本部门员工 + 借入本部门 Team 成员，**只读** | ❌ | 收发 |
| 精灵 | ❌ | 全工作区，**只读检索** | ❌ |

## 5. 非功能需求

| # | 类别 | 需求 | 验收标准 |
|---|------|------|---------|
| NFR-01 | 安全 | 路径穿越防护 | 所有文件访问强制约束在目标 Agent 工作目录内，`..`/绝对路径/符号链接逃逸被拒绝 |
| NFR-02 | 安全 | 权限不可伪造 | 调用者身份从运行时上下文取（Agent 标识），不接受工具入参声明身份 |
| NFR-03 | 性能 | 文件读取延迟 | 200KB 内文件读取 < 500ms |
| NFR-04 | 性能 | 会话检索延迟 | FTS 检索 < 2s（10 万级消息量） |
| NFR-05 | 可靠性 | 信箱消息不丢 | 消息先落库再触发唤醒；唤醒失败不影响消息本体，未读消息下次激活可见 |
| NFR-06 | 可审计 | 审计完整性 | 三个通道 100% 覆盖（含拒绝），审计写入失败时拒绝本次访问（fail-closed） |
| NFR-07 | 隔离性 | 沙箱不破坏 | 员工 Agent 的 file/shell 工具沙箱行为与现状完全一致，零改动 |
| NFR-08 | 容量 | 信箱规模 | 单部门收件箱 ≤ 10000 条，超出归档 |

## 6. 约束与边界（首版不做）

| 边界 | 说明 |
|------|------|
| ❌ 主管读员工 session | 工作过程透明度由"目录产物 + 审批流"覆盖，对话内容留待后续按需开放 |
| ❌ 主管写员工目录 | 只读，防误改破坏任务 |
| ❌ 员工之间互读目录 | 沙箱保持，无此诉求 |
| ❌ 精灵写会话 / 精灵收发信箱 | 首版精灵仅只读检索 |
| ❌ 主管↔主管 A2A 实时对话 | 已决策走异步信箱 |
| ❌ 跨部门直接读目录 | 跨部门信息流只走交付物 + 信箱（传递与监管分离） |
| ❌ 按 Team/任务级目录粒度授权 | 借调成员目录整体对双主管开放，细粒度路径授权留待后续迭代 |
