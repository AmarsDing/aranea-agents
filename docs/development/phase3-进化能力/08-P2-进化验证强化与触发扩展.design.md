# 08 - P2 进化验证强化与触发扩展 — 设计文档

> **依据**：2026-08-09 skill 进化调研（Voyager / ACE / ReasoningBank / Trace2Skill / SKILL-KD / Anthropic skill-creator 等 20+ 来源）与差距分析方案，用户批准范围 P0+P1 共 4 项。
> **前置**：[06-P0-LLM-Curator与Reload接线.design.md](./06-P0-LLM-Curator与Reload接线.design.md)、[07-P1-delta协议与归因观测.design.md](./07-P1-delta协议与归因观测.design.md)
> **状态**：已实施（2026-08-09，设计已评审，评审修正 3 处：ReplayAB 基线不可得契约、GoldenResult 双端对照、SuccessTrigger 门控位置）

---

## 1. 背景与目标

现有进化闭环（观测 → Curator → 五维 Gate → 审批 → Reload → 归因）与学界 2026 主流结构同构，但对照外部实践存在 4 个缺口：

| # | 缺口 | 外部依据 | 本设计对应 |
|---|------|---------|-----------|
| F1 | 回放只测绝对通过率，无 with-skill vs baseline 对照，无法发现「skill 本身有害」 | skill-creator A/B eval；Trace2Skill 实证官方 xlsx skill 把 35B agent 从 19.00 拖到 9.67；EvoSkill 棘轮机制 | A/B 对照回放 + 棘轮门控 |
| F2 | 无 skill 漂移检测（单例过拟合/臃肿/破坏性更新） | SKILL-KD 三类漂移；ACE grow-and-refine | Gate 第六维 drift |
| F3 | 触发全是失败/指标驱动，无成功沉淀通道 | Voyager 技能入库、ReasoningBank 双侧经验蒸馏 | SuccessTrigger |
| F4 | 无触发准确率评测（description/triggers 质量是 skill 召回的第一决定因素） | skill-creator should-trigger/should-not-trigger 黄金集 | 触发率黄金集回归进 Gate |

**非目标**（明确排除）：
- `evo_auto_apply` 全自动应用（2026 工程共识：无 eval 门控的自动应用空转或危险，保持 HITL）
- 分模型档位回归（需要多模型配置，后续独立任务）
- 黄金集 LLM 自动生成（本期黄金集经既有 evaluation UI/API 手工维护，自动生成列为后续项）
- Skill 市场生态（独立立项）

## 2. 总体设计

四项全部挂在既有进化管线上，不引入新流水线：

```
Trigger 层          Draft 层              Gate 层（本设计主战场）
────────────        ─────────────         ─────────────────────────────
PatternTrigger                          ① functional: sandbox + 回放(绝对阈值)
HealthTrigger       Curator             ② security
AgentConfigTrigger  (delta/full)   →    ③ performance
SuccessTrigger(F3)                      ④ style
                                        ⑤ effectiveness(harmful≥3)
                                        ⑥ drift (F2 新增)
                                        ⑦ ratchet: AB回放棘轮 (F1 增强①)
                                        ⑧ trigger_accuracy: 黄金集 (F4 新增)
```

**统一降级语义**（沿用项目 best-effort 风格）：所有新维度的依赖未配置/数据缺失时**跳过不阻断**，只有确定完成且不达标才拒绝。

> **P3 M1 增补（2026-08）**：Gate 后续新增第 8/9 维 paired_regression / no_op_change（逐 case 配对判定与等价改动检测），AB 回放改为一次 Verify 单次执行、三维共用。最新维度清单以 [20-skill.design.md §6.8](../../20-skill.design.md) 为准。

## 3. F1 — A/B 对照回放 + 棘轮门控

### 3.1 现状

- 端口 `biz.SkillReplayRunner.Replay(ctx, skillID, draftBody, maxCases)`（[skill_evolution_loop.go](../../../internal/biz/skill_evolution_loop.go)）只跑 draft。
- 实现 `service.SkillReplayRunner`（[skill_replay_runner.go](../../../internal/service/skill_replay_runner.go)）已持有 `skills biz.SkillLookupReader`，可直接取当前正文做基线。
- Gate `verifyReplay`：通过率 < `ReplayPassThreshold`(0.6) 拒绝。

### 3.2 设计

**biz 层新增**（`skill_evolution_loop.go`，Stability:evolving）：

```go
// SkillReplayABResult 是一次 A/B 对照回放结果。
type SkillReplayABResult struct {
    Baseline *SkillReplayResult // 当前线上正文
    Draft    *SkillReplayResult // 进化草稿
}

// SkillReplayABRunner 用同一评测集对当前正文与草稿做对照回放。
type SkillReplayABRunner interface {
    ReplayAB(ctx context.Context, skillID string, draftBody string, maxCases int) (*SkillReplayABResult, error)
}
```

**service 层**：`SkillReplayRunner` 增加 `ReplayAB` 方法——同一批 cases（寻址约定与截断逻辑完全复用 `Replay` 现有路径），先跑当前正文（`GetLatestSkillMarkdown`）再跑 draft，顺序执行。成本：2× LLM 调用（≤5 cases × 2 = 10 次/Gate），在评审中确认可接受。

**ReplayAB 契约（评审修正）**：当前正文获取失败（`GetLatestSkillMarkdown` error）时**不报错**，返回 `Baseline=nil` + 正常 Draft 结果——基线不可得只丧失棘轮能力，不应拉垮整个回放；Gate 见 `Baseline==nil` 仅执行绝对阈值判定。

**Gate 层**：新增 option `WithABReplayRunner(SkillReplayABRunner)`。`verifyReplay` 逻辑扩展：

1. AB runner 已接线且对照完成（无数据集/LLM 未配置 → 维持现有跳过语义）：
   - 绝对阈值：draft 通过率 < 0.6 → 拒绝（现有行为保留）
   - **棘轮**：`draft.PassRate < baseline.PassRate` → 拒绝，reason 展示两侧通过率（"draft 40% < baseline 60%，进化不得劣于基线"）
2. AB runner 未接线 → 回退现有单跑逻辑（nil-safe）。

**同例对比的公平性**：两跑使用同一 cases、同一 LLM、同一 contains-match 评分，无随机变量，棘轮判定为确定性。

## 4. F2 — 漂移检测（Gate 第六维）

### 4.1 依据

SKILL-KD 识别三类 skill 漂移：case-specific drift（过拟合单例）、skill-bloat drift（臃肿）、destructive-update drift（破坏性更新）。本期实现后两类（可程序化判定），第一类依赖 trace 链接（规则↔来源轨迹），当前数据模型不支持，列为后续项。

### 4.2 设计

`GateVerifier` 新增 `verifyDrift(ctx, skillID, draftBody)`，check 名 `"drift"`，插入 Verify 链第六位。输入经既有 `skillLookup`（`WithSkillLookup` 已接线）取当前正文，双端 `ParseRuleBlocks` 解析。

**判定规则**（常量集中在 `skill_evolution_loop.go` 常量区）：

| 漂移 | 规则 | 阈值常量 |
|------|------|---------|
| 破坏性更新 | draft 删除了当前正文中 `helpful >= GateHarmfulRuleRejectThreshold`(3) 的规则 → 拒绝 | 复用现有 |
| 破坏性更新 | 当前规则数 ≥ 4 且 draft 删除比例 > 50% → 拒绝 | `GateMaxRemoveRatio = 0.5` / `GateRemoveRatioMinRules = 4` |
| 臃肿 | 当前有规则块，且 draft 规则数 > 当前 × 1.5 **且** > 当前 + 5 → 拒绝（双条件防小基数误杀） | `GateMaxRuleGrowthRatio = 1.5` / `GateMaxRuleGrowthAbs = 5` |

**跳过语义**：`skillLookup` 未接线、取正文失败、当前正文无规则块（全量重写阶段无法归因删除）→ 通过。

**判定实现**：删除集 = 当前规则 id 集合 − draft 规则 id 集合（modify/merge 不算删除）。

## 5. F3 — 成功沉淀触发器（SuccessTrigger）

### 5.1 依据

Voyager/ReasoningBank：成功案例单次调用即可提取模式，成本低、防「重复发明」。与失败驱动**不对称并行**——失败触发修问题，成功触发固化正向模式（强化有效规则、补充成功示例），防止好模式在后续全量重写中丢失。

### 5.2 设计

**新触发器**（`skill_evolution_triggers.go`）：

```go
// SuccessTrigger 从高成功率 skill 中检测成功模式沉淀需求。
type SuccessTrigger struct {
    aggregator SkillHealthAggregator
    skills     SkillLookupReader   // 检查规则块（delta 能力门控）
    lg         loggateway.Logger
}
```

- `TargetType()=skill`、`ActionType()=improve_skill`、`TriggerSource()="success"`。

**触发条件**（全部满足才发建议，`skill_evolution_triggers.go` 常量区新增）：

| 条件 | 阈值 |
|------|------|
| 30d 调用量 ≥ `EvoTriggerMinInvocations` | 复用现有常量 |
| 30d 成功率 ≥ `SuccessTriggerSuccessRate` | 0.85 |
| 当前正文含规则块 | 无规则块则跳过——对健康 skill 做全量重写风险大于收益 |
| 冷却 | 复用 orchestrator 既有 per-(target,action) 冷却 + D8 自适应降频 |

**注意（评审确认项）**：success 与 health 共用 `(skill, improve_skill)` 冷却槽——一次 health 改进后一周内不会再发 success 建议。这是有意的保守（同一 skill 一周最多一次改进类建议），如需独立槽位须扩 action 枚举，本期不做。

**门控（评审确认项）**：trigger 层不做 settings 检查——平台 opt-in 门控统一在 `self_improvement` observe worker 层（与 HealthTrigger/AgentConfigTrigger 一致），SuccessTrigger 不引入新的门控分歧。

**建议内容**：`TriggerReason` 携带成功统计（"30d 成功率 96.2%（N 次调用），沉淀正向模式"）；metadata 落 `success_rate`/`invocation_count`/`trigger_source=success`。

**Curator prompt 适配**（`llm_skill_evolver.go`）：
- `SkillDraftInput.SuggestType` 已有类型枚举，新增取值 `EvolutionSuggestSuccessPattern = "success_pattern"`，由 `SkillIntelligenceUsecase.generateDraft` 从 suggestion metadata 的 `trigger_source=="success"` 映射。
- `buildEvolverUserPrompt` 增加成功分支：指令为「固化与强化」而非「修复」——保留现有规则结构、可为高 helpful 规则补充成功示例、禁止删除 `helpful>0` 规则。
- delta system prompt 增加一行约束：success 来源时 `remove` 操作仅允许针对 `harmful>0` 规则。

**接线**：`provideSkillEvolutionOrchestrator`（cmd/admin/wire.go）追加 `orch.RegisterTrigger(biz.NewSuccessTrigger(aggregator, skills, lg))`。

## 6. F4 — 触发率黄金集回归

### 6.1 依据

skill-creator：description/triggers 决定 skill 是否被调用，是独立于功能正确性的第二评测轴；用 20 条 should-trigger/should-not-trigger 黄金查询迭代。本项目运行时触发为确定性机制：`skillruntime.matchTrigger`（CJK 子串 / ASCII 词边界，trigger 命中置顶 preload），triggers 声明在 SKILL.md frontmatter（`internal/skill/importer/manifest.Parse` 解析）——因此黄金集评测**无需 LLM，完全确定性**。

### 6.2 设计

**黄金集承载**：复用 evaluation 数据集，寻址约定 = 回放约定 + 后缀：数据集名 = `{skill.Name|Slug}__trigger`。Case 约定：`Input` = 用户查询，`ExpectedOutput` ∈ `{"trigger","no_trigger"}`（大小写不敏感，其它值视为非法用例跳过并计 Warn）。

**biz 层新增端口**（`skill_evolution_loop.go`，Stability:evolving）：

```go
type SkillTriggerGoldenResult struct {
    DatasetName      string
    Total            int     // 合法用例数
    Accuracy         float64 // draft 判定正确率
    BaselineAccuracy float64 // 当前线上正文判定正确率（棘轮对照端）
    HasBaseline      bool    // 当前正文可解析时 true；false 时 Gate 跳过棘轮仅查绝对下限
    FalseNeg         int     // should-trigger 未命中（draft 端）
    FalsePos         int     // should-not-trigger 误中（draft 端）
}
```

（评审修正：单端 result 无法支撑棘轮，runner 内部同时评测当前正文并随结果返回双端准确率。）

```go
type SkillTriggerGoldenRunner interface {
    RunTriggerGolden(ctx context.Context, skillID string, draftBody string, maxCases int) (*SkillTriggerGoldenResult, error)
}
```

**service 层实现**（新文件 `internal/service/skill_trigger_golden_runner.go`）：
1. 按寻址约定找数据集（复用 `evalDatasetReader`，无数据集 → `ErrNoReplayDataset` 语义跳过）
2. 从 `draftBody` 解析 frontmatter triggers（`internal/skill/importer` 的 `manifest.Parse`；service 层 import 无环）
3. 每条用例：`skillruntime.MatchTrigger`（需将 `matchTrigger` 导出为 `MatchTrigger`，包装一行）命中与否 vs 期望
4. draft 无可解析 triggers 且存在 should-trigger 用例 → 全部 FalseNeg（如实反映）

**Gate 层**：option `WithTriggerGoldenRunner(...)`，check 名 `"trigger_accuracy"`，第七维。判定（runner 完成时）：
- **棘轮**：draft 准确率 < 当前正文准确率 → 拒绝（双端判定确定性、无 LLM 成本，始终对照）
- **绝对下限**：draft 准确率 < `TriggerGoldenMinAccuracy`(0.8) → 拒绝
- 跳过语义：runner 未接线 / 无数据集 / 数据集为空 / 全部用例非法 → 通过

**黄金集维护**：本期经既有 evaluation UI/API 手工创建；LLM 自动生成（skill-creator 式 20 查询迭代）列为后续项。

## 8. 测试计划（TDD）

| 功能 | 关键用例 |
|------|---------|
| F1 | 棘轮拒绝（draft<baseline）；棘轮通过（draft≥baseline）；绝对阈值仍生效；无数据集跳过；LLM 未配置跳过；baseline 取正文失败→跳过棘轮保留绝对阈值 |
| F2 | 删 helpful≥3 规则→拒绝；删除比例>50%(≥4 规则)→拒绝；臃肿双条件边界（1.5×且+5）；无规则块跳过；lookup 失败跳过；modify/merge 不计删除 |
| F3 | 高成功率+有规则块→发建议；成功率不足/调用量不足/无规则块→不发；trigger 层无 settings 门控（worker 层统一 opt-in）；orchestrator 冷却集成 |
| F4 | trigger/no_trigger 判定正确性；棘轮拒绝（draft 准确率低于当前）；绝对下限拒绝；无数据集跳过；非法 ExpectedOutput 跳过计 Warn；draft 无 triggers 全 FalseNeg；CJK/ASCII 匹配语义与 matchTrigger 一致 |

验证命令：`go test ./internal/biz/... ./internal/service/... -run 'Gate|Replay|Trigger|Success' -count=1`，提交前全量 `make build && make test`。
