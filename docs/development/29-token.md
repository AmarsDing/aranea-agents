# 模型 Token 消耗统计

> **编号**：29 | **模块**：Token 用量 | **优先级**：P2

---

## 1. 模块定位

记录和统计 Agent / Team 运行中模型调用的 Token 消耗与费用，支持按时间、Agent、Provider / Model 维度查询和聚合，帮助运营和开发精准把控模型使用情况。

---

## 2. 用户故事

### US-1：查看用量概览

> 作为运营人员，我想在概览页看到今日/本月的 Token 用量、调用次数、费用和成功率，以便快速了解系统运行状况。

### US-2：查看用量趋势

> 作为运营人员，我想按天查看 Token 消耗和费用的趋势图，以便发现异常峰值或使用变化。

### US-3：按模型分析占比

> 作为运营人员，我想看到不同 Provider / Model 的调用量、Token 占比和费用占比，以便识别高成本模型。

### US-4：按 Agent 分析成本

> 作为开发人员，我想看到各 Agent 的消耗排行，以便了解哪些 Agent 消耗最多资源。

### US-5：查看异常请求

> 作为开发人员，我想快速筛选出失败、超时、高成本的异常请求，以便排查问题。

### US-6：查看用量明细

> 作为运营人员，我想查看每条模型调用的详细消耗记录（Token 数、费用、延迟、状态），以便做精细分析。

### US-7：记录用量事件

> 作为系统，每次模型调用结束后应自动记录一条不可变的消耗流水，包含 Token 数、价格快照、费用和状态。

### US-8：用量限额管控（P2）

> 作为管理员，我想为 Agent / 用户 / 全局设置月度 Token 或费用预算，超限时拦截后续调用，以避免意外高额费用。

### US-9：用量告警通知（P3）

> 作为管理员，我想在用量达到预算阈值时收到通知，以便及时关注和处理。

### US-10：Team 与 Agent 用量不重复计费（P2）

> 作为运营人员，我想在概览、排行和配额统计中看到「可计费」用量，且 Team 并行运行时成员消耗计入对应 Agent，而整轮 `team_turn` 仅用于对账、不重复叠加到平台总额。

## 3. 功能规格

### 3.1 用量记录

| 规格项 | 说明 |
|--------|------|
| 记录时机 | 每次模型调用结束后写入一条明细记录 |
| 流式回复 | 流式结束后写入完整记录 |
| 用户中断 | 写入 `cancelled` 状态，记录已产生的 Token |
| 请求失败 | 写入 `failed` 状态，记录错误码与错误信息 |
| 请求超时 | 写入 `timeout` 状态 |
| 重试 | `retry_count` 记录重试次数 |
| 价格快照 | 每条记录保存当时的模型单价，历史费用不受后续价格变化影响 |
| 费用单位 | 所有费用以 micro USD 存储（1 USD = 1,000,000 micro USD），前端展示时转换 |

### 3.2 用量查询

| 查询维度 | 说明 |
|----------|------|
| 概览 | 今日/昨日/本月/自定义范围的汇总（调用次数、Token、费用、成功率、平均延迟、平均 TPS） |
| 趋势 | 按天分组的 Token、费用、调用次数、成功率趋势 |
| Top 模型 | 按费用/调用量排序的模型排行 |
| Top Agent | 按费用/调用量排序的 Agent 排行 |
| 异常请求 | 非 success 状态的请求列表 |
| 明细列表 | 全量消耗记录，支持按 Provider/Model/Agent/状态/时间范围筛选 |

### 3.3 筛选条件

| 筛选项 | 可选值 |
|--------|--------|
| 时间范围 | today / 7d / 30d / month / 自定义 start_date + end_date |
| Provider | 按 provider_code 筛选 |
| 模型 | 按 model_api_id 筛选 |
| Agent | 按 agent_id 筛选 |
| Team | 按 team_id 筛选（明细页；Team 整体费用见 §3.6） |
| 来源 | 按 usage_kind 筛选（明细页；`chat_turn` / `team_member` / `team_turn` 等） |
| 状态 | success / failed / cancelled / timeout / abnormal（非 success） |

### 3.6 统计口径（可计费 vs 对账）

| 场景 | 计入规则 | 用户可见含义 |
|------|----------|--------------|
| 平台概览、趋势、Top 模型/Agent | **可计费**：单 Agent 对话 `chat_turn` + Team 成员 step `team_member`；**不含**整轮 `team_turn` | 避免 Team 一轮运行被「成员 + 整轮」重复统计 |
| Agent 排行 / 单 Agent 配额已用额 | 同上（按 `agent_id` 汇总可计费行） | 与 Chat 拦截一致 |
| Team 整体消耗 | `team_member` 且 `team_id` 一致之和（无成员明细时由 anchor 成员承载整轮 tokens） | Team 页/报表按 Team 维度展示时使用 |
| 用量明细 `/usage/events` | **全部** `usage_kind`（含 `team_turn`） | 排障与对账可看整轮聚合行 |
| `team_turn` | 仅对账、审计；**默认不进**概览/排行/配额 SUM | 与 `team_member` 成员明细互补 |

技术实现与 SQL 常量见 [29 token.design.md](./29%20token.design.md) §4.5；迭代任务见 [29-token-development.md](./29-token-development.md) §9。

### 3.4 用量限额（P2）

| 规格项 | 说明 |
|--------|------|
| 限额范围 | Agent 级 / 用户级 / 全局 |
| 限额周期 | 月度 |
| 限额维度 | 费用（micro USD） |
| 超限行为 | 拦截后续模型调用，返回明确错误提示 |
| 重置 | 每月自动重置 |

### 3.5 用量告警（P3）

| 规格项 | 说明 |
|--------|------|
| 告警范围 | Agent 级 / 用户级 / 全局 |
| 告警阈值 | 占预算比例（如 50%、80%、100%） |
| 通知方式 | 系统通知（后续可扩展邮件/ webhook） |

## 4. 前端看板规格

### 4.1 概览页入口

在现有 Overview 页面增加「模型消耗」模块，点击「查看明细」进入完整用量页。

### 4.2 核心卡片

| 卡片 | 主指标 | 辅助指标 |
|------|--------|----------|
| 今日调用 | 调用次数 | 较昨日变化百分比 |
| 今日 Token | 总 Token 数 | 输入 / 输出 Token |
| 今日费用 | 总费用 | 较昨日变化百分比 |
| 本月费用 | 月累计费用 | 月预算使用率（P2 后） |
| 平均延迟 | 平均响应耗时 | — |
| 平均 TPS | 平均每秒输出 Token | — |

### 4.3 趋势图

| 图表 | 内容 | 用途 |
|------|------|------|
| 调用次数趋势 | 按天分组的调用次数 | 判断使用活跃度 |
| Token 趋势 | 输入/输出/总 Token 堆叠 | 判断上下文与输出变化 |
| 费用趋势 | 按天分组的总费用 | 发现成本峰值 |
| 成功率趋势 | success/failed/timeout 分布 | 发现模型或网络异常 |

### 4.4 占比分析

| 图表 | 口径 |
|------|------|
| 模型调用占比 | 按 Provider + Model 汇总调用次数 |
| 模型费用占比 | 按模型汇总费用 |
| Provider 费用占比 | 按 Provider 汇总费用 |
| Agent 调用占比 | 按 Agent 汇总调用次数 |

### 4.5 Top 排行

| 模块 | 字段 |
|------|------|
| Top 模型消耗 | 模型、调用次数、Token、费用、平均 TPS |
| Top Agent 成本 | Agent、调用次数、费用、平均延迟 |
| 异常请求 | 时间、模型、Agent、状态、错误、费用 |

### 4.6 明细列表

完整明细页字段：时间、Agent、Provider / Model、调用次数、输入 Token、输出 Token、总 Token、费用、延迟、TPS、状态、错误信息。

## 5. 验收标准

### 5.1 用量记录

- [x] 每次模型调用（含流式/非流式/失败/取消）均产生一条明细记录
- [x] 明细记录包含完整的 Token 数（输入/输出/缓存/推理/Embedding）
- [x] 明细记录包含价格快照和计算后的费用
- [x] 费用以 micro USD 存储，无浮点误差
- [x] 流式回复在结束后写入完整记录
- [ ] 用户中断流式时写入 cancelled 状态记录（落库路径待统一验证）
- [x] 模型请求失败时写入 failed 状态及错误信息

### 5.2 用量查询

- [x] 概览 API 返回今日/昨日/本月/自定义范围的汇总数据
- [x] 趋势 API 按天返回 Token、费用、调用次数、成功率
- [x] Top 模型 API 按费用排序返回模型排行
- [x] Top Agent API 按费用排序返回 Agent 排行
- [x] 明细 API 支持按 Provider/Model/Agent/Team/来源/状态/时间范围筛选
- [x] 异常请求 API 返回非 success 状态的请求
- [x] 概览/排行/配额 SUM **不包含** `team_turn`；Team 整体可按 `team_id` 汇总 `team_member`

### 5.3 前端看板

- [x] 概览页展示核心卡片（调用/Token/费用/延迟/TPS）
- [x] 趋势图展示按天的调用/Token/费用/成功率
- [x] Top 模型和 Top Agent 排行列表
- [x] 异常请求列表
- [x] 明细列表支持筛选和分页

### 5.4 用量限额（P2）

- [x] 可为 Agent 设置月度费用预算（`usage_quotas`）
- [x] 可为用户 / 全局设置月度费用预算（`scope_type=user/global`）
- [x] 超过预算后 Agent / Team 对话被拦截（`USAGE_QUOTA`）
- [x] 预算每月自动重置（`period_start` / `period_end` 界定）

### 5.5 用量告警（P3）

- [x] 达到告警阈值时写入监控事件（`usage.budget_alert`）
- [x] 告警阈值可配置（Agent 权限 Tab）

### 5.6 增强分析（P3）

- [x] 小时级趋势查询可用（`granularity=hour`）
- [x] CSV 导出功能可用
- [x] 低性价比模型可被识别和标记（`InefficientModels` + `UsageInefficientModels.vue`）
