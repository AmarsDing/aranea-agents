# 76 编程 Agent 桥接（Coding Agent Bridge）

## 1. 模块概述

精灵助手通过语音/聊天接收编程任务指令，统一桥接外部编程 CLI Agent（Claude Code、Codex、CodeBuddy），在指定项目目录执行任务；外部 agent 运行中的工具确认/澄清消息实时中继给用户，用户语音或卡片操作后回传；任务完成后语音播报结果。Trae 仅作为"拉起 IDE 查看项目"的入口。

## 2. 用户故事

| # | 用户故事 |
|---|---------|
| US-1 | 作为用户，我对精灵说"让 Claude Code 给 aranea-agents 项目跑一下测试并修复失败"，精灵自动派发任务到对应项目目录，执行期间我无需值守 |
| US-2 | 作为用户，当外部 agent 想执行命令或修改文件时，精灵通过卡片+语音问我"Claude Code 想执行 go test，允许吗？"，我语音回答"允许"或点击卡片按钮，外部 agent 收到我的决定后继续 |
| US-3 | 作为用户，我可以随时问"任务跑得怎么样了"，精灵汇报当前进度状态 |
| US-4 | 作为用户，我可以说"取消那个任务"，精灵终止外部 agent 并告知已取消 |
| US-5 | 作为用户，我可以在管理界面维护可用的编程工具（名称、启动命令）和项目目录（项目名 → 磁盘路径），精灵派发时按名称解析 |
| US-6 | 作为用户，任务完成后我可以点击结果卡片上的"在 Trae 中打开"，自动拉起 Trae 并打开对应项目 |
| US-7 | 作为用户，当编程工具未安装或不可用时，精灵明确告知并引导我处理，而不是静默失败 |

## 3. 功能需求

| # | 需求 | 描述 | 优先级 |
|---|------|------|--------|
| FR-1 | 任务派发 | 语音/聊天自然语言指令 → 解析目标工具、项目、任务描述 → 驱动外部 agent 在指定目录执行 | P0 |
| FR-2 | 进度汇报 | 外部 agent 执行中的阶段性进度以事件形式推送，用户可主动询问 | P0 |
| FR-3 | 审批中继 | 外部 agent 的工具执行确认/澄清请求 → 确认卡片 + 语音播报 → 用户语音/点击作答 → 回传外部 agent | P0 |
| FR-4 | 任务取消 | 用户语音/聊天/卡片取消执行中的任务，外部 agent 进程收到取消并停止 | P0 |
| FR-5 | 结果回收 | 任务完成/失败/取消后，语音播报摘要 + 结果卡片展示（工具、项目、状态、摘要、耗时） | P0 |
| FR-6 | Agent 注册管理 | 管理界面维护编程工具条目：标识、显示名、启动命令与参数、环境变量、启用开关 | P0 |
| FR-7 | 项目目录注册 | 管理界面维护项目条目：项目名 → 本机磁盘路径；派发时按名称模糊解析，歧义时向用户澄清 | P1 |
| FR-8 | Trae 拉起 | 结果卡片提供"在 Trae 中打开"操作，拉起 Trae 并打开项目目录 | P1 |
| FR-9 | 可用性探测 | 派发前探测目标工具命令是否可用，不可用时明确语音/卡片提示 | P0 |
| FR-10 | 并发控制 | 同一工具同时执行的任务数有上限，超出排队并告知用户 | P2 |

## 4. 验收标准

| # | 验收标准 |
|---|---------|
| AC-1 | 语音说"让 CodeBuddy 给 <已注册项目> 做 <任务>"，60 秒内任务进入执行状态，流程日志可见派发记录 |
| AC-2 | 外部 agent 发起工具确认时，3 秒内出现确认卡片且语音播报问题；用户语音"允许"后外部 agent 在 5 秒内继续执行 |
| AC-3 | 用户说"取消任务"，10 秒内外部 agent 停止，状态为已取消，语音确认 |
| AC-4 | 任务完成/失败后 5 秒内语音播报摘要，结果卡片可见，卡片含"在 Trae 中打开"（配置 Trae 后可用） |
| AC-5 | 派发未安装的工具时，精灵明确告知"未检测到 <工具>"并中止，不产生僵死任务 |
| AC-6 | 同一工具已达并发上限时再次派发，精灵告知排队位置 |
| AC-7 | 服务重启后，进行中的任务标记为中断，不残留子进程 |
| AC-8 | 项目名有歧义（多个匹配）时，精灵列出候选让用户选择 |

## 5. 非功能需求

| # | 需求 |
|---|------|
| NFR-1 安全 | 外部 agent 仅能访问已注册的项目目录；审批中继默认开启；危险操作（删除/git push/网络）确认卡片需明确标注风险 |
| NFR-2 可靠性 | 外部进程崩溃必须被检测并回收；任务状态机转换持久化，重启可审计 |
| NFR-3 性能 | 进度事件推送需限流（同一任务 ≤ 2 条/秒），禁止每事件一条日志 |
| NFR-4 可观测 | 派发/完成/失败/审批/进程生命周期均有流程日志（K1/K2/K3/K7）与进程日志 |
| NFR-5 兼容 | 桥接层协议与工具解耦，新增 ACP 兼容工具仅需注册配置，不改代码 |

## 6. 交互规格（用户视角）

### 6.1 语音话术契约

| 场景 | 精灵话术示例 |
|------|-------------|
| 派发成功 | "好的，已让 Claude Code 处理 aranea-agents 项目：跑测试并修复失败" |
| 审批询问 | "Claude Code 想执行命令 go test ./...，允许吗？" |
| 审批超时 | "等待确认超时，任务已暂停，你可以稍后继续" |
| 完成 | "任务完成了。Claude Code 修复了 3 个失败的测试，全部通过" |
| 失败 | "任务失败了：外部工具进程异常退出，已记录日志" |
| 工具缺失 | "没有检测到 Claude Code，请先安装或检查配置" |

### 6.2 卡片形态

- **确认卡片**：复用现有工具确认卡片样式，标题区显示外部工具名 + 项目名，正文显示请求内容（命令/文件操作），按钮：允许本次 / 始终允许（本任务内）/ 拒绝
- **结果卡片**：工具名、项目名、状态（完成/失败/取消）、摘要、耗时、"在 Trae 中打开"按钮

## 7. 范围外（Out of Scope）

- ❌ 驱动 Trae SOLO/Chat 执行任务（无官方接口，二期 PoC 评估）
- ❌ GUI 可视化操控任何 IDE（Electron CDP 注入）
- ❌ 结果卡片展示 diff/代码细节（用户明确不需要）
- ❌ 外部 agent 的模型/密钥管理（沿用各 CLI 自身登录态）
- ❌ 远程机器上的 agent 执行（一期仅本机子进程）
