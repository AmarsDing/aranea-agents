# 移动客户端（Aranea Mobile）需求文档

> 编号 72 · 状态：已批准 · 2026-07-28

## 背景

Aranea-Agents 目前只能在 PC 上查看任务执行情况和下达指令。用户需要在外出时通过手机实时监控任务执行、下达任务指令、完成人工确认等操控，避免任务因等待确认而长时间阻塞。

## 已确认的决策（需求探索结论）

| 决策点 | 结论 |
|--------|------|
| 网络环境 | 外网远程访问（手机不在同一局域网时可用） |
| 端形态 | Tauri 2 Android App（Rust 打包，复用现有桌面壳架构） |
| 目标平台 | 仅 Android（APK 直接分发，不上架） |
| 功能范围 | 任务/会话查看 + 实时执行流 + 下达指令 + 完整操控 |
| 后台通知 | Android 前台服务保活 WebSocket + 本地通知 |
| 公网接入 | frp + 用户自有 VPS（Caddy 自动 HTTPS） |

## 用户故事

- US-1：作为用户，我在手机上打开 App 并配置一次服务器地址后，可以登录我的 Aranea 实例。
- US-2：作为用户，我在手机上能看到会话列表和任务列表，了解每个任务的状态和进度。
- US-3：作为用户，我在手机上能实时看到任务执行流（思考/动作/回复/团队阶段），与桌面端一致。
- US-4：作为用户，我在手机上能向精灵助手发消息，下达新的任务指令。
- US-5：作为用户，我在手机上能处理人工确认卡片、暂停/恢复/注入等操控，不让任务因我不在电脑前而阻塞。
- US-6：作为用户，App 不在前台时，任务完成/失败/需要确认能收到手机本地通知，点击通知跳转到对应任务。
- US-7：作为用户，我的服务端暴露到公网后，登录接口有防爆破保护。

## 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-1 | App 首次启动提供服务器地址配置页，地址持久化保存，运行时可修改即时生效 | P0 |
| FR-2 | 复用现有账号密码登录，登录状态可长期保持 | P0 |
| FR-3 | 会话列表、任务列表、任务状态查看的移动版界面 | P1 |
| FR-4 | 实时执行流移动版界面（纵向时间线；DAG 画布降级为分阶段折叠列表） | P1 |
| FR-5 | 移动版聊天输入，可向精灵助手下达指令 | P1 |
| FR-6 | 确认卡片、暂停/恢复/注入按钮的触控化适配 | P1 |
| FR-7 | 登录接口按客户端 IP 限流 + 连续失败锁定 | P0 |
| FR-8 | Android 前台服务保活 WS，Important 级事件触发本地通知，点击跳转 | P2 |
| FR-9 | Token 认证（长期 token + WS Bearer），解决 WebView cookie 持久化不可靠场景 | P2 |
| FR-10 | 扫码配对（桌面端显示含服务器地址的二维码） | P3 |
| FR-11 | frp 部署模板（frps/frpc/Caddyfile）与部署文档 | P0 |

## 非功能需求

- NFR-1：Go 后端继续绑定 `127.0.0.1`，公网暴露面收敛在 VPS，后端业务接口零改动
- NFR-2：前端同一套代码库，不 fork 移动版；仅新增移动端视图组件，共用 stores/services/api 层
- NFR-3：移动布局按屏幕宽度 <600px 自动切换，桌面端行为完全不变
- NFR-4：全链路 HTTPS（Caddy 自动证书），WS 走 wss
- NFR-5：APK 体积 ≤ 30MB
- NFR-6：UI 文案遵循项目多语言规范（zh-CN/en-US）

## 明确不做（YAGNI）

- iOS 版本（架构预留，本期不做）
- 手机端 DAG 编排画布（降级为列表视图；如未来需要单独立项）
- FCM/厂商推送通道（以前台服务保活替代）
- Google Play / 应用商店上架

## 验收标准

- AC-1：手机在外网（4G/非局域网 WiFi）通过配置的 https 域名登录成功
- AC-2：手机上发起任务指令后，能实时看到执行流推进，与桌面端事件一致
- AC-3：任务产生确认请求时，手机上能完成确认/拒绝，任务继续推进
- AC-4：App 切后台后，任务完成/失败/待确认能收到本地通知，点击通知跳转到对应任务
- AC-5：登录接口连续失败触发锁定，锁定期内返回明确错误
- AC-6：桌面端（Windows）现有功能与行为无任何回归
