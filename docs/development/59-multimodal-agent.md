# M59: 多模态 Agent — 需求规格

> 版本：v1.0（2026-07-28）
> 来源：由 `phase5-差异化创新/02-多模态Agent.md` 规划评审后升格为正式模块文档。评审结论：phase5 原规划假设「从零建设 MultimodalAsset/AssetStore/处理器栈」，与代码现状严重脱节——项目已有 27-artifact 资产体系、Chat 附件→ContentPart 链路、media 生成工具、知识库 VisionExtractor、63-tts。本模块重新定义为「在现有资产体系上的增量补齐」，而非另起炉灶。

> 本文档仅描述用户故事、功能需求、验收标准与非功能需求。技术方案见 [59-multimodal-agent.design.md](./59-multimodal-agent.design.md)；进度与任务见 [59-multimodal-agent.development.md](./59-multimodal-agent.development.md)。

## 1. 产品模型

多模态 Agent = 普通 LLM Agent 在对话中理解并产出非文本内容的能力集合，**不是新的 Agent 类型**。

| 语义 | 产品形态 | 入口 |
|------|----------|------|
| 多模态输入 | 用户在 Chat 中随消息上传图片/文件/音频 | Chat 输入框附件按钮（已有） |
| 多模态理解 | Agent 经 Vision/多模态模型理解图片，经提取链路理解文档，经 STT 理解音频 | 自动（按模型能力门控） |
| 多模态产出 | Agent 调用生成工具产出图片/视频/语音，以 Artifact 形式落库 | 对话中工具调用（已有 generate_image 等） |
| 多模态回放 | 历史消息中的附件可重新预览/播放/下载 | 会话消息列表 |

与既有模块的边界：

| 模块 | 职责 | 本模块消费方式 |
|------|------|----------------|
| 27-artifact | 资产上传/存储/预览/下载（StorageKind=local，PreviewKind text/image/pdf/audio/video/binary） | **唯一资产底座**，本模块不新建资产表与存储 |
| 63-tts | 文本转语音工具 | 复用，不重复建设 |
| 37-knowledge | 知识库文档提取（VisionExtractor 图片理解、OOXML 提取、MarkdownOrganizer） | 文档结构化提取能力在本模块中按「Chat 附件理解」场景复用其 Extractor |
| provider/media | 异步媒体生成（文生图/文生视频/图生视频） | 复用，不重复建设 |

## 2. 需求清单

### 2.1 图片输入理解（P0，链路已存在，本模块负责验收与治理）

**用户故事**：作为用户，我在 Chat 中上传一张或多张图片并提问，Agent 能基于图片内容回答。

**验收标准**：
- 上传 png/jpg/jpeg/webp 图片后，消息以图片 ContentPart 进入多模态模型（已实现：[attachments.go](../../internal/agent/attachments.go)）
- 模型不支持视觉时，Turn 在闸前被拒绝并给出明确提示（已实现：`validateTurnAttachmentCapabilities`）
- 单张图片 ≤ 20MB；超限返回明确错误
- 大图在发送前压缩到模型合理输入范围（长边 ≤ 2048px，治理项，待实现）

### 2.2 文件输入理解（P0，部分存在，需增强）

**用户故事**：作为用户，我上传 PDF/DOCX/XLSX/PPTX/TXT/MD 文件并提问，Agent 能基于文件内容回答。

**验收标准**：
- 文本类文件（txt/md/json/csv）现有 blob/preview 注入路径可用（已实现）
- OOXML/PDF 文件经知识库 Extractor 结构化提取为 Markdown 后注入对话上下文（待实现：当前仅纯文本化/blob 治理）
- 单文件 ≤ 100MB；提取失败时降级为文件名+错误提示，不阻断对话

### 2.3 音频输入理解（P1，未实现）

**用户故事**：作为用户，我上传一段录音（mp3/wav/m4a），Agent 能听懂内容并回答。

**验收标准**：
- 音频附件经 STT 转写为文本后注入对话（工具/处理器路径，默认实现）
- 当模型原生支持音频输入（如 Gemini audio ContentPart）时可选直通（增强路径）
- 单个音频 ≤ 50MB；STT 失败时降级为「无法识别音频内容」提示，不阻断文本对话

### 2.4 图片/视频产出（P1，已实现，本模块负责验收）

**用户故事**：作为用户，我要求 Agent「画一张……」「生成一段……视频」，Agent 调用生成工具产出媒体并以附件形式呈现在对话中。

**验收标准**：
- `generate_image` / `generate_video` / `image_to_video` 工具产出 Artifact 并在消息中可预览/下载（已实现，[tools/media](../../internal/tools/media/generate_image.go)）
- 生成失败返回结构化错误，Agent 可转述原因

### 2.5 语音产出（P1，已实现，本模块负责验收）

**用户故事**：作为用户，我要求 Agent「把回复读出来」，Agent 调用 TTS 工具产出语音附件。

**验收标准**：
- TTS 工具产出音频 Artifact，消息中可在线播放（63-tts，待端到端验收）

### 2.6 多模态消息渲染与回放（P0，部分存在，需补齐）

**用户故事**：作为用户，我在消息列表中看到图片缩略图、音频播放器、文件卡片，刷新/重进会话后仍可回放。

**验收标准**：
- 用户消息中的图片附件渲染缩略图，点击 Lightbox 预览（部分已实现，核查补齐）
- Agent 产出的媒体附件以卡片呈现（图片内嵌/音频播放器/视频播放器/文件下载卡）
- **历史回放**：重开会话后，历史消息的附件引用完整恢复（待实现：消息持久化需记录附件引用）
- 前端渲染层与数据层对齐 PreviewKind（image/audio/video/pdf/text/binary）

### 2.7 多模态治理与安全（P1）

**验收标准**：
- 上传类型白名单（图片/文档/音频），可执行文件拒绝
- 附件数量与总大小单 Turn 上限（≤ 10 个 / ≤ 100MB）
- 附件按 session 隔离，跨会话引用拒绝（已实现于 ResolveAttachmentRefs，核查）

### 2.8 视频输入（P2，暂缓）

**用户故事**：上传视频，提取关键帧+音轨转写后理解。暂缓，待 P0/P1 稳定后排期。

## 4. 非功能需求

| # | 需求 | 指标 |
|---|------|------|
| NFR1 | 图片上传 | 单张 ≤ 20MB，单 Turn ≤ 10 个附件 |
| NFR2 | 音频上传 | 单个 ≤ 50MB，STT 1 分钟音频 < 15s |
| NFR3 | 文件上传 | 单个 ≤ 100MB |
| NFR4 | 图片治理 | 长边 > 2048px 自动压缩，体积 > 4MB 自动转 jpeg 质量 85 |
| NFR5 | 提取降级 | 任何提取/STT 失败不阻断文本对话，降级为明确提示 |
| NFR6 | 回放完整性 | 附件引用随消息持久化，重开会话 100% 可回放 |

## 5. 交互规格（用户视角）

### 5.1 上传与发送

- Chat 输入框附件按钮（已有）支持选择图片/文件/音频；选择后显示缩略/文件名卡片，可移除
- 发送后附件卡片显示在用户消息气泡内（图片缩略图、音频播放条、文件图标+名称+大小）

### 5.2 能力提示

- 当前 Agent 模型不支持视觉时，上传图片发送 → 输入框上方提示「当前模型不支持图片理解，请切换多模态模型」（闸前拦截，不消耗 Turn）

### 5.3 生成结果呈现

- Agent 生成图片：消息流中出现图片卡片（内嵌图 + 下载按钮），点击 Lightbox
- Agent 生成语音：消息流中出现音频卡片（播放/暂停/进度条）
- Agent 生成视频：消息流中出现视频卡片（poster + 点击播放）
