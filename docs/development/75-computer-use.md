# M75: Computer Use（桌面 GUI 自动化控制）— 需求规格

> 编号：75 | 状态：已评审（2026-08-12） | 优先级：P0（Windows 优先）
> 上游方案：[2026-08-12-research-computer-use.md](../reports/2026-08-12-research-computer-use.md)（含 OmniParser V2 专题调研）

## 1. 产品模型

让 Aranea Agent 获得"看见并操作本机桌面"的能力：用户在 Chat（或 Team 编排）中用自然语言下达桌面操作任务，Agent 感知屏幕内容、定位目标控件、执行鼠标键盘动作，并将每一步实时展示给用户。

**核心范式**：无障碍树（a11y）优先的元素级精确操作 + 视觉模型兜底，而非纯像素猜测 —— 保证"快速、精确"。

**平台分期**：P0=Windows（本机控制），P2=Linux，P3=iOS 模拟器（macOS 宿主）。本文档需求覆盖全部分期，开发计划以 Windows 为实施范围。

**边界**：本模块是"桌面控制执行层"，不包含任务规划智能（规划由 Agent LLM 完成）；不承诺真机 iOS 控制。

## 2. 需求清单

### 2.1 桌面感知（P0）

- 用户/Agent 可请求当前屏幕快照：前台应用窗口的可访问元素树（名称、类型、位置、是否可交互）+ 可选截图。
- 元素必须带稳定引用（ref），供后续动作直接引用，避免坐标猜测。
- 支持窗口枚举（标题、进程名、前台状态）与按标题聚焦窗口。
- 支持多显示器与 DPI 缩放：所有坐标统一为物理像素，元素位置必须与实际点击位置一致。

### 2.2 语义动作执行（P0）

- Agent 可用自然语言描述目标执行动作：`computer_use.act(target: "保存按钮")` → 自动定位并执行。
- 动作类型：点击（invoke/左键）、右键、双击、输入文本、组合键（如 Ctrl+S）、滚轮、拖拽、等待。
- **a11y 快路径**：元素树模糊匹配命中时直接元素级调用（无坐标、零模型调用）。
- **视觉兜底路径**：a11y 未命中（自绘控件/Electron 等）时，截图解析 + 标注编号 + 视觉模型选择元素，点击其中心点；密集界面支持局部放大再判。
- 动作执行后可做结果校验（局部截图比对），失败自动重试（≤2 次）后向用户报告。

### 2.3 应用启动与窗口管理（P0）

- 按名称/路径启动应用（如"打开记事本"）。
- 按标题正则聚焦已打开窗口。

### 2.4 安全确认门（P0）

- 只读操作（观察、截图）免确认。
- 写操作（act、launch）首次执行需用户确认；支持"允许本次/允许本会话/持久授权/拒绝"四选项，复用现有工具确认门与 tool-grants 持久化。
- **高危语义强制人工确认**：目标文本命中敏感词表（删除/支付/转账/发送/格式化等）时，无论是否持久授权都必须逐次人工确认。
- 禁区：密码管理器/银行类进程窗口前置时拒绝执行动作。
- 预算：每任务最大步数（默认 50）与墙钟超时，超限自动终止并向用户说明。
- 干跑模式：只输出将要执行的动作计划与标注截图，不实际注入输入。
- 急停：用户可随时通过前端按钮/API 立即终止当前桌面任务。

### 2.5 视觉兜底解析服务（P1）

- 接入 OmniParser V2（独立 HTTP 服务，可部署在本机或远程 GPU 机）作为标准视觉解析组件：截图 → 可交互元素 bbox + 语义描述。
- 双源融合：a11y 元素为主表，OmniParser 元素为补充表，IoU>0.1 去重合并。
- 服务不可用时自动降级为"截图 + 视觉模型直判"，并在流程日志中显式标注降级。

### 2.6 审计与步骤回放（P1）

- 每次动作落库审计：任务、目标元素、grounding 路径（a11y/vision）、动作参数、前后截图引用、耗时、确认人、结果。
- 用户可在监控页查看任务步骤流（每步：目标描述、命中方式、截图缩略、耗时、结果）。

### 2.7 实时步骤流展示（P1）

- Chat 内执行桌面任务时，前端实时展示步骤卡片流（复用聊天实时事件通道）：当前正在操作什么、命中路径、成功/失败。

### 2.8 Linux 桌面控制（P2）

- 同构能力覆盖 Linux：AT-SPI 元素树感知 + xdotool(X11)/ydotool(Wayland) 执行；显示服务器自动探测。

### 2.9 iOS 模拟器控制（P3）

- 通过 macOS 宿主的 WebDriverAgent 控制 iOS 模拟器：元素树感知、点按、滑动、输入；sidecar 以 MCP server 形态接入平台托管。

## 3. 验收标准总览

| # | 场景 | 验收标准 |
|---|------|---------|
| A1 | 记事本端到端 | Chat 中说"打开记事本，输入 hello，保存到 test.txt"：Agent 依次 launch→type→key(Ctrl+S)→对话框输入路径→确认，全程步骤流可见，文件真实生成 |
| A2 | a11y 快路径 | 对标准 Win32/WPF 应用（记事本/计算器），act 端到端 P95 < 300ms，零模型调用 |
| A3 | 元素级精度 | a11y 命中时动作 100% 落在目标控件（invoke 无坐标） |
| A4 | 视觉兜底 | 对 Electron/自绘应用（a11y 盲区），视觉路径落点在目标 bbox 内命中率 ≥95%，端到端 P95 < 3.5s（VLM 直判） |
| A5 | 确认门 | act 首次弹出确认卡四按钮全通；敏感词目标强制逐次确认；grant_persisted 后非敏感目标免确认 |
| A6 | 禁区 | 密码管理器窗口前置时 act 被拒绝并说明原因 |
| A7 | 预算 | 超过 max_steps 自动终止并在 Chat 中说明；禁止自动重建会话，须显式 `session.start` |
| A8 | 急停 | 任务执行中点击急停，下一步动作不再注入 |
| A9 | 审计 | 每次 act 在审计表有完整记录；监控页步骤流可回放 |
| A10 | 双轨日志 | session.start/act/fallback/error 等流程日志步骤齐全，进程日志含 sidecar 启停 |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | a11y 路径 P95 < 300ms；视觉路径 P95 < 3.5s；观察流 ≥2fps（差分推送） |
| 精度 | 元素级 100%；视觉落点 ≥95%（SoM + 局部放大） |
| 安全 | 默认最小权限；高危语义不可持久豁免；演示/评测建议在 VM 快照环境 |
| 可靠性 | sidecar 崩溃自动重启；心跳丢失任务自动失败回落；sidecar 僵死看门狗终止 |
| 可观测 | 双轨日志（流程+进程）覆盖 K1-K7；审计可追溯每次动作 |
| 许可 | 不作为选型约束（用户已决策 2026-08-12）；OmniParser 仍独立 HTTP 服务部署以隔离 Python/torch 技术栈 |

## 5. 交互规格（用户视角）

### 5.1 发起桌面任务

用户在 Chat 对 Agent 说："帮我把下载文件夹里最新的 PDF 用记事本打开"。Agent 规划步骤后调用 `computer_use.session.start`（可选）→ `observe` → `act`/`launch` 序列。

### 5.2 首次确认

首次 `act`/`launch` 弹出工具确认卡（复用现有确认卡 UI）：展示动作摘要（"点击『文件』菜单"）、目标应用、参数；按钮：允许本次 / 允许本会话 / 持久授权 / 拒绝。

### 5.3 高危确认

目标文本命中敏感词（如"删除""支付"）时确认卡标注"高危动作"红色徽标，且只有"允许本次/拒绝"两选项。

### 5.4 步骤流

任务进行中，聊天气泡内嵌步骤卡片流：每步显示 目标描述 + 命中路径徽标（a11y=绿色"精确"/vision=蓝色"视觉"）+ 耗时 + 结果；失败步骤展开显示原因与重试。

### 5.5 急停

步骤流卡片头部有"急停"按钮；点击后任务立即终止，卡片标记"已被用户终止"。

### 5.6 降级提示

视觉解析服务不可用走 VLM 直判时，步骤流对应步骤标注"视觉服务降级"；sidecar 未启动时工具返回明确错误并引导用户检查部署。
