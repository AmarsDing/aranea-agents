# Agent 创建弹窗 — 需求文档

本文档从用户视角描述「创建 Agent」弹窗的控件、布局、行为与校验需求。技术实现细节见 [2 agents-create.design.md](./2%20agents-create.design.md)，开发计划见 [2 agents-create.development.md](./2%20agents-create.development.md)。

后端 Agent 运行时基于 trpc-agent-go 框架。

---

## 1. 页面定位与信息架构

| 项目 | 说明 |
|------|------|
| **入口** | Agent 管理列表页 →「创建」按钮 |
| **形态** | 居中模态对话框 |
| **目标** | 采集创建 Agent 所需最小字段；可选描述由用户输入或模板填充；模型可用性经后端校验后再允许提交 |
| **成功结果** | 调用创建接口写入 Agent 行，关闭弹窗并刷新列表（或跳转详情） |

---

## 2. 整体布局（用户视角）

```
┌─────────────────────────────────────────────────────────────┐
│  创建 Agent                                           [×]    │
├─────────────────────────────────────────────────────────────┤
│  [头像]    [两列栅格]     显示名称*  | Agent标识*              │
│            [三列栅格]     行业 ▼  | 部门 ▼  | 职位 ▼          │
│            [两列栅格]     Provider* | 模型* [检查]           │
│  [单列]     描述您的 Agent                                   │
│            [模板芯片行]                                      │
│            [多行描述]                                        │
│            辅助说明文案                                       │
│  [卡片]     自我进化 .............................. [toggle]  │
├─────────────────────────────────────────────────────────────┤
│                          [取消]  [创建]                       │
└─────────────────────────────────────────────────────────────┘
```

| 区域 | 用户感知 |
|------|----------|
| 对话框容器 | 居中模态，约 640–720px 宽，圆角 |
| 标题栏 | 左右分布：标题 + 关闭按钮 |
| 表单主体 | 响应式两列布局，小屏单列 |
| 描述区 | 全宽多行文本 |
| 高级项 | 全宽条带卡片 |
| 页脚 | 右对齐按钮组 |

## 3. 控件清单（用户视角）

### 3.1 显示名称 *（必填）

| 维度 | 说明 |
|------|------|
| **字段** | 显示名称 |
| **必填** | 是 |
| **校验** | 非空；建议最大长度 255；自动 trim |
| **行为** | 聚焦时可展示历史曾用名称供选择回填 |
| **辅助** | 左侧展示头像缩略图 |

### 3.2 Agent 标识 *（必填）

| 维度 | 说明 |
|------|------|
| **字段** | Agent 标识（业务侧 slug） |
| **必填** | 是 |
| **占位** | 例：`my-agent` |
| **辅助文案** | 小写字母、数字、连字符 |
| **校验** | 正则：`^[a-z0-9]+(-[a-z0-9]+)*$`；长度上限 100；创建前查重（未软删行唯一） |
| **行为** | 失焦或防抖后调用「可用性检查」接口；冲突时显示 inline error |

### 3.3 业务分类（行业 / 部门 / 职位）

与技术指标 `agent_type`（如 `open`）**不同**：本块为 **业务画像分类**，数据模型见 `4.agent-type.md`（`agent_category_nodes` + `agents.category_position_id`）。

| 维度 | 说明 |
|------|------|
| **字段** | 行业 / 部门 / 职位（三级级联） |
| **必填** | 否（默认三项均可为空） |
| **占位** | 选择行业 / 选择部门 / 选择职位 |
| **联动** | 切换行业 → 清空部门、职位并加载该行业下部门；切换部门 → 清空职位并加载该部门下职位 |
| **提交** | 仅 **职位**（第 3 层叶子）写入接口；行业、部门仅用于联动与展示 |
| **辅助** | 可选「管理分类」跳转 `/settings/agent-categories`（`4.agent-type.md` §5） |

### 3.4 Provider *（必填）

| 维度 | 说明 |
|------|------|
| **字段** | Provider |
| **必填** | 是 |
| **占位** | 选择 Provider |
| **行为** | 变更时清空已选模型并置「模型检查」为未通过 |

### 3.5 模型 *（必填）+ 检查

| 维度 | 说明 |
|------|------|
| **字段** | 模型 |
| **必填** | 是 |
| **占位** | 输入或选择模型 |
| **「检查」启用条件** | Provider 与模型均非空 |
| **点击「检查」** | 调用模型校验接口；成功则提示通过；失败则显示错误信息 |
| **校验** | 检查通过后才允许提交 |

### 3.6 描述您的 Agent（模板 + 多行文本）

| 维度 | 说明 |
|------|------|
| **区块标题** | 描述您的 Agent |
| **模板芯片** | 小狐、程序员、客服、写手、翻译、小罗、米米（各带图标） |
| **行为** | 点击芯片：将预设 prompt 写入描述框（首次为空时替换，已有内容时追加） |
| **多行输入** | 约 200px 高度的多行文本框 |
| **辅助说明** | 「AI 将根据此描述自动生成 Agent 的上下文文件。留空则使用模板。」 |

### 3.7 自我进化

| 维度 | 说明 |
|------|------|
| **字段** | 自我进化 |
| **文案** | 标题：自我进化；说明：允许 Agent 通过 SOUL.md 随时间进化其风格和语调 |
| **默认值** | 与 `2 agent.md` 一致：**默认开启** |

### 3.8 头像

**关联 `50 Avatar.md`**：本节只约定 **创建/编辑表单内的触点**；头像 **库表、BLOB、`AgentAvatarPicker`、出图 API** 等均以 **`50 Avatar.md`** 为准，与本节 **成对维护**。

| 维度 | 说明 |
|------|------|
| **位置** | 与「显示名称」同一行或名称字段左侧 |
| **行为** | 点击头像打开选图流程：内置图库 + 本地上传 + 裁剪 |
| **展示** | 列表/预览使用缩略图；`emoji` 与 icon 二选一由 UI 定 |

### 3.9 页脚按钮

| 按钮 | 行为 |
|------|------|
| **取消** | 关闭对话框；若有未保存修改可二次确认（可选） |
| **创建** | 表单校验通过 **且** 模型检查通过才可点；点击后 loading，调用创建 API，成功关闭并通知列表 |
| **关闭** | 标题栏关闭按钮，行为同取消 |

## 4. 校验规则（用户视角）

| 字段 | 规则 |
|------|------|
| 显示名称 | 非空，最大 255 字符 |
| Agent 标识 | 正则 `^[a-z0-9]+(-[a-z0-9]+)*$`，最大 100 字符，未软删唯一 |
| Provider | 必选 |
| 模型 | 必填，且需通过模型检查 |
| 业务分类 | 可选；若选则需选到职位叶子节点 |
| 描述 | 可选；空则使用模板 |
| 自我进化 | 默认开启 |

**校验顺序**：客户端必填/格式 →（可选）agent_key 唯一 → 模型检查 → 提交。

---

## 5. 交互行为需求

1. 用户点击「创建 Agent」→ 打开模态对话框
2. 填写必填字段 → Agent 标识失焦时前端正则校验
3. 选择 Provider → 自动加载可用模型列表
4. 输入模型 → 点击「检查」→ 调用模型校验接口
5. 检查通过 → 「创建」按钮可用
6. 点击「创建」→ 调用创建 API
7. 成功 → 关闭弹窗，刷新列表，toast「创建成功」
8. 失败 → 显示 inline error 或 banner

---

## 6. 验收标准

- [ ] 必填项标 `*` 与提交前错误提示一致
- [ ] Agent 标识符合「小写字母、数字、连字符」且唯一
- [ ] **业务分类**：行业/部门/职位级联正确；提交仅带职位叶子节点；与技术类型 `agent_type` 无混淆
- [ ] 未做模型「检查」时「创建」不可点（按既定规则）
- [ ] 模板芯片与描述框、服务端生成上下文文件的约定一致（空描述 = 模板）
- [ ] 自我进化默认开启
- [ ] **头像**：点击头像打开选图流程；与 **`50 Avatar.md`** 一致
- [ ] 深色主题下对比度与焦点态可读

## 7. Agent 类型：LLM 与 A2A 远程代理（2026-05-20）

> 完整 A2A 协议与 Endpoint 语义见 [26 a2a-protocol.md](./26%20a2a-protocol.md) §2.5。技术设计见 [26 a2a-protocol.design.md](./26%20a2a-protocol.design.md) §十一。

### 7.1 类型选择

创建对话框顶部增加 **Agent 类型**（单选，默认 LLM）：

| 类型 | 说明 | 用户可见标识 |
|------|------|--------------|
| **LLM Agent** | 现有行为：Provider + Model + 描述 + 进化等 | 无额外徽章 |
| **A2A 远程代理** | 接入外部 A2A 服务，无需本地 LLM | 列表/卡片 `A2A ↗` |

与 `agents.agent_type`（技术开放类型，如 `open`）、`category_position_id`（业务分类）**三者独立**。

### 7.2 LLM Agent 表单（默认）

与 §3 一致，无变更。

### 7.3 A2A 远程代理表单

选择「A2A 远程代理」后：

| 控件 | 必填 | 说明 |
|------|------|------|
| 显示名称、Agent 标识、头像、业务分类 | 同 LLM | 与 §3.1–3.3、§3.8 一致 |
| **远程 URL** | ✅ | A2A 服务根地址；旁侧「发现 AgentCard」按钮 |
| 流式响应 | — | 默认跟随远程 Card |
| 超时（秒） | — | 默认 30 |
| 鉴权类型 | — | none / api_key / mtls；展开对应配置项 |

**隐藏或禁用**：Provider、模型检查、描述模板（可选保留简短描述）、自我进化、记忆/Skill 相关（创建时不展示）。

### 7.4 创建后行为

- 列表刷新并展示 `A2A ↗` 徽章
- 可选：自动跳转 Agent 设置 → A2A Tab 展示只读远程 AgentCard
- Chat 侧栏可选该 Agent，交互与 LLM Agent 一致

### 7.5 验收要点（A2A Proxy）

- [ ] 类型切换时表单字段正确显隐
- [ ] 远程 URL 为空时不可提交
- [ ] 「发现 AgentCard」成功后可预览远程名称与 capabilities
- [ ] 创建成功后 Chat 可选用该 Agent
- [ ] 与 LLM 创建流程互不干扰（默认仍为 LLM）

## 8. trpc-agent-go 对齐需求（M2 Agent 构建）

> 本节补充 `plan.md` M2 模块的对齐需求，确保 Agent 构建完全复刻 trpc-agent-go `llmagent` 能力。技术设计见设计文档 §九。

### 8.1 占位符变量

**需求**：
- Agent 的 `system_prompt` 支持 `{variable_name}` 占位符
- 运行时从 `Invocation.Variables` 注入实际值
- 内置变量：`{agent_name}`、`{session_id}`、`{user_id}`、`{current_date}`
- 自定义变量：通过 `AgentRuntimeSetting.variables_json` 配置

**验收标准**：Agent Instruction 中 `{key}` 被正确替换为运行时值

### 8.2 ModelInstructions

**需求**：
- `AgentRuntimeSetting` 增加 `model_instructions_json` 字段
- 格式：`{"gpt-4o": "你是一个精确的助手", "claude-3": "你是一个有创意的助手"}`

**验收标准**：不同模型使用不同的指令片段

### 8.3 ContextCompaction

**需求**：
- `AgentRuntimeSetting` 增加 `context_compaction` 布尔字段
- 压缩策略：保留最近 N 轮 + 摘要历史

**验收标准**：长对话自动压缩，不丢失关键信息

### 8.4 SessionSummary

**需求**：
- `AgentRuntimeSetting` 增加 `session_summary` 布尔字段
- Session 结束时自动生成摘要
- 新 Session 可通过摘要继承上下文

**验收标准**：新 Session 可通过摘要继承旧 Session 上下文

### 8.5 SkillLoadMode

**需求**：
- `AgentRuntimeSetting` 增加 `skill_load_mode` 字段
- 可选值：`auto`（自动匹配）、`manual`（手动指定）、`none`（不加载）

**验收标准**：Agent 按配置策略加载技能

### 8.6 StructuredOutput

**需求**：
- `AgentRuntimeSetting` 增加 `output_schema_json` 字段
- LLM 输出自动校验和解析

**验收标准**：Agent 输出符合预定义的 JSON Schema

### 8.7 ModelSelector

**需求**：
- `AgentRuntimeSetting` 增加 `model_selector` 字段
- 可选值：`default`（使用配置模型）、`auto`（根据任务复杂度选择）

**验收标准**：Agent 根据任务复杂度动态选择模型
