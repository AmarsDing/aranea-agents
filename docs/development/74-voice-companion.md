# M74: 语音伴侣（贾维斯桌面语音）— 需求规格

> 版本：v1.0（2026-08-05）
> 来源：语音支持需求经头脑风暴评审后立项。评审结论：语音只是平台的新 **I/O 形态**，Chat Turn 编排内核（工具/记忆 L0-L4/Team/Graph/审批/流程日志）零改动；桌面载体复用已有 Tauri 2.x 壳（`web/src-tauri`）；3D 形象走抽象科幻 HUD 路线（Three.js 程序化生成，零美术资产依赖）；语音链路走级联流式管线（流式 ASR → 现有 Chat 管线 → 分句流式 TTS），不走端到端 S2S Realtime API（后者旁路平台编排内核，与平台定位冲突）。
>
> 本文档仅描述用户故事、功能需求、验收标准与非功能需求。技术方案见 [74-voice-companion.design.md](./74-voice-companion.design.md)；进度与任务见 [74-voice-companion.development.md](./74-voice-companion.development.md)。

---

## 1. 产品模型

语音伴侣 = Aranea 平台的**桌面语音交互形态**：一个常驻桌面的科幻 HUD（贾维斯），用户用语音（或文字）与 Agent 连续对话，Agent 通过语音播报回复，并可受控地操作用户桌面（打开应用等）。**不是新的 Agent 类型**——所有对话都经由现有 Chat Turn 管线执行，全部编排能力（工具、记忆、团队、审批）原样保留。

| 语义 | 产品形态 | 入口 |
|------|----------|------|
| 语音输入 | 用户对麦克风说话，实时字幕，自动判停后发送 | 桌面 HUD / 语音模式 |
| 语音播报 | Agent 回复以语音形式播出，可随时打断 | 自动（语音模式开启时） |
| 科幻 HUD | 3D 全息能量球常驻桌面，状态（聆听/思考/播报）可视化 | 桌面端启动即见 |
| 聊天窗口 | HUD 旁滑出的完整聊天面板，可打字、看记录 | 点击 HUD / 热键 |
| 桌面控制 | 语音指令让 Agent 打开本机应用/网址等，科幻开启动画 | 语音或文字指令 |
| 移动端伴侣 | Android 上同一语音对话体验 | Tauri Android 路径 |

与既有模块的边界：

| 模块 | 职责 | 本模块消费方式 |
|------|------|----------------|
| 1-chat | 消息管线、Turn 编排、流式 delta、CancelRun | **唯一执行内核**，ASR 终稿与打字走完全相同的入口 |
| 23-tools | 工具注册/装配/确认门 | 客户端工具（打开应用等）注册为普通工具，沿用确认门 |
| 27-artifact | 资产存储（audio PreviewKind） | 语音消息音频留档/回放 |
| 63-tts | Agent 主动调用的 TTS **工具**（占位，未实现） | 职责独立：63 是工具化 TTS（Agent 调用产出音频附件）；本模块是**播报管线**（会话级语音输出）。两者可后续共用 SpeechProvider 端口 |
| 59-multimodal-agent | 多模态理解（音频附件 STT 理解是其 P1） | 本模块 V4 期提供 ASR 能力给附件链路复用 |
| 72-mobile-client | 移动端客户端 | 复用其 Tauri Android 路径承载语音伴侣 |
| 9-provider | LLM Provider 配置体系 | Speech Provider 配置参照其管理模式（System Settings 管理面） |

## 2. 需求清单

### 2.1 语音对话闭环（P0）

**用户故事**：作为用户，我在桌面端对麦克风说话，Agent 能快速以语音回复我，形成「说-听」闭环。

**验收标准**：
- 说话过程中实时显示识别字幕（partial），停顿后自动判停并发送
- ASR 终稿文本作为用户消息进入对话，与打字发送的消息在记录中无差别呈现
- Agent 回复文本流式产生的同时，语音按句流式播报，无需等全文生成完毕
- 说完话到开始听到回复的端到端延迟 < 2.5 秒（NFR1 环境达标时）
- 语音模式下每条用户语音的音频可选留档（配置开关），消息可回放原音

### 2.2 连续对话与打断（P0）

**用户故事**：作为用户，我开启语音模式后可以连续多轮对话，Agent 播报时我随时开口说话就能打断它，无需任何按键操作。

**验收标准**：
- 语音模式开启后：聆听 → 识别 → 播报 → 自动回到聆听，循环免提
- 播报期间检测到人声 ≤ 300ms 内停播并切换回聆听态（barge-in）
- 打断同时取消后端正在生成的 Turn（不复读旧内容）
- 扬声器播放 Agent 语音时不应被自身播报触发误打断（回声消除生效）
- 语音模式可一键退出；退出后聊天窗口文字对话不受影响

### 2.3 科幻 HUD 交互（P0）

**用户故事**：作为用户，桌面上常驻一个科幻风格的全息能量球，它的形态和颜色让我一眼看出 Agent 当前在聆听、思考还是说话。

**验收标准**：
- HUD 为 3D 全息能量球（能量核 + 环绕粒子 + 线框壳），透明背景、无边框、可拖拽、可置顶
- 状态可视化：idle（呼吸脉动）/ listening（外环展开 + 实时频谱）/ thinking（环加速 + 核收缩）/ speaking（随播报音频振幅跳动）/ interrupted（红闪后回聆听）
- 点击 HUD 滑出聊天窗口；双击/热键收起为迷你态
- HUD 动画帧率流畅（桌面端 ≥ 40fps），不阻塞语音采集

### 2.4 聊天窗口（P0）

**用户故事**：作为用户，我可以让 HUD 旁边弹出聊天窗口，用打字方式对话，也能看到语音对话的历史记录。

**验收标准**：
- 聊天窗口从 HUD 旁滑出/收起，与 HUD 位置联动
- 完整消息渲染能力（markdown、步骤、附件、工具调用展示），与普通 Web 端聊天一致
- 语音产生的对话记录在该窗口可见；同一会话在普通 Web 端打开也可见（同一份数据）
- 窗口内可直接打字发送，与语音输入混用

### 2.5 语音控制桌面应用（P1）

**用户故事**：作为用户，我说「打开微信」「打开浏览器」，HUD 浮出科幻确认卡，确认后应用以炫酷的动画效果被打开，并有语音播报反馈。

**验收标准**：
- Agent 可将「打开本机应用/网址」识别为客户端工具调用，在**用户本机**（而非服务器）执行
- 执行前弹出全息确认卡（应用图标 + 名称 + 操作描述），支持语音确认（「好的」）或点击确认；可配置为免确认（沿用「始终允许」授权语义）
- 确认后播放粒子发射开启动画，随后目标应用启动，HUD 语音播报结果（成功/失败原因）
- 目标应用不在白名单或找不到时，给出明确语音/文字提示，不静默失败
- 桌面客户端不在线时，Agent 应明确告知「桌面客户端未连接」，而非假装已执行

### 2.6 深度系统控制（P2）

**用户故事**：作为用户，我可以用语音让 Agent 完成更多桌面操作：调节音量/亮度、窗口管理、截图、文件操作、读取屏幕内容。

**验收标准**：
- 常用系统控制（音量/亮度/窗口）以客户端工具形式提供，逐个接入确认门
- 截图可回传对话作为图片附件，Agent 可基于截图内容回答（走多模态图片理解链路）
- 文件操作限定在用户授权目录内；危险操作（删除/覆盖）必须确认
- 每项能力接入时同步更新工具白名单与审计日志

### 2.7 语音消息留档与回放（P1）

**用户故事**：作为用户，我可以在历史消息中回看语音对话，必要时重听当时说的话。

**验收标准**：
- 开启留档后，用户语音以音频附件形式挂在用户消息上，可在线播放
- 留档开关默认关闭；关闭时不产生音频文件
- 音频附件随消息持久化，重开会话后仍可回放（复用 27-artifact 资产体系）

### 2.8 Speech Provider 可插拔与管理（P1）

**用户故事**：作为管理员，我可以配置 ASR/TTS 服务商（首接火山引擎，预留阿里/OpenAI），设置音色、语言等参数，无需改代码即可切换。

**验收标准**：
- ASR 与 TTS Provider 各自可配置（驱动、端点、凭据、音色、语言），经 System Settings 管理面维护
- 凭据加密存储，不出现在日志中（敏感字段）
- Provider 未配置或失效时，语音功能给出明确降级提示（仅文字模式），不影响文字对话
- 新增 Provider 只需实现端口接口并注册，不动语音网关与前端

### 2.9 移动端语音伴侣（P2）

**用户故事**：作为用户，我在 Android 手机上也能用同样的语音对话体验。

**验收标准**：
- 同一套语音伴侣 UI 在 Android 上可用（布局自适应：HUD 居中、聊天窗口全屏抽屉）
- 语音采集/播放在移动 WebView 中正常工作
- 移动端不支持的能力（如打开桌面应用）优雅降级并明确提示

### 2.10 音频附件理解（P2，与 59 号模块共建）

**用户故事**：作为用户，我上传一段录音文件，Agent 能听懂内容并回答（59-multimodal §2.3 的落地）。

**验收标准**：
- 音频附件（mp3/wav/m4a）经 STT 转写为文本后注入对话（默认路径）
- 当模型原生支持音频输入时可选直通（增强路径）
- STT 能力复用本模块的 ASR Provider 端口，不重复建设
- 失败降级为「无法识别音频内容」提示，不阻断文本对话

## 4. 非功能需求

| # | 需求 | 指标 |
|---|------|------|
| NFR1 | 端到端首音延迟 | 语音停顿 → 开始听到回复 < 2.5s（ASR 尾延迟 ≤600ms + LLM 首 token ≤900ms + 首句 TTS ≤700ms；稳定网络 + Provider 正常时） |
| NFR2 | 打断响应 | 人声检测 → 本地停播 ≤ 300ms；后端 Turn 取消 ≤ 1s |
| NFR3 | 音频采集 | 16kHz/16bit/单声道 PCM；20ms 帧；回声消除开启（扬声器场景） |
| NFR4 | 播报连续性 | 跨句音频拼接无明显断点/爆音；句间间隙 < 150ms |
| NFR5 | 并发与资源 | 单用户单语音会话；HUD 渲染 ≥ 40fps；语音会话空闲 10 分钟自动挂起 ASR 连接 |
| NFR6 | 安全 | 客户端工具全部经确认门/授权体系；可执行目标白名单化；凭据加密存储；麦克风使用期间有明确视觉指示 |
| NFR7 | 降级 | ASR/TTS Provider 故障时自动退回纯文字模式并明确提示；任何语音失败不影响文字对话 |
| NFR8 | 隐私 | 未开启语音模式时不采集麦克风；留档音频按会话隔离，跨会话引用拒绝 |

## 5. 交互规格（用户视角）

### 5.1 进入/退出语音模式

- 桌面端启动即见 HUD（迷你球形态）；点击展开为完整 HUD
- 点击 HUD 麦克风按钮（或全局热键）进入语音模式：HUD 切聆听态，出现「正在聆听…」指示与麦克风使用标识
- 再次点击/热键或关闭 HUD 退出语音模式；退出后一切文字功能不变

### 5.2 语音对话

- 聆听态说话：HUD 频谱随声音起伏；实时字幕浮现在 HUD 下方
- 停顿片刻：字幕转正为已发送消息，HUD 切思考态
- Agent 播报：HUD 随声音跳动；聊天窗口同步流式出字
- 播报中说话：播报立即停止，HUD 红闪一下回到聆听态，开始识别新指令

### 5.3 打开应用

- 语音说「打开微信」→ HUD 前浮出全息确认卡（图标 + 名称 + 「确认打开？」）
- 用户说「好的」或点击确认 → 确认卡化作粒子流发射 → 应用启动 → 语音播报「已为你打开微信」
- 说「算了」或点击取消 → 卡片消散，无动作
- 对该应用选择「始终允许」后，后续同类指令免确认直接执行（沿用工具授权语义）

### 5.4 聊天窗口

- 点击 HUD → 聊天窗口从 HUD 右侧滑出；再点 HUD 或点收起按钮 → 滑回
- 窗口内可打字、发附件、查看历史；语音字幕与消息同流呈现
- 窗口与 HUD 可分别拖拽位置，再次打开时记忆上次位置

### 5.5 降级提示

- 未配置语音 Provider：HUD 麦克风按钮置灰，悬停提示「请先在系统设置中配置语音服务」
- 播报/识别失败：HUD 显示短暂错误提示并自动退回文字模式，聊天记录中保留失败原因
