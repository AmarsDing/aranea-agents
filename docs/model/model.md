# 模型与供应商功能需求

本文档只描述**功能需求**（不含表结构细节，见同目录 **`sql.md`**）。需求来源对齐 **`pkg/docs/9 provider.md`** 与当前 **`pkg/backend`** 已实现能力。

---

## 1. Provider / 模型管理

1. **列表与检索**：支持按供应商代码、展示名、模型名、标签等搜索；支持分页。
2. **列表展示**：每一行对应一个「供应商 + 模型 API ID」配置；展示启用状态、模型分类标签、模型规模与上下文等辅助选模信息；展示近 30 天调用量、费用、成功率、延迟、TPS、热度等统计（无数据时占位，不破坏布局）。
3. **启用 / 停用**：支持在行内或详情中切换启用状态，与 Agent 选模校验一致（仅可选用已启用且未删除的 provider+model）。
4. **新增 / 编辑 / 删除**：支持创建、更新、删除单条模型配置；删除前确认；编辑时 API 密钥可「留空表示不修改」。
5. **连接信息一致性**：同一供应商代码下多条模型共享连接配置时，修改基础 URL 或密钥应对该供应商下所有行保持一致（批量更新）。
6. **供应商与模型标识**：供应商代码为小写 slug；模型 ID 与上游 API 一致；业务上保证同一供应商 + 模型 API ID 不重复（与唯一键策略一致）。

---

## 2. 连接与鉴权

1. **供应商类型**：支持配置厂商类型（如 OpenAI Compatible、Anthropic 等），用于路由不同的自检与调用逻辑。
2. **连接参数**：可配置 API 基础 URL、API 密钥；密钥展示需脱敏；列表或详情能区分「已配置 / 未配置」密钥。
3. **连接自检**：支持对指定配置发起模型存在性 / 元数据探测（如 OpenRouter、OpenAI 兼容 `/models`、Anthropic 等），并将结果用于回填展示名、上下文、价格建议等（具体字段以后端自检接口为准）。

---

## 3. 模型分类与展示属性

1. **能力分类**：支持为一个模型配置一个或多个分类；每项包含枚举键、展示名、一句话说明（Tooltip）；用于列表展示与 Agent 选模辅助。
2. **可选展示字段**：模型规模标签、上下文长度（K）、最大输出 Token、用户主观评级（数值越大表示越强）；热度和 TPS 为系统统计结果，界面只读、不提供手工录入（与产品文档一致）。
3. **排序**：支持在同一供应商下配置展示顺序。

---

## 4. 计价与成本

1. **价格配置**：支持维护输入 / 输出 / 缓存输入 / 推理 / 嵌入等单价（微美元每千 Token 等等价口径以后端为准）；保存后与计价规则同步，供调用计费使用。
2. **调用成本归因**：每次模型调用应能记录 Token、费用、延迟、成功失败等，并支持按模型 / Agent / 时间维度汇总（支撑列表与趋势）。

---

## 5. 使用统计与趋势

1. **明细与聚合**：支持基于调用事件写入明细表，并按日聚合；用于近 30 天调用次数、Token、费用、平均延迟、TPS 等。
2. **热度**：热度分为只读计算字段（0～100），由调用次数、Token、费用、成功率、最近使用时间等综合得出，规则可配置但不对普通用户手工编辑。
3. **趋势看板**：支持按模型查看历史趋势（调用、Token、费用、延迟、成功率等）及最近调用抽样列表；可与明细 / 日表对接。
4. **会话侧汇总**：会话维度可累计模型调用次数、Token 与费用，便于对话级成本感知（与后端会话字段更新行为一致即可）。

---

## 6. API 与集成

1. **REST 资源**：提供模型供应商资源的列表、详情、创建、更新、删除；路径与后端现有 **`/api/v1/llm-provider-models`** 族一致或可映射。
2. **自检接口**：提供模型 / 连接自检接口（如 **`inspect`**），供 UI 或 CLI 触发。
3. **元数据接口（可选）**：可提供模型分类等枚举下发，供前端下拉与 Tooltip 一致。
4. **CLI / 技能**：支持管理员通过 CLI 或受控技能列出、增删改 Provider 模型（与内置工具权限一致）。

---

## 7. Embedding 与记忆链路

1. **用途区分**：调用类型应能区分聊天与嵌入等（`usage_kind`），以支撑记忆 / 检索侧 Embedding 配置与成本统计。
2. **配置协同**：Embedding 相关模型选择与 **`9 provider.md`** 及 Agent 运行时记忆配置一致；具体开关与字段以运行时设置文档为准。

---

## 8. 非功能与安全

1. **密钥安全**：生产环境应对 `api_key` 加密存储或接入密钥管理服务；本地开发库也需避免日志明文打印密钥。
2. **软删与审计**：删除行为宜支持软删或保留审计痕迹，避免引用断裂（与平台 `deleted_at` 约定一致）。
3. **多租户（若适用）**：工作区 / 用户维度的统计与隔离与 `model_token_usage_*` 表中的 `workspace_id`、`user_id` 等字段对齐。
