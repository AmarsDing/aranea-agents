# 接口与数据库开发规范（Kratos + Ent + Web）

面向后续开发与 AI：**先协议、再生码、分层清晰、最后用 Wire 串起来**。本仓库的路径以当前代码为准（例如入口 `cmd/admin`、HTTP JSON 挂载在 **`/v1/...`**，由生成的 `*_http.pb.go` 与 `axios` baseURL 配合）。

---

## 1. 分层与依赖方向

```
api/**/*.proto （唯一对外契约：HTTP+gRPC）
        ↓  make api / protoc 生成 *.pb.go、*_grpc.pb.go、*_http.pb.go、web/src/services/ TypeScript）
internal/service  （实现 gRPC 接口 AdminServiceServer，转调 biz）
        ↓
internal/biz      （领域模型、Usecase、Repo 抽象接口、paging/filter 组装）
        ↓
internal/data     （Ent + SQLite CRUD / pgvector Repo 实现）
```

**禁止**：`data` 直接依赖 `service` / `proto`；`biz` 不导入 `api/*/v1`。跨层只允许 **向内**依赖。

---

## 2. 新增一对「HTTP(JSON) API」的标准流程（以 AdminService 为例）

### 2.1 编辑 Proto

- 路径：`api/kratos/<module>/v1/<module>.proto`（或新业务包）。
- 使用 **Google API HTTP 注解**：`google/api/annotations.proto` 中为每个 RPC 配置 `post:` / `get:` 与方法体 `body`。

### 2.2 生成代码

在项目根：

1. **`make init`**（首次或未装插件时）。
2. **`make api`**：生成：
   - `./api/**`：`*.pb.go`、`*_grpc.pb.go`、`*_http.pb.go`
   - **`web/src/services/**`**：`protoc-gen-typescript-http` 输出的客户端（路径与 `Makefile` 中 `--typescript-http_out` 一致）。
3. 如有仅 `internal/conf`：`**make config**`。

合并入 PR 时请包含生成的 **Go + TS**，避免 CI 与本地不一致。

### 2.3 实现服务端

| 步骤 | 位置 | 说明 |
|------|------|------|
| 嵌入未实现 RPC | `internal/service/*.go` | `struct XxxService struct { embed v1.UnimplementedXxxServer; uc *biz.Usecase }`，实现新方法：将 `proto` Request 转成 `biz` 入参，`biz` 结果转 proto（参见 `convertAdmin`、`timestamppb`）。 |
| 业务逻辑 | `internal/biz/` | **扩写或新增** Usecase；错误用 `errors`/`github.com/go-kratos/kratos/v2/errors` 与存量风格一致；列表用 `pagination.go` 的 `ListOption`。 |
| 注册 HTTP | `internal/server/http.go` | **`v1.RegisterXxxHTTPServer(srv, service实例)`**。 |
| Wire | `biz.ProviderSet`、`service.ProviderSet`、`data.ProviderSet`（见 §4）；`cmd/admin/wire.go` 不手写实现，改动后 **`go run github.com/google/wire/cmd/wire ./cmd/admin`**生成 **`wire_gen.go`**。 |

## 3. Web 前端（TypeScript）：定义位置与用法

### 3.1 生成物位置

- 生成目录：`web/src/services/kratos/admin/v1/`（随 proto 版本与 Makefile 产出路径变化）。
- `web/src/services/index.ts` 对工厂 **聚合并导出**：  
  ```ts
  import { createAdminServiceClient } from "./kratos/admin/v1/index";
  import { requestHandler } from "./axiosHandler";
  export function createAdminService() {
    return createAdminServiceClient(requestHandler);
  }
  ```

### 3.2 运行时请求

- **统一网关**：`web/src/services/axiosHandler.ts` — `axios` 实例 `baseURL = getBackendOrigin()`（来自 `web/src/config/runtime.ts`）。
- 开发环境常为 **空字符串 + Vite 代理**，使请求落到同源 `/v1/...`。

### 3.3 新增模块 Web 接入步骤（Checklist）

1. Proto 中加 `service`/RPC，`make api`。
2. 确认 `web/src/services/kratos/<...>/index.ts` 已生成 **`createXXXServiceClient`**。
3. 在 `web/src/services/index.ts` **增加一行**  
   `export function createFooService()` → **`createFooServiceClient(requestHandler)`**。
4. 页面/`import.meta.env`、`runtime-config.json` 仅调 **`getBackendOrigin()`**，不按接口拆多套根路径（与现有注释一致）。

## 4. 数据库新增：SQLite（Ent）+ 可选 Postgres（向量）

### 4.1 原则

| 用途 | 技术 | 说明 |
|------|------|------|
| 后台业务表、用户配置缓存 | **SQLite + Ent** | `internal/data/ent/schema/*.go` 建模；迁移见 `DEPLOY_ENV=dev` 与 Makefile。 |
| 向量记忆（按维度拆表） | **Postgres pgvector** | `internal/data/pgvector`、`internal/data/memory.go`；用户维度偏好存 SQLite。**不要**在同一套 Ent Client 上使用 Postgres。 |

### 4.2 新增实体（Ent）

1. 在 **`internal/data/ent/schema/`** 添加 `XXX.go`，定义 **Fields（及 Index/Edge 如需）**。  
2. **`go generate ./internal/data/ent`**（或项目已有 `Makefile` **`generate`** 目标内含 `go generate ./...`）。  
3. 实现 **`internal/data/<entity>.go`**：类型 **`xxxRepo`** 实现 **`biz.XxxRepo`**，`NewXxxRepo(d *data.Data)`内用 **`d.Ent()`**（与 **`Data.entClient`** 同一指针，仅 SQLite）。
4. 在 **`internal/biz/`**：**定义 `Xxx` 模型 + `XxxRepo` interface + `XxxUsecase`**；如对外暴露再在 proto 中加 RPC 与 service 封装。

### 4.3 Biz 仓储接口契约

- 接口放在 **`internal/biz`**，例如 `AdminRepo`。  
- 实现放在 **`internal/data`**，`admin.go` **仅依赖** `biz` 与 **`internal/data/ent`**。  
- 列表：`ListXXX(ctx, ...ListOption)` 与 `pagination.go`、`ents.ApplyFilter` 一致。

### 4.4 Wire

- **`data.ProviderSet`**：`NewData`、`NewXxxRepo`。  
- **`biz.ProviderSet`**：`NewXxxUsecase`。  
- **`service.ProviderSet`**：`NewXxxService`。  
- 重新生成 **`cmd/admin/wire_gen.go`**。

## 5. 错误码、分页、校验（与存量对齐）

- **HTTP**：Kratos 错误链；中间件：`internal/server/http.go` 中 `recovery`、`validate`。  
- **列表**：Biz 传入 `biz.ListOffset` / `ListLimit` / `ListFilter` / `ListOrderBy`（见 **`internal/biz/pagination.go`**、`internal/service/admin.go`）。

## 6. AI / 人机协作时使用本规范的检查清单（复制即用）

新增「带数据库的 REST 接口」时请逐项确认：

- [ ] **`api/**/*.proto`**：RPC、HTTP path、请求/响应字段已定义。  
- [ ] 已运行 **`make api`**（及需要的 **`make config`**），Go 与 **`web/src/services`** 已提交。  
- [ ] **`internal/biz`**：模型 + `Repo` 接口 + `Usecase` 方法与错误语义齐全。  
- [ ] **`internal/data`**：Ent Schema + Repo + 仅通过 `Ent()`/`Postgres()` 访问 DB。  
- [ ] **`internal/service`**：`Unimplemented*` 嵌入、proto ↔ biz 映射。  
- [ ] **`internal/server`**：Register HTTPServer（与 gRPC 若启用）。  
- [ ] **`web/src/services/index.ts`**：导出新 **`createXXXService`**。  
- [ ] **`wire`** 已更新并成功生成 **`cmd/admin/wire_gen.go`**。
