# ADR：知识库内容、权限与存储可靠性

日期：2026-10-21。背景：同日业务与用户体验审查发现不同入口未维护统一授权、原件、版本及索引不变量。用户已要求按报告修复。

## 决策

1. 在已有知识领域与服务边界修复，不改变组织/专项 Agent 架构。
2. 检索与治理均以可信调用上下文授权；显式库 ID 仅缩小范围，不能授予权限。
3. 二进制原件只读，派生 Markdown 独立；修复旧 MIME 行的编辑/下载防线。
4. 本地文件操作使用回收站与补偿，数据库身份和计数同事务；尚无文件迁移保障的本地跨库组合拒绝执行。
5. 团队正文 CAS 与失效旧 chunks 同事务；复用既有重放与后台修复，以“短暂缺索引”代替“继续回答已否决事实”。
6. 治理提案锁定、处置和终态采用事务；索引重放在事务提交后进行，失败不丢任务资格。
7. 保存响应返回提交版本 hash；前端编辑版本和持久版本分别跟踪，并提供离开保护和隔离草稿。
8. 默认新库使用现有托管 team 模式；新增 GetDocument RPC 支持不依赖分页列表的命中打开。

## 后果与替代方案

会新增向后兼容的 RPC/响应字段；不支持的本地跨库移动返回明确错误。正文提交后索引重建期间可能短暂无命中，但不会继续返回被否决旧证据。选择可靠拒绝而非只改归属；选择原件与提取稿隔离而非覆盖原始路径；选择共享调用边界授权而非只修单个 HTTP handler。

## 验证

针对越权、原件 hash、覆盖失败补偿、删除重扫、正文 CAS、保存竞态、跨库命中、时态及范围编写回归。真实环境与浏览器结果按实际证据记录，不把静态检查等同用户验收。
