## 一、评审结论

1. **SP1 作为知识内核是正确的第一步，三件套质量达标**——块模型、双链解析纯函数、refs 整文档重插、派生索引可重建，与 SiYuan 内核哲学对齐且落在 PG/Ent/Kratos 栈上。**非完全复制**：SiYuan/Logseq 均 AGPL，只借决策不抄代码，License 纪律已立。
2. **4 个阻断性缺口**（B-1~B-4），实施前必须补进三件套，否则 SP1-A~C 阶段卡住或返工。
3. **整体提升判断**：SP1 只解决「知识的形态」，未解决「知识的来源、生命、与人的关系」。本项目区别于一切开源 PKM 的独特资产是 **agent 平台本身**（L0-L4 记忆、团队执行、会话流、审计）——前瞻提案围绕「知识库 × agent 平台合体」展开，属学术已背书、开源无人占位的组合创新带。

## 三、阻断性问题（B-1~B-4，用户裁决：全部合入）

### B-1 跨 Collection 的 `[[doc]]` 解析规则未定义

Obsidian 只在单 vault 内解析；统一索引横跨个人库 + 团队库，`raw_target` 可能多库命中。S3 仅写「最短路径唯一匹配」，跨库歧义优先级、显式跨库语法、可见性过滤（不可见库参与匹配会泄漏文档名）全部未定。

**合入规则**：同 collection 优先 → 可见 collection 内最短路径唯一匹配 → 多义时按（collection 创建序、路径字典序）取首并记 `ambiguous=true`；**不可见 collection 不参与匹配**。显式跨库链接语法后置 SP2 定案。

### B-2 team 库写路径的冲突/审计契约缺位

R-1~R-6 契约（frontmatter 分区/hash 重读/trash 备份/写入审计）全部针对 local 文件。team 库文档本体在 PG，并发控制与审计归属未声明。

**合入声明**：SP1 阶段 team 写入仅经「粘贴文本入库」/agent write（单写者），审计沿用 activities；并发冲突协议（版本/etag）后置 SP2 编辑器定案，SP1 不实现。

### B-3 晋升后目标库派生索引重放未写明

S7 PromoteBlocks 克隆块行，但块不带向量——目标库 chunks/FTS/embedding 何时重建未写。验收 41 隐含「晋升后立即可检索」。

**合入规则**：每个新建目标文档同事务触发整文档重建管线（chunk→embed（有语义层时）→FTS），晋升完成即可检索。

### B-4 Vault 重设计与 SP1 的关系声明缺失

V1 说「文件系统即真相源」是全局转向，SP1-S6 说 team 库 PG 是真相源——并存矛盾。

**合入声明**：「文件即真相源」仅适用 backend=local；SP1 引入 backend 维度后，V 子模块契约按 backend 分别适用（team 库无 frontmatter/trash/SyncEngine 概念）。

## 五、前瞻性提升提案（G1~G8，用户裁决：全部采纳）

> 学术依据详见 `test/pkm-research/A-academic-frontier.md`；此处为产品化裁决摘要。

### G1 ★ 知识-记忆同基底（最大整体提升）

**现状**：知识库（Collection/chunks/links）与记忆中心（L0-L4）两套系统平行。学术趋势（Mem0/Zep/Letta/Collaborative Memory/ESWC'25 双写）全部指向合体：**agent 长期记忆就是一种知识库**。
**提案**：SP1 块模型统一基底后，记忆 L3 事实/L4 实体投影为「agent vault」块（backend=agent 系统库，只读投影不动记忆内核）。收益：一套检索栈、一张图谱、一次治理；**agent 读人写的笔记，人看 agent 学到的东西**。

### G2 ★ 隐性知识写回飞轮（团队 KB 差异化价值）

**依据**：HKMF-LM（企业 70%+ 隐性知识）、Cognee living wiki、llm-wiki（append-only + 归因 + 验证门）。
**提案**：会话/团队执行/会议纪要 → LLM 抽取 → 块 + 三元组写入团队库，带不可变 provenance + 验证门（推测不得当事实归档）。**独有优势**：TeamRun/会话/审计全现成，开源 PKM 结构上做不到——团队库靠工作流自动沉淀而活。

### G3 成熟度光谱替代二元晋升

**依据**：Knowledge Maturing 五阶段、super note 边界对象。
**提案**：US-27 复制式晋升保留为底层机制；其上建模「草稿→共享→精炼→规范」状态机（>3 态，按 AS-FSM-01 显式建模）；AI 辅助「去私人化」综合后再晋升。

### G4 时间维（知识演化而非覆盖）

**依据**：Zep/Graphiti 双时序（LongMemEval +18.5%），与记忆 Phase 6 #01 同源。
**提案**：blocks/refs 增 valid_from/valid_to；「更新」= 新版本 + 旧版本失效；图谱时间轴回放（Obsidian 时间轴过滤器的服务端版）。与记忆双时序共用语义。

### G5 多模态摄取细化（SP4 路线定案）

**现状**：图片 ✅、Office ✅、**视频/音频缺**。
**依据**：Video-RAG 文本代理（+2K token 达 GPT-4o 级）、UniversalRAG 模态分库+路由、AdaVideoRAG 复杂度路由。
**提案**：视频/音频走文本代理（Whisper ASR + 关键帧 OCR + 场景描述，**时间戳回链原片**）；一切模态归一为块；检索侧模态分库 + 轻量路由。

### G6 主动知识伙伴（SP6 重定义）

**依据**：Irec/JITAI 主动唤回、Notemd 自动链接（维护成本是第二大脑弃用主因）、LLM Wiki 编译期综合。
**提案**：① 写入即自动链接/标签建议；② 会话决策点主动唤回（复用 BeforeModel 钩子）；③ 摄入即综合（摘要卡扩展到交叉引用 + 矛盾检测）。

### G7 人的维度（从找文档到找人）

**依据**：CSCW 两代 KM 教训——只做知识仓库必失败。
**提案**：块带作者/agent provenance（审计已有），聚合「谁懂什么」专家视图；团队检索可降级为「找懂的人」。成本极低，差异化极高。

### G8 知识健康度治理

孤儿率、链接密度、dangling 复活率、新鲜度、检索金标准回归（对齐 V6 S-5）——给「系统能力提升」可度量证据链。
