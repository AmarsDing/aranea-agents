## 背景

ORG-FAST 已落地：组织剪枝、花名册绑人、Brief/Bulk、配方回放（新开 Team、不复活旧行）。后续澄清：

1. 精灵不是全行业拆解专家，只能做粗路由。
2. 每家公司应有**总经理**；公司之间总经理传话，公司内部门领导传话。
3. 向上：员工 → 部门领导 → 总经理 → 精灵。
4. 这套链服务于**重型长任务**，会跑很久。
5. 同类班底可复用，但必须**新开一团**，不得在已结束的 Team 上续跑。

若把该四层做成每条消息的串行 LLM 会，长任务会被汇报拖死，并与已落地的「主管不当业务 Lead / 热路径不二次分解」冲突。

## 复审（两轮）

| 风险 | 若不处理 | 决议 |
|------|----------|------|
| 轻任务也走四层 | 改一句文案也开总经理会 | **分档**：轻/中走现网；仅重型启用完整链 |
| 等汇报再派工 | 兄弟部门空等 | **预授权剧本**：无依赖并行开工；有依赖只等 Brief |
| 每步上行 | inbox 风暴 | **例外即时 + 阶段心跳**；过程文件不上行 |
| 总经理当派工人 | 又成第二 Planner | 总经理授权剧本/对外 Brief/冲突仲裁；**不点员工、不拆原话** |
| 部门领导当信息中枢灌全文 | 上下文爆、泄密 | 横向只传 Brief/Bulk；监管仍走 memberfs |
| 跨公司无边界 | 越权读对方工作区 | 公司级 Brief 声明字段 + 机密级；无 2+ 公司节点则该通道休眠 |
| 复用旧 Team 行 | 交付物/inbox/DAG 污染 | 维持 R8：新 `AssembleTeam` |
| 复用班底但约束变了 | 做错活 | 配方带**约束指纹**；对不上则只复用槽位或 `force_new` |
| 长任务中断 | 从精灵重新开会 | checkpoint 记剧本 ID、已授权阶段、已发 Brief（对齐 M70） |
| 两公司总经理循环吵架 | 死锁 | 公司争议 → 精灵呈用户，禁止互怼循环 |
| 单公司 workspace | 「公司间传话」无对象 | 默认一棵公司树；跨公司实施列为 P3，契约先写死 |

## 决策

采用 **分档组织链（ORG-HEAVY）**，叠加在 ORG-FAST 上，不推翻 PlanExecutor：

1. **轻 / 中 / 重** 三档。重型才启用总经理与上行汇报。
2. **公司流程剧本** = 隐形的、可预授权的「公司怎么干活」。总经理对剧本一次签字，不是每单开会。
3. **三管道**：上行（例外/阶段摘要）、横向（部门领导 Brief；跨公司总经理 Brief）、下行（授权/放行）。
4. **对人说话**仍是精灵；组织链不替代用户会话。
5. **班底复用** = 配方槽位 + keys → 新 Team；同会话同目标未结束仍 `reuse_existing`。

**拒绝**：每步员工产出都传到精灵；无剧本时每单让总经理自由拆解用户原话；复活 completed Team。

## 后果

- 重型任务有编制语义（总经理/部门领导/员工），调度仍可并行。
- M67 需增 `company_lead`（对称 `dept_lead`），本期设计、Phase 4 实施。
- 跨公司通道与「任务内不检索/不创建公司」不矛盾：有第二棵公司节点才启用，创建仍走管理面。
- 与 US-78-12 兼容：轻/中仍是协议 + 精灵汇总；重型增加组织横向/上行，精灵仍对人汇总。
