 记忆管家(Memory-Agent)
 memory: 想法：做一个内置的agent专注于管理记忆，独立线程随系统一起启动，后天可以配置开启和关闭，功能：实时监控历史对话，异步压缩与存储，管理memoryL0-L4层记忆，形成一个统一的神经记忆系统。神经记忆系统的理解：每个memory块语意完整，相互关联，当某个记忆块改动，自动复盘相关联记忆块是否需要更新，形成知识图谱，例如：一个人，住在北京工作，其相关的时间，地点，交通，天气等的记忆都与这个地点相关联，此时这个人来到了纽约工作，那时间，地点，交通，天气等等的与之相关联的记忆会跟随工作地点的变动而发生更动。为解决上述问题，想通过后台agent对用户的聊天信息进行深度的整合，不会发生因为工作地点变动，导致AI还是回复错误的交通方式和路径。

二、Manage-Agent（总管）
2.1 定位
Manage-Agent 是任务级协调器，后台运行，可配置开启和关闭，不执行具体原子操作。核心目标：准确理解用户意图、规划最优执行路径、动态组建最佳 Agent 团队。

2.2 意图理解与澄清
2.2.1 核心流程

初步解析：接收用户输入，结合 Memory-Agent 提供的用户画像和历史上下文，识别可能的意图方向。

歧义检测：评估当前输入的歧义程度——如存在多种可能的意图解释、关键参数缺失、约束不明确等情况，则进入澄清流程。

澄清决策：参考 MAC（Multi-Agent Clarification）框架的策略——由 Manage-Agent 自主判断“何时打断用户”以及“如何构造最优澄清问题”，目标是前置性一次获取所有必要信息，减少平均对话轮次。

澄清输出：生成精准的澄清问题，向用户确认理解或请求缺失信息。澄清问题设计遵循：

区分性：问题应能有效区分候选意图

前置批量：一次提问尽可能覆盖所有缺失槽位，避免多轮反复

上下文感知：利用 Memory-Agent 和历史对话减少不必要的提问

意图确认（Intent Preview） ：对于复杂或高风险任务，在执行前向用户展示理解摘要和执行计划预览，获得确认后再启动。

2.2.2 澄清策略配置项

配置项	默认值	说明
clarification_mode	adaptive	always（总是先澄清）/ adaptive（仅在歧义高于阈值时）/ minimal（尽可能不打扰）

2.4 团队组建（最优 Agent 群）
2.4.1 支持的 Agent 类型

基于 trpc-agent-go 框架提供的 Agent 类型，Manage-Agent 根据任务特征自动选择最合适的类型进行编排：

Agent 类型	适用场景	编排时的选择依据
LLMAgent法学文学硕士	通用对话、文本生成、单步决策	任务可用单个 LLM 调用完成时优先使用
GraphAgent图代理	复杂多步骤工作流、有状态路由、条件分支	任务有明确的状态图、需要类型安全的状态管理和可预测路由时选用
ChainAgent链特工	链式顺序执行	子任务间有严格先后依赖
ParallelAgent平行代理	独立子任务并行处理	多个子任务相互独立，可同时执行以提升效率
CycleAgent	需要迭代优化、循环收敛	任务需要反复执行直到满足终止条件（如搜索+优化循环）

2.4.2 组建策略

遍历任务 DAG，对每个子任务匹配可执行的 Agent（查询 Agent 注册表，匹配能力标签）。

根据子任务间的依赖关系，决定 Agent 的组织形式：

顺序依赖 → ChainAgent

无依赖并行 → ParallelAgent

复杂分支/条件 → GraphAgent

迭代收敛 → CycleAgent

对于无合适 Agent 的子任务，向 Skill-Agent 请求生成新技能或向 Tools-Agent 查询可用工具后创建临时 LLMAgent。

组建结果：一个 Team（trpc-agent-go Team 概念），包含选定的 Agent 集合及其协调策略。

组建完成后，为 Team 指定模型（使用各 Agent 配置中已预设的模型，无需额外选择）【用户确认】。

2.5 执行监督与自适应
将 Team 提交 Runner 执行，同时监听执行事件。

异常处理：

单个子任务失败 → 分析原因，决定重试 / 替换 Agent / 降级方案

工具不可用 → 通知 Tools-Agent，重新规划受影响路径

整体超时 → 返回部分结果并说明

无法完成时 → 向用户报告进度并请求指引

失败案例用于优化规划策略
