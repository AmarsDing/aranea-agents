## TD-2026-05-27-01 — Ent Generator 与 tablewriter 版本冲突

**状态**：Open  
**优先级**：High  
**关联范围**：PGO-3 `DefaultRefineLLM`、`internal/data/system_setting_patch.go`

### 背景

当前执行：

```bash
go generate ./internal/data/ent/...
```

会在 `entgo.io/ent@v0.14.5/cmd/internal/printer` 编译阶段失败，原因是 Ent generator 依赖旧版 `github.com/olekukonko/tablewriter` API（如 `SetHeader` / `SetAutoFormatHeaders`），而项目已使用新版 tablewriter。

### 影响

- `internal/data/ent/schema/system_setting.go` 暂不能作为唯一 schema 真相源新增字段。
- PGO-3 的 `refine_llm_*` 字段目前通过 `internal/data/system_setting_patch.go` 运行时补列。
- 对应读写逻辑使用 raw SQL：
  - `systemSettingRepo.GetRefineLLM`
  - `systemSettingRepo.UpdateRefineLLM`
  - `systemSettingRepo.Get` 中的 redacted overlay

### 临时约束

在该债务未偿还前，新增 `system_settings` 字段时必须：

1. 在 `system_setting_patch.go` 添加补列逻辑。
2. 在 data repo 中使用 raw SQL 读写新增列。
3. 避免在未重新生成 Ent 代码的情况下引用 Ent generated struct 字段。

### 偿还计划

1. 中期：升级 Ent 到兼容 tablewriter v1.x 的版本，或锁定 tablewriter 到 Ent generator 兼容版本。
2. 恢复 `go generate ./internal/data/ent/...`。
3. 将 `refine_llm_*` 写回 Ent schema，重新生成 Ent 代码。
4. 移除相关 raw SQL overlay，仅保留迁移/补列的兼容路径。
