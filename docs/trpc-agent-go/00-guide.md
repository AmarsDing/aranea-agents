# trpc-agent-go 框架对齐工作指导

> 本文档为各模块向 trpc-agent-go 框架对齐的统一指导，所有模块对比文档必须遵循此规范。

---

## 一、工作目标

基于 [框架对比分析报告](../reports/2026-06-16-review-framework-vs-implementation.md)，逐模块评估项目实现与框架架构的差异，制定对齐方案，使项目在保持业务能力的前提下最大化利用框架能力，减少自建代码维护负担。

### 核心原则

1. **框架优先**：框架已提供的功能，优先使用框架实现，不自建替代
2. **接口合规**：自建实现必须实现框架接口，确保可替换性
3. **示例驱动**：对齐时必须参考 `pkg/trpc-agent-go/examples/` 中对应的示例代码，以示例代码为标准用法进行对齐（详见下方「示例代码参考要求」）
4. **渐进对齐**：按优先级分批对齐，不中断现有业务
5. **收益量化**：每个对齐项必须量化预期收益（代码减少量/性能提升/维护成本降低）

### 示例代码参考要求

框架示例代码位于 `pkg/trpc-agent-go/examples/`，是对框架 API 标准用法的权威参考。在对齐工作中必须遵循以下要求：

1. **必读示例**：每个模块对齐前，必须先阅读并理解框架 examples 中对应示例的完整代码
2. **以示例为标准**：当项目实现与示例代码的用法不一致时，以示例代码的用法为准进行对齐
3. **示例覆盖映射**：每个模块文档必须在附录 A 中列出所有相关示例，并标注每个示例展示的关键 API 和使用模式
4. **对齐验证**：对齐后的代码应与示例代码的初始化模式、Option 配置方式、接口调用方式一致

### 优先级说明

- **P1（立即对齐）**：对齐度极低，框架功能完全未使用或完全自建，对齐收益最大
- **P2（下个迭代）**：对齐度中等，有自建扩展但框架接口已合规，需评估自建必要性
- **P3（按需对齐）**：对齐度较高，仅需小幅调整或添加缺失功能
- **P4（保持现状）**：对齐度极高，仅需记录当前状态，无需改动

## 四、对齐项类型定义

| 类型 | 定义 | 示例 |
|------|------|------|
| **启用框架功能** | 框架已提供但项目未使用的功能 | 启用 ToolPipe Extension、启用 Auto Memory 模式 |
| **替换自建实现** | 项目自建了框架已提供的功能，用框架实现替换 | 用框架 Team 替换自建 TeamRunner |
| **新增适配层** | 项目需要将自建功能适配到框架接口 | EventBridge 适配框架事件到 EventBus |
| **贡献回框架** | 项目自建的功能框架缺失，应贡献回框架 | EventBus、Callback Chain、Agent Build Cache |

## 六、工作流程

### 6.1 单模块对齐流程

```
1. 阅读框架示例代码 → 理解框架标准用法（必读！以示例为对齐标准）
2. 阅读框架文档和源码 → 填写「框架能力全景」
3. 阅读项目实现代码 → 填写「项目实现现状」
4. 对比分析（项目实现 vs 框架示例 vs 框架源码）→ 填写「对比分析」
5. 制定对齐方案（以示例代码用法为目标状态）→ 填写「对齐方案」
6. 评审对齐方案 → 项目组评审
7. 实施对齐 → 按 Phase 执行
8. 验证对齐 → 对齐后代码与示例代码用法一致性检查 + 测试 + 回归
```

### 6.2 评审检查清单

每个模块文档完成后，需通过以下检查：

- [ ] 框架示例代码是否已阅读并理解（附录 A 必须列出所有相关示例）
- [ ] 框架能力全景是否完整（接口/类型/扩展点/配置/内置实现）
- [ ] 项目实现现状是否准确（合规性标注有代码依据）
- [ ] 自建功能清单是否完整（无遗漏）
- [ ] 未使用框架功能是否逐一分析原因
- [ ] 对比分析是否客观（框架优势和项目优势均列出）
- [ ] 差异根因是否深入（不只是"历史遗留"，要分析具体原因）
- [ ] 对齐方案是否以示例代码用法为目标状态（初始化/Option/调用方式一致）
- [ ] 对齐项是否可执行（有明确的代码变更范围和验证方法）
- [ ] 收益是否量化（有具体的数字预估）
- [ ] 风险是否有缓解措施
- [ ] 实施路线是否有阶段划分

### 6.3 依赖关系

部分模块的对齐存在依赖关系，需按顺序执行：

```
Event 对齐 → Session 对齐 → Memory 对齐
                          ↓
Team 对齐 → Agent 对齐 → Runner 对齐
              ↓
         Tool 对齐 → Callback 对齐
              ↓
         Skill 对齐 → Knowledge 对齐
```

**说明**：
- Event 对齐是 Session/Memory 对齐的前置（EventBus 与 Session/Memory 交互）
- Team 对齐依赖 Agent 对齐（Team 使用 Agent 接口）
- Knowledge 对齐依赖 Skill 对齐（Knowledge Search 作为 Skill Tool）
