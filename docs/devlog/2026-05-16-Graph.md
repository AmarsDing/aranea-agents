## 阶段一：P0 基础能力

### 1. Graph 事件桥接到 EventBus/WS

**问题**：ExecuteGraph 中 eventCh 事件被消费后丢弃，前端无法感知节点执行状态。

**方案**：新建 EventBridge，将 trpc-agent-go 的 event.Event 转换为项目 event.Envelope，通过 EventBus 发布到 WS graph channel。

**新增文件**：
- `internal/graph/trpc/event_bridge.go`：事件桥接器，支持 9 种 ObjectType → EnvelopeType 映射

**修改文件**：
- `internal/event/envelope.go`：新增 4 种 Graph 事件类型，更新 RouteChannel
- `internal/biz/graph.go`：集成 EventBridge（consumeEvents），新增 eventBus 字段

### 2. Checkpoint 查询 API

**问题**：缺少 ListCheckpoints/GetStateSnapshot/EditState 端点。

**方案**：在 Proto 中新增三个 RPC，Biz/Service 层实现。

**修改文件**：
- `api/kratos/graph/v1/graph.proto`：新增 CheckpointInfo/StateSnapshot/EditState 消息和 RPC
- `internal/biz/graph.go`：新增 ListCheckpoints/GetStateSnapshot/EditState 方法
- `internal/service/graph.go`：实现三个新 RPC 方法

### 3. DOT 可视化增强

**问题**：VisualizeGraph 仅返回原始 DOT 字符串，前端无法直接渲染。

**方案**：解析 DOT 输出为结构化 JSON（nodes/edges），支持 Vue Flow 渲染。

**新增文件**：
- `internal/graph/trpc/visualize.go`：ParseDOTToVisualGraph + NodeTypeStyle 样式映射

**修改文件**：
- `api/kratos/graph/v1/graph.proto`：VisualizeGraphResponse 新增 nodes/edges 字段
- `internal/service/graph.go`：VisualizeGraph 返回结构化 JSON

### 4. 前端事件流

**修改文件**：
- `web/src/features/chat/envelope.ts`：新增 4 种 Graph 事件类型
- `web/src/features/chat/useEnvelopeStream.ts`：新增 useGraphStream composable

### 5. Wire 注入

**修改文件**：
- `cmd/admin/wire_gen.go`：GraphUsecase 构造函数注入 EventBus

## 阶段二：P0/P1 四维架构实现

### 6. 设计时校验引擎（P0）

**问题**：Graph 定义在执行前无法验证正确性，拓扑错误、Agent 引用缺失、State Schema 不匹配等问题只能在运行时暴露。

**方案**：新建 validator.go，实现五维度设计时校验。

**新增文件**：
- `internal/graph/trpc/validator.go`：设计时校验引擎

**校验维度**：

| 维度 | 校验内容 | 错误码 |
|------|----------|--------|
| 拓扑校验 | 空图、入口点缺失、节点不可达、孤立节点、重复节点、边目标缺失 | `empty_graph`/`no_entry_point`/`unreachable_node`/`orphan_node`/`duplicate_node`/`edge_target_missing` |
| 节点引用 | FuncRef/CondFuncRef 是否在 Registry 注册 | `func_ref_not_found`/`cond_func_not_found` |
| Agent 引用 | Agent 类型节点的 AgentName 是否存在 | `agent_not_found` |
| State Schema | Reducer 与类型匹配性（Append→切片、Merge→map） | `reducer_type_mismatch` |
| 循环出口 | 检测无退出条件的循环 | `loop_no_exit` |

**核心接口**：
```go
type AgentExistenceChecker func(agentName string) bool
func ValidateGraph(def *GraphBuildConfig, agentChecker AgentExistenceChecker, reg *Registry) *ValidationResult
```

### 7. 设计模式模板（P1）

**问题**：用户从零设计 Graph 门槛高，缺乏常见工作流模式的参考和快速创建能力。

**方案**：新建 templates.go，定义 6 种内置设计模式模板。

**新增文件**：
- `internal/graph/trpc/templates.go`：6 种内置模板 + 转换逻辑

**内置模板**：

| 模板 ID | 名称 | 拓扑 | 适用场景 |
|---------|------|------|----------|
| `pipeline` | 顺序流水线 | 4 节点线性链 | 数据处理管线、报告生成 |
| `approval` | 审批流 | 提交→审批→通过/驳回→结果 | 需人工确认的业务流程 |
| `parallel_review` | 并行评审 | 分发→3 并行评审→汇总 | 多人并行评审 |
| `review_loop` | 生成-评审循环 | 生成→评审→路由→最终/回环 | 迭代优化、质量把关 |
| `dispatch` | 条件分发 | 分类→路由→3 分支→完成 | 分类处理、多通道分发 |
| `nested_subgraph` | 子图嵌套 | 预处理→Agent 子工作流→后处理 | 复用通用流程片段 |
