# Skill: 移动端开发最佳实践

## 概述
移动端应用开发的系统化实践规范，覆盖架构模式、性能优化、离线优先、安全、跨平台策略与发布管理。目标是构建高性能、安全可靠、用户体验优秀的移动端应用。

## 核心规则

### 1. 架构模式
- MVVM 适合大多数场景：View 绑定 ViewModel，ViewModel 持有状态和业务逻辑，Model 提供数据
- MVI 适合复杂状态管理：单向数据流（Intent → Model → View），状态不可变，便于调试和测试
- VIPER 适合大型模块化项目：View/Interactor/Presenter/Entity/Router 职责严格分离，模块边界清晰
- 单向数据流原则：状态变更必须经过唯一通道（ViewModel/MVI 的 Reducer），禁止多处直接修改状态
- 依赖注入：使用 DI 框架（Hilt/Koin/Swinject）管理依赖，构造函数注入优先，禁止在 ViewModel 中 new 依赖
- 模块化分层：App → Feature → Domain → Data，跨层依赖方向与 Clean Architecture 一致
- 导航集中管理：路由表统一注册，Deep Link 通过路由表分发，禁止硬编码页面跳转
- 生命周期感知：ViewModel/UseCase 不持有 View 引用，通过响应式流（Flow/Combine/RxSwift）通信

### 2. 性能优化
- 启动优化：冷启动 ≤ 2s，延迟初始化非首屏依赖，使用启动任务框架并行初始化
- 内存管理：图片加载使用缓存池（Glide/Coil/Kingfisher），及时释放大对象引用，监听内存警告主动释放
- 列表流畅度：RecyclerView/UICollectionView 必须复用 ViewHolder，diff 更新使用 DiffUtil，禁止整体 notifyDataSetChanged
- 网络优化：请求合并（批量接口）、数据压缩（Protobuf/FlatBuffers）、缓存策略（ETag/Last-Modified）、预加载
- 布局优化：减少嵌套层级（≤ 4 层），使用 ConstraintLayout/AutoLayout 替代多层嵌套，避免过度绘制
- 线程模型：IO 操作走独立线程池，CPU 密集任务走计算线程池，UI 操作只在主线程
- 包体积：资源压缩（WebP 替代 PNG）、动态加载（按需下载模块）、代码混淆和 Tree Shaking
- ANR/卡顿监控：主线程耗时 > 500ms 自动上报，帧率 < 55fps 触发告警

### 3. 离线优先
- 本地缓存策略：网络数据优先写入本地数据库，UI 从本地数据库读取，网络结果异步更新数据库
- 数据同步：增量同步优于全量同步，使用时间戳或版本号标识变更，后台定期拉取 + 推送触发即时同步
- 冲突解决：服务端权威优先（Last Write Wins with Server Timestamp），本地修改标记为待同步，冲突时提示用户
- 渐进增强：核心功能离线可用（浏览、查看历史），增强功能需网络（支付、实时协作）
- 网络状态感知：监听网络变化，离线时切换到本地数据源，恢复时自动同步待提交操作
- 队列化写操作：离线时的写操作进入持久化队列，恢复网络后按序提交，支持重试和去重
- 缓存失效：设置合理的 TTL，关键数据支持手动刷新，缓存版本号与数据模型版本绑定
- 存储选型：结构化数据用 SQLite/Realm，键值对用 SharedPreferences/UserDefaults，大文件用文件系统

### 4. 安全
- 证书锁定（Certificate Pinning）：生产环境必须启用，防止中间人攻击，内置备份指纹应对证书轮换
- 安全存储：敏感数据（Token/密钥/密码）使用 Keychain/Keystore 硬件级加密存储，禁止 SharedPreferences/UserDefaults 明文存储
- 越狱/Root 检测：启动时检测运行环境，检测到越狱/Root 后限制敏感功能或拒绝运行
- 数据加密：传输层 TLS 1.3，本地加密使用 AES-256-GCM，密钥派生使用 PBKDF2/Argon2
- 代码混淆：ProGuard/R8 混淆 + 字符串加密，增加逆向难度
- 日志安全：生产环境禁止输出敏感信息（Token/密码/个人信息），日志级别可远程配置
- 屏幕截图防护：敏感页面（支付/证件）禁止截屏和录屏，后台返回时模糊处理
- 深度链接验证：Deep Link 必须校验来源和参数合法性，防止恶意跳转和参数注入

### 5. 跨平台策略
- 共享逻辑层：业务逻辑（网络请求、数据转换、状态管理）抽取到共享模块（KMM/Flutter Dart 层），UI 层各端原生实现
- 平台适配：UI 组件遵循各平台设计规范（Material/iOS HIG），不强制统一视觉风格
- 性能边界：动画/手势/相机等高性能场景使用原生实现，跨平台层只处理逻辑
- 原生桥接：Platform Channel/FFI 调用必须异步，桥接层做类型安全转换，禁止传递大对象
- 选型决策：内容展示型应用优先 Flutter/React Native，工具/系统型应用优先原生，混合型优先 KMM + 原生 UI
- 渐进式迁移：新模块使用跨平台方案，老模块保持原生，通过路由统一跳转
- 测试策略：共享逻辑层单元测试覆盖率 ≥ 80%，UI 层各端独立集成测试
- 构建产物管理：跨平台产物版本与原生项目版本绑定，避免版本不一致

### 6. 发布管理
- 版本号策略：语义化版本（Major.Minor.Patch），Build Number 递增，Hotfix 递增 Patch 版本
- 热修复：关键崩溃通过热修复框架（Tinker/Kiwi/Rollout）紧急修复，热修复仅用于阻断性问题
- 灰度发布：内测 → 1% → 5% → 20% → 50% → 全量，每阶段监控崩溃率和关键指标
- 应用商店审核：提前了解各商店审核规则，避免违规内容，预留审核周期（iOS 1-3 天）
- 回滚能力：发布后崩溃率 > 基线 2 倍立即回滚，回滚方案在发布前验证
- 发布清单：每次发布必须包含版本号、变更内容、已知问题、回滚方案、监控看板
- A/B 测试：新功能通过 A/B 测试验证效果，样本量满足统计显著性后再全量
- 多渠道管理：各渠道包使用统一构建流水线，渠道差异通过配置注入

## 反模式（禁止）

- 主线程 IO：数据库/文件/网络操作在主线程执行，导致 ANR/卡顿
- 无限列表无复用：长列表不使用 ViewHolder 复用机制，滚动卡顿和内存溢出
- 硬编码 UI 尺寸：像素值写死，不同屏幕密度和尺寸下布局错乱
- 明文存储密钥：Token/密码存储在 SharedPreferences/UserDefaults 或代码中硬编码
- 同步网络请求：在主线程同步等待网络响应，阻塞 UI 线程
- 全量刷新列表：数据变更时整体刷新而非增量更新，导致闪烁和滚动位置丢失
- 忽略生命周期：异步回调直接操作 UI，页面销毁后仍更新导致崩溃
- 无降级的网络依赖：离线时应用完全不可用，用户无法查看任何已有数据
