## 战术设计要素

### 聚合根（Aggregate Root）
1. 聚合根是事务一致性边界，跨聚合只能最终一致
2. 聚合根必须通过 ID 引用其他聚合，禁止持有对方实体引用
3. 聚合内所有变更必须经过聚合根，外部不能直接修改内部实体
4. 聚合粒度宜小不宜大，单个聚合操作应在 100ms 内完成

### 值对象（Value Object）
5. 值对象不可变，相等性基于属性值而非标识
6. 优先使用值对象替代原始类型（String/Int），提升领域表达力
7. 值对象序列化需考虑向后兼容

### 领域事件（Domain Event）
8. 事件命名使用过去时态（OrderCreated / PaymentSucceeded）
9. 事件必须包含发生时间 + 聚合 ID + 事件版本号
10. 跨聚合通信必须通过领域事件，禁止同步调用

### 仓储（Repository）
11. 仓储接口定义在领域层，实现在基础设施层
12. 仓储只服务于聚合根，非聚合根实体无独立仓储
13. 仓储方法不超过 5 个，超出则按职责拆分子接口

### 领域服务（Domain Service）
14. 不自然属于任何实体或值对象的领域逻辑放入领域服务
15. 领域服务无状态，仅通过方法参数获取上下文
