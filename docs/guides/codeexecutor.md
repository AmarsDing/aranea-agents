# CodeExecutor Guide

> Sprint 6 — T41 | M-8

The CodeExecutor module provides sandboxed execution of model-generated code. It supports two backends: a `local` subprocess executor for development and a `docker` backend for production isolation with resource limits.

---

## Architecture

```
trpc_build.go
   └── codeexecutor.Executor (interface)
           ├── LocalExecutor   (direct subprocess, no isolation)
           └── DockerExecutor  (one-shot container, resource limits)
                    └── artifact dir → Artifact service (T34)
```

## Configuration

In `agent.codeexecutor.kind`:

| Value | Backend | Notes |
|-------|---------|-------|
| `local` | `LocalExecutor` | Default. Runs code in the host process environment. |
| `docker` | `DockerExecutor` | Requires Docker on the host. |

### Docker Config Fields

```go
DockerConfig{
    Image:          "python:3.11-slim",
    Network:        "none",           // no internet access
    CPUQuota:       50000,            // 50% of one core
    MemoryBytes:    256 * 1024 * 1024,// 256 MiB
    TmpSize:        "128m",
    PullPolicy:     "missing",
    WorkspaceMount: "",               // optional read-only host path → /data
}
```

## Docker Execution Flow

1. Write the model-generated code to a temporary file.
2. Create an output directory for artifacts.
3. Start a one-shot container (`--rm`) with:
   - Code file bind-mounted read-only at `/workspace/main.<ext>`.
   - Output dir bind-mounted writable at `/workspace/out`.
   - Optional host workspace mounted read-only at `/data`.
   - `--read-only` root filesystem with `/tmp` as `tmpfs`.
   - Network set to `none` (no internet access).
   - Memory hard limit + CPU quota.
4. Capture stdout, stderr, and the contents of `/workspace/out`.
5. Remove container automatically (`--rm`).

---

## Result

```go
type Result struct {
    Stdout      string
    Stderr      string
    ExitCode    int
    TimedOut    bool    // context.DeadlineExceeded
    OOM         bool    // exit code 137 (SIGKILL by OOM killer)
    ArtifactDir string  // path to /workspace/out contents on host
}
```

Files in `ArtifactDir` should be uploaded to the Artifact service (T34) by the caller.

## Security

| Control | Implementation |
|---------|---------------|
| No network | `--network none` |
| Read-only root | `--read-only` |
| Memory cap | `--memory` + `--memory-swap` (equal → disable swap) |
| CPU cap | `--cpus=0.5` |
| Ephemeral | `--rm` — container removed after run |
| Timeout | `context.WithTimeout` + `--stop-timeout` |

---

## Fallback

If Docker is unavailable, the application layer should fall back to `LocalExecutor` and emit an alert. Future: `kind=firecracker` or `kind=nsjail` for lighter VMs (S7+ candidate).

---

## Acceptance Criteria

- Python script generated by model → docker container executes → stdout + `/workspace/out` artifacts returned.
- Timeout exceeded → `Result.TimedOut=true`; `codeexec_runs_total{status="timeout"}` increments.
- Memory exceeded → `Result.OOM=true`; `codeexec_oom_total` increments.
