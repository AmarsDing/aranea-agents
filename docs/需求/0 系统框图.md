### 2.3 Team 编排模式关系

```
Team 定义 (TeamDefinition)
    │
    ├── mode: coordinator
    │       └── coordinator Agent → 成员作为 AgentTool 调用
    │           └── MemberToolConfig: StreamInner / InnerTextMode / HistoryScope
    │
    ├── mode: swarm
    │       └── entry Agent → transfer_to_agent 自由转移
    │           └── SwarmConfig: MaxHandoffs / NodeTimeout / RepetitiveHandoff
    │           └── CrossRequestTransfer: 跨请求上下文转移
    │           └── SwarmHandoffInputBuilder: 自定义转移输入
    │
    ├── mode: sequential
    │       └── chainagent → 按顺序执行，上一个输出进入下一个
    │
    ├── mode: parallel
    │       └── parallelagent → 并行执行，synthesizer 汇总
    │
    └── mode: critic_loop
            └── cycleagent → 生成+评审迭代，达到阈值或最大轮数
                └── CriticLoopConfig: MaxIterations / ScoreThreshold
```

### 2.4 Graph 工作流执行引擎

```
Graph 定义 (StateGraph)
    │
    ├── State Schema (StateFieldDef[])
    │       └── 字段名 / 类型 / Reducer(default|append|merge|cover|message)
    │
    ├── Nodes (NodeDef[])
    │       ├── function 节点 → Go 函数
    │       ├── llm 节点 → LLM 调用
    │       ├── tool 节点 → 工具调用
    │       ├── agent 节点 → 子 Agent
    │       ├── router 节点 → 条件路由
    │       └── join 节点 → 并行汇聚
    │
    ├── Edges (EdgeDef[] + ConditionalEdgeDef[])
    │       ├── 固定边: from → to
    │       └── 条件边: from → condition_expr → path_map{branch: target}
    │
    ├── HITL (人机中断)
    │       ├── interrupt_before → 暂停等待人工确认
    │       └── interrupt_after  → 执行后等待确认
    │
    ├── Checkpoint (检查点)
    │       └── 每步执行后保存状态快照
    │
    ├── Time Travel (时间旅行)
    │       └── 回溯到任意检查点重新执行
    │
    └── Subgraph (子图)
            └── 嵌套 Graph，input_mapper / output_mapper 映射
```

```

    │
```

### 3.4 Team 编排数据流

```
用户消息 → Team.Run()
    │
    ├── mode: coordinator
    │       │
    │       ▼
    │   Coordinator Agent 接收消息
    │       │
    │       ▼
    │   Coordinator 决策 → 调用成员 Agent (AgentTool)
    │       │                    │
    │       │                    ▼
    │       │               成员 Agent 执行 → 返回结果
    │       │                    │
    │       ▼                    ▼
    │   Coordinator 汇总 → 返回最终响应
    │
    ├── mode: swarm
    │       │
    │       ▼
    │   Entry Agent 接收消息
    │       │
    │       ▼
    │   Agent 执行 → transfer_to_agent(目标Agent)
    │       │              │
    │       │              ▼
    │       │          目标 Agent 接收上下文 → 继续执行
    │       │              │
    │       │              ▼
    │       │          可能再次 transfer 或返回最终结果
    │       │
    │       ▼
    │   SwarmConfig 安全限制: MaxHandoffs / NodeTimeout / RepetitiveHandoff
    │
    ├── mode: sequential
    │       │
    │       ▼
    │   Agent_1(input) → Agent_2(output_1) → ... → Agent_N(output_N-1) → 最终结果
    │
    ├── mode: parallel
    │       │
    │       ▼
    │   ┌── Agent_1(input) ──┐
    │   ├── Agent_2(input) ──┤──▶ Synthesizer Agent → 最终结果
    │   └── Agent_3(input) ──┘
    │
    └── mode: critic_loop
            │
            ▼
        Generator Agent → Critic Agent → 评分
            │                              │
            │         评分 < 阈值 && 轮数 < 上限
            │                              │
            └──────────────────────────────┘
                          │
                    评分 >= 阈值 或 轮数 >= 上限
                          │
                          ▼
                      最终结果
```

### 3.5 事件系统数据流

```
Agent/Team/Graph 运行
    │
    ▼
产生 Event (trpc-agent-go event.Event)
    │
    ├── text         → 文本增量
    ├── tool_call    → 工具调用开始
    ├── tool_result  → 工具返回结果
    ├── state_delta  → 状态增量 (set/append/delete)
    ├── transfer     → Agent 转移控制权
    ├── done         → 运行完成
    └── error        → 错误事件
    │
    ▼
事件元数据增强
    ├── Branch       → 分支追踪 (agent_a/agent_b)
    ├── FilterKey    → 层级过滤
    ├── Tag          → 业务标签 (code_execution;transfer)
    ├── Extensions   → 扩展元数据
    ├── Actions      → 流控制 (skip_summarization)
    └── StateDelta   → 状态变更
    │
    ▼
事件分发
    ├── Session 持久化 → sessionmemory.Store
    ├── SSE 推流 → 前端实时渲染
    ├── Monitor 日志 → MonitorLogBroker
    ├── Token 用量 → ModelTokenUsageEvent
    └── Callback 触发 → CallbackRegistry.Fire
```

## 六、Gateway 网关与运行控制流

```
┌──────────────────────────────────────────────────────────────────┐
│                      Gateway 网关层                               │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  并发控制     │    │  运行状态     │    │  运行取消     │       │
│  │  activeRuns  │    │  RunStatus   │    │  CancelRun   │       │
│  │  (sync.Map)  │    │  (查询API)   │    │  (中断执行)   │       │
│  └──────┬───────┘    └──────┬───────┘    └──────┬───────┘       │
│         │                   │                   │                 │
│  ┌──────┴───────┐    ┌──────┴───────┐    ┌──────┴───────┐       │
│  │  消息排队     │    │  人工回复路由 │    │  Webhook     │       │
│  │  pendingQueue│    │  AwaitUser   │    │  回调通知     │       │
│  │  (sync.Map)  │    │  ReplyRoute  │    │  (HTTP POST) │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**运行控制流程**：

```
1. 用户发送消息 → ChatService 检查并发 → activeRuns 注册 → Runner.Run()
2. 运行中查询状态 → RunStatus API → 返回 running/event_count/last_event_at
3. 需要人工确认 → HITL 中断 → AwaitUserReply → 前端展示确认按钮
4. 用户确认/取消 → EnqueueUserMessage → Runner 恢复执行
5. 用户主动取消 → CancelRun API → Runner.Cancel() → 清理资源
6. 运行完成 → activeRuns 注销 → Webhook 回调通知 → Token 用量记录
```

## 十一、架构约束与红线

AI 在实现任何模块时，必须遵守以下架构约束（详见 `docs/guides/AI-DEVELOPMENT-SPECIFICATION.md`）：

1. **依赖方向铁律**：`api → service → biz → data`，跨层只允许向内依赖
2. **Biz 层禁止 import `pkg/trpc-agent-go`**：框架运行时仅在 `internal/agent`、`internal/team`、`internal/tools`、`internal/provider` 中使用
3. **Service 层是框架调用的唯一桥点**：不在 `internal/server` 或 `internal/biz` 中直接使用框架运行时
4. **TurnMount 是工具装配的唯一入口**：新工具类型必须通过 `TurnMount.Attach` 挂载
5. **Proto 是唯一对外契约**：禁止一半在 proto、一半手写路由
6. **SQLite 通过 Ent ORM 访问**：禁止在 `NewData` 外另开 `sql.Open`
7. **事件流经 Broker 分发**：禁止模块间通过全局变量共享状态
8. **Wire 依赖注入**：禁止手动编写 `wire_gen.go`
