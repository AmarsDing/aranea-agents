# 学习闭环

## 一、需求文档

### 1.1 背景

当前项目的进化系统（`internal/cronrunner/jobs/evolution_scanner.go`）仅实现了"扫描建议"的半环：`EvolutionScanner` 定期扫描 Agent 指标，当工具成功率或检索质量低于阈值时创建 `EvolutionSuggestion`，但缺少从经验中学习的完整闭环。Hermes Agent 的 Learning Loop 提供了完整范式：Observation → Pattern Extraction → Skill Proposal → Validation → Registration，Agent 能自动识别重复模式并提取为可复用知识。

框架层 `pkg/trpc-agent-go/memory/extractor/` 已提供 LLM 驱动的自动记忆提取能力（`MemoryExtractor` 接口），支持从对话中提取事实（fact）和情节（episode），并具备 Checker 机制控制提取触发条件。当前项目已有 `internal/cronrunner/jobs/auto_memory.go` 实现自动记忆提取定时任务，但提取结果仅存储为记忆条目，未形成"观察→模式识别→知识提议→验证→注册"的完整闭环。

### 1.2 目标

1. 建立从经验中学习的完整闭环，让 Agent 自动识别重复模式并提取为可复用知识
2. 将现有 `EvolutionScanner` 的"扫描建议"升级为"学习闭环"，增加模式提取和知识注册环节
3. 复用框架 `MemoryExtractor` 的提取能力，在其输出基础上增加模式识别层
4. 支持人工审批环节，确保自动提取的知识质量可控

### 1.3 功能需求

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F1 | 经验观察收集器 | P0 | 从会话事件中收集 Agent 行为数据（工具调用结果、用户反馈、检索命中），构建 Observation 数据结构 |
| F2 | 重复模式检测器 | P0 | 基于记忆条目和工具调用统计，识别高频重复模式（如同一工具被反复以相似参数调用） |
| F3 | 知识提议生成器 | P0 | 调用 LLM 对识别出的模式生成结构化知识提议（KnowledgeProposal），包含模式描述、适用场景、建议行动 |
| F4 | 提议验证器 | P1 | 对生成的知识提议进行自动化验证：去重检查、与现有知识冲突检测、最小数据量阈值 |
| F5 | 知识注册器 | P0 | 将验证通过的知识提议注册到记忆系统或技能系统，支持自动注册和人工审批两种模式 |
| F6 | 闭环编排器 | P0 | 编排 Observation → Pattern → Proposal → Validation → Registration 的完整流程 |
| F7 | 学习闭环定时任务 | P1 | 在 `internal/cronrunner/jobs/` 新增 `learning_loop.go`，定期触发学习闭环 |
| F8 | 前端闭环可视化 | P2 | 在 Agent 详情页展示学习闭环状态：已识别模式数、待审批提议、已注册知识 |

### 1.4 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF1 | 性能 | 模式检测在 1000 条记忆条目内完成时间 < 5s |
| NF2 | 可靠性 | 闭环流程任何环节失败不影响其他环节，采用异步 + 重试 |
| NF3 | 安全性 | 自动注册模式必须经过人工审批（EvoAutoApply=false 时），防止低质量知识污染 |
| NF4 | 可观测性 | 每次闭环执行产出结构化日志（经 `internal/event` FlowLog），记录各阶段耗时和结果 |

### 1.5 验收标准

1. Agent 在 30 天内积累 ≥10 次相似工具调用模式后，系统能自动生成知识提议
2. 知识提议经人工审批后，自动注册为记忆条目或 Skill 提示
3. 注册后的知识在后续会话中被 Agent 实际引用（检索命中率提升）
4. 闭环各阶段有完整的日志记录和指标统计

#### Hermes Learning Loop 参考

Hermes 的学习闭环流程：Observation → Pattern Extraction → Skill Proposal → Validation → Registration。核心概念：
- **Observation**：从 Agent 运行时收集的行为数据
- **Pattern Extraction**：LLM 驱动的模式识别
- **Skill Proposal**：基于模式生成可操作的知识提议
- **Validation**：自动化 + 人工审批
- **Registration**：注册到记忆或技能系统

#### 数据流图

```
会话事件 (tool_call / feedback / memory_hit)
    │
    ▼
Observation 收集器 (cronrunner / callback)
    │  写入 learning_observations 表
    ▼
模式检测器 (LearningLoopUsecase.DetectPatterns)
    │  读取 observations + memory entries
    │  LLM 辅助模式识别
    │  写入 learning_patterns 表
    ▼
知识提议生成器 (LearningLoopUsecase.GenerateProposals)
    │  读取 patterns
    │  LLM 生成结构化提议
    │  写入 learning_proposals 表
    ▼
提议验证器 (LearningLoopUsecase.ValidateProposal)
    │  去重检查 + 冲突检测 + 最小数据量
    │  更新 proposal status → validated
    ▼
知识注册器 (LearningLoopUsecase.RegisterKnowledge)
    │  EvoAutoApply=true → 自动注册
    │  EvoAutoApply=false → 等待人工审批
    │  注册到 memory.Service 或 Skill 系统
    ▼
闭环完成 → FlowLog 记录
```

### 2.4 与框架的集成方式

1. **记忆提取复用**：模式检测阶段复用 `MemoryExtractor.Extract()` 从对话历史中提取结构化信息，在其 `Operation` 输出基础上进行模式聚合
2. **Checker 机制复用**：闭环触发条件使用 `CheckMessageThreshold` + `CheckTimeInterval` 组合，控制闭环执行频率
3. **事件发射**：闭环各阶段通过 `agent.EmitEvent(ctx, inv, ch, evt)` 发射学习事件，供前端实时展示
4. **程序化 Agent**：闭环编排器实现 `agent.Agent` 接口（5 方法），通过 `Runner.Run()` 调用，确保 Session/Invocation 生命周期由 Runner 管理
5. **工具构建**：闭环中的 LLM 调用使用 `function.NewFunctionTool[I, O]` 构建工具
6. **异步写入**：知识注册经 broker/async 异步写，符合红线 #8

### 2.5 错误处理

| 场景 | 处理方式 |
|------|----------|
| 模式检测 LLM 调用失败 | 记录 FlowLog Warn，跳过本次检测，下次重试 |
| 提议生成 LLM 调用失败 | 同上，不阻塞其他模式 |
| 知识注册冲突 | 与现有知识冲突时标记 proposal 为 `conflict`，等待人工决策 |
| 数据库写入失败 | 返回 `kerrors.InternalServer`，cronrunner 下次重试 |
| 人工审批超时 | `EvoProposalTTLDays` 到期后自动标记为 `expired` |
