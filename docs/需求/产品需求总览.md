# 产品与技术需求总览

本文档收敛原 **`总体设计文档.md`** 中的产品定位与记忆体系目标，以及 **`设计需求.md`** 中 **LLM Gateway 建设的第一部分（提炼）**。**目标态架构、限界上下文、迁移 Runbook、LLM Gateway（第二篇凝练）与 Kratos+tRPC-Agent-Go 编排速查** 均以 **[`../design/platform-architecture.md`](../design/platform-architecture.md)**（**第一篇～第三篇**）为准；运行时 API 仍以 **`pkg/trpc-agent-go`** 为框架真相源。

---

## 1. 产品定位

**多智能体任务编排平台**：用户通过可视化界面组装 LLM、工具、子 Agent，形成可运行工作流；会话内多轮协作、可观测、可配置记忆与提供商。

**不作平台内建实现的能力（经端口外挂）**：模型推理、向量检索引擎、对象存储、IM 协议等（与 **`platform-architecture.md` 第三篇** §1 一致）。

---

## 2. 技术栈（当前约束）

| 层级 | 选型 |
|------|------|
| 后端 | Go（Kratos 服务编排见 `docs/guides/`；Agent 运行时以 **`pkg/trpc-agent-go`** 为框架真相源） |
| 前端 | Vue 3 + Quasar |
| 主库 | SQLite（向量/图可按阶段外挂 pgvector、专用图库） |

## 3. 五层记忆体系（需求级定义）

设计原则：**越往下容量越大、访问越慢、持久性越强；越往上越快、时效性越强。** 每层详细接口、数据表与验收见 **`12 memory-L0`**～**`16 memory-L4`** 系列文档。

### 3.1 各层摘要

| 层级 | 名称 | 需求定义（摘要） |
|------|------|------------------|
| **L0** | 瞬时 / 感知 | LLM 上下文内即时信息：当前轮次、最近 N 条消息、工具结果；FIFO/压缩；不单独做 SQL 内容仓，由装配层编排（见 `12`） |
| **L1** | 工作 / 核心 | 当前任务结构化快照（目标、约束、子任务、决策）；小容量、显式读写 API/工具；任务结束归档到 L2（见 `13`） |
| **L2** | 会话 / 事件 | 本会话全量交互痕迹：消息、工具、决策、错误；Runner/事件表为主；可检索、可检查点；为 L3 巩固提供 episode（见 `14`） |
| **L3** | 语义 / 知识 | 跨会话事实：偏好、规范、领域片段；向量 + 元数据；版本、反馈、冲突与衰减（见 `15`） |
| **L4** | 持久 / 进化 | 图谱化经验、因果与行为策略；巩固 Job、遗忘与冲突仲裁；可影响 Agent 配置与提示（见 `16`） |

### 3.2 与 tRPC-Agent-Go 的映射（目标态）

| 层级 | 实现映射（需求期望，非替代专题文档） |
|------|----------------------------------------|
| L0 | `Session` 状态 + 上下文压缩/装配；与 `12` 中 `MemoryL0Service` 一致化 |
| L1 | 结构化 `session.State` / 专用 L1 存储；工具化读写 |
| L2 | Runner 事件、Session History、`Artifact` 大对象 |
| L3 | `memory.Service` 语义检索；可接外部向量库 |
| L4 | 图与巩固 Job；与 Evolution 档案联动 |

### 3.3 跨层协调（需求）

| 机制 | 触发 | 期望行为 |
|------|------|----------|
| L0→L2 | 每轮结束 | 消息与工具调用进入会话史 / 事件视图 |
| L2→L3 | 会话结束 / 高价值标记 / 阈值 | 抽取事实、去重、写入 L3 |
| L3→L4 | 定时或积累阈值 | 抽象模式、更新图与策略候选 |
| L3→L1 | 新任务开始 | 按任务描述检索并注入工作记忆 |
| L4→L1 | 复杂任务 | 图遍历/因果链摘要注入（可选） |
| 用户反馈 | 显式确认/反驳 | 调整 L3 置信度等 |
| 冲突 | 多版本事实 | 仲裁或待用户确认 |

### 3.4 多 Agent 共享记忆（Global Memory Bus）— 需求要点

- 共享语义空间：多 Agent 可读写的记忆总线，**细粒度权限**（读/写/管）。
- **A2A**：Agent 能力与记忆上下文的发现与传递（与 `pkg/trpc-agent-go` A2A 适配协同）。
- 事件驱动同步：订阅记忆变更，减少轮询。
- **隔离与联邦**：Agent 私有 vs 项目/组织共享；乐观锁或版本机制处理并发写冲突。

## 4. 记忆系统质量指标（目标值）

| 指标 | 说明 | 目标（需求） |
|------|------|--------------|
| 检索准确率 | L3 Recall@k | > 90% |
| 检索延迟 | L3 P99 | < 200 ms |
| 巩固效率 | L2→L3 吞吐 | > 1000 条/min |
| 存储效率 | 去重率 | > 85% |
| 推理增益 | L4 注入对复杂任务完成率 | > 15%（需 A/B 定义口径） |
| 上下文利用率 | L1 有效信息占比 | > 80% |

---

## 5. MVP 分阶段记忆建设

| Phase | 范围 |
|-------|------|
| **Phase 1** | L0 + L1 + L2：单 Agent 会话记忆闭环，优先 tRPC-Agent-Go 原生能力 |
| **Phase 2** | L3：向量检索、L2→L3 管道、L3→L1 注入、用户反馈驱动强化/衰减 |
| **Phase 3** | L4 + Global Bus：图谱、巩固 Job、L4→L1、多 Agent 隔离/联邦、A2A 记忆传递 |
| **Phase 4** | 自适应重组、冲突自动仲裁与治理策略 |

## 6. LLM Gateway（建设需求·提炼）

> **Gateway 设计凝练与设计要领**（路由/降级/负载均衡等）见 **[`../design/platform-architecture.md`](../design/platform-architecture.md) 第二篇**。  
> **当前仓库对内模型管控**已实现路径见 **`9 provider.md`**（Kratos + 控制台）；本节描述若建设**独立网关层**时应满足的需求。

### 6.1 要解决的业务问题

| 痛点 | 建设要求 |
|------|----------|
| 多模型/厂商、格式不一 | 统一对外协议 + 内部标准请求/响应 |
| 运维分散 | 密钥、路由、配额集中；调用方只面对 Gateway |
| 容错分散 | 重试、降级、熔断统一策略 |
| 成本与性能黑盒 | 路由（能力/成本/延迟）+ 指标与成本统计 |

**建设目标**：统一管控、智能路由、容错兜底、成本与可观测可优化。

### 6.2 三层职责

| 层级 | 职责 |
|------|------|
| 接入层 | 协议归一、鉴权、限流与配额 |
| 决策层 | 路由引擎、健康与延迟、负载均衡；**可动态配置** |
| 出口层 | 厂商适配、SSE、响应归一、日志与指标 |

### 6.3 路由与容错（需求摘要）

- 路由能力 / 成本（级联小→大）/ 延迟 / 语义（后期）组合使用，分期落地。
- 降级：同模型重试（指数退避）→ 跨厂商 → 跨等级 → 兜底；熔断阈值**宽于**通用 RPC。
- 负载均衡：动态加权、按 token 量、跨区域与负载折中。

### 6.4 可观测与缓存

- 语义缓存：注意时效与个性化场景；可配置 TTL。
- 日志/指标/追踪：请求 ID、路由决策、降级路径、token、成本。

### 6.5 落地路线（可执行）

1. MVP：统一 API、简单路由、鉴权、限流、基础日志指标  
2. 可用性：分级重试 + 降级链 + 熔断  
3. 成本：级联 + 可选语义缓存  
4. 规模化：延迟感知、按 token 均衡、全链路追踪与成本看板
