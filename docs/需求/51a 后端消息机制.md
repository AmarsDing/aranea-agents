# 51a 后端消息机制 — 通信与事件体系设计

> 本文档设计 Aranea-Agents 后端的通信消息机制。核心决策：**WebSocket 统一传输**。前端消息机制见 [51b 前端消息机制](./51b%20前端消息机制.md)。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| 统一事件模型 | 所有通信（Chat/Team/Graph/Channel/Cron/A2A/Monitor）共享同一套事件定义与流转规则 |
| 框架对齐 | 事件模型以 trpc-agent-go `event.Event` 为真相源，项目层只做投影与扩展 |
| 分层清晰 | 事件产生在运行时层、路由在 Biz 层、传输在 Server 层，各层职责不越界 |
| 双向通信 | WebSocket 原生支持上行（cancel/enqueue/steer/subscribe），无需额外 HTTP 端点 |
| 通道复用 | 一个 WebSocket 连接承载所有事件类型（chat/monitor/team/graph/system），多路复用 |
| 可扩展 | 新场景（Graph 节点事件、A2A 消息、Artifact 通知）无需修改核心机制 |
| 可靠性 | 背压控制、心跳检测、事件缓冲与重放、自动重连 |
| 传输无关 | 同一 Envelope 可投射到 WebSocket / Webhook，传输层可替换 |

---

## 二、设计原则

```
原则 1：trpc-agent-go event.Event 是事件真相源，项目层不重新定义事件语义
原则 2：事件投影（Event → Envelope）是唯一需要项目层实现的逻辑
原则 3：事件路由由统一 EventBus 承担，Service 层不直接管理订阅
原则 4：传输协议（WS）与事件模型解耦，同一事件可投射到多种传输
原则 5：WebSocket 是唯一传输，上行消息走 WS
原则 6：一个 WS 连接通过 Channel 多路复用所有事件类型
原则 7：客户端通过 subscribe/unsubscribe 动态控制订阅范围
```

## 三、现状复盘与问题

### 3.1 现有通信路径

```
前端 POST /v1/chat/messages/stream
  → ChatService.ProxyStream()
    → proxyNativeStream()          ← 解析 body、写 SSE header
      → runNativeAgentTurn()

          → RunTRPCUserTurn()      ← runner.Run() → <-chan *event.Event
          → 事件循环（trpc_turn.go）← 逐事件投影为 SSE
            → stream.Emit("delta", ...)     ← 文本增量
            → stream.Emit("tool.call", ...) ← 工具调用
            → stream.Emit("state_delta", ...) ← 状态增量
            → stream.Emit("done", ...)      ← 完成
```

### 3.2 现有事件 Broker

| Broker | 位置 | 用途 | 问题 |
|--------|------|------|------|
| `TeamRunEventBroker` | `internal/biz/team_run_events.go` | Team 运行事件推流 | 仅支持 Team 维度过滤，无 Session/FilterKey 过滤 |
| `MonitorLogBroker` | `internal/biz/` | 运维日志推流 | 独立体系，与 Agent 事件无关，需单独连接 |
| `streamWriter` | `internal/service/chat_native.go` | Chat 流写入 | 无背压、无重放、事件投影逻辑散落在 Service 层 |

### 3.3 核心问题

| # | 问题 | 影响 |
|---|------|------|
| 1 | **事件投影逻辑散落在 Service 层** | `trpc_turn.go` 中 200+ 行事件循环，混合了事件解析、传输写入、消息落库、用量记录 |
| 2 | **事件类型不统一** | Chat 用 `delta/done/tool.call`，Team 用 `TeamRunEvent.Type`，Monitor 用 `log` |
| 3 | **无统一事件总线** | 各 Broker 独立实现，无法跨场景路由 |
| 4 | **无事件持久化与重放** | 断连后无法恢复，前端刷新丢失中间状态 |
| 5 | **无双向通信** | 用户中断、SteerableRunner.EnqueueUserMessage 无法通过现有连接上行 |
| 6 | **背压缺失** | 慢客户端导致 channel 满后事件被丢弃 |
| 7 | **Monitor 日志与 Agent 事件割裂** | 运维日志走独立端口（:8001），与 Agent 事件无法统一订阅和过滤 |
| 8 | **连接浪费** | Chat + Monitor + Team 需要多个独立连接 |

## 五、统一信封模型（Envelope）

### 5.1 设计思路

trpc-agent-go 的 `event.Event` 是运行时内部结构，包含 `*model.Response`、`StateDelta`、`Extensions` 等框架细节。直接暴露给传输层会：

1. 违反分层原则（传输层不应依赖框架内部类型）
2. 导致前端需要理解 trpc 框架的事件语义
3. 无法在不修改框架的情况下扩展业务字段

因此设计 **Envelope（信封）** 作为项目层统一的事件传输单元：

- **Envelope 是 event.Event 的投影**，不是替代
- **Envelope 包含完整元数据**，前端可独立消费
- **Envelope 是 JSON 友好的**，所有字段可直接序列化
- **一个 trpc Event 投影为一个 Envelope**，不再拆分为多个传输事件
- **Envelope 同时服务于 WS**，传输层只负责编码方式

### 5.3 事件类型映射

| Envelope type | trpc model.ObjectType | 说明 | WS channel |
|---------------|----------------------|------|-----------|
| `text_delta` | `chat.completion.chunk` (IsPartial) | 文本增量 | chat |
| `text_done` | `chat.completion.chunk` (!IsPartial, Done) | 文本完成 | chat |
| `tool_call` | `chat.completion.chunk` (ToolCalls) | 工具调用开始 | chat |
| `tool_result` | `tool.response` | 工具返回结果 | chat |
| `state_delta` | `state.update` | 状态增量 | chat |
| `transfer` | `agent.transfer` | Agent 转移 | chat / team |
| `runner_completion` | `runner.completion` | 运行完成 | chat |
| `error` | `error` | 错误 | chat |
| `log` | — | 运维日志 | monitor |
| `graph_node_start` | `graph.node.start` | Graph 节点开始 | graph |
| `graph_node_end` | `graph.node.end` | Graph 节点结束 | graph |
| `checkpoint` | `checkpoint.*` | 检查点事件 | graph |
| `intent_pass` | — | 意图识别结果 | chat |
| `member_message_start` | — | Team 成员消息开始 | team |
| `member_delta` | — | Team 成员增量 | team |
| `member_message_done` | — | Team 成员消息完成 | team |

**关键设计决策**：同一 Envelope 类型可路由到不同 Channel（如 `transfer` 在单 Agent 场景走 `chat`，在 Team 场景走 `team`），由 EventBus 根据 Session 类型自动路由。

### 5.4 Channel 自动路由

```go
func routeChannel(env Envelope) string {
    switch env.Type {
    case "log":
        return "monitor"
    case "member_message_start", "member_delta", "member_message_done":
        return "team"
    case "graph_node_start", "graph_node_end", "checkpoint":
        return "graph"
    default:
        if env.TeamID != "" {
            return "team"
        }
        return "chat"
    }
}
```

### 5.5 向后兼容映射

| 旧事件名 | 新 Envelope type | 迁移策略 |
|---------|------------------|---------|
| `delta` | `text_delta` | 前端改为监听 Envelope，按 `type` 分发 |
| `done` | `text_done` + `runner_completion` | `done` 拆分为两个语义明确的事件 |
| `tool.call` | `tool_call` | 名称统一 |
| `user_message` | 保留为独立上行消息 | 用户消息回显不走 Envelope |
| `error` | `error` | 结构增强，保留 `message` 字段 |
| `state_delta` | `state_delta` | 从独立事件变为 Envelope type |
| `intent_pass` | `intent_pass` | 从独立事件变为 Envelope type |

## 六、EventBus 统一事件总线

### 6.1 设计思路

现有 `TeamRunEventBroker` 和 `MonitorLogBroker` 是各自独立的 pub/sub 实现。EventBus 统一所有事件路由：

1. **单一发布入口**：所有事件通过 `EventBus.Publish()` 发布
2. **多订阅者路由**：按 session_id / team_id / channel / filter_key 路由到不同传输
3. **内部消费**：状态持久化、用量记录、回调触发等作为内部订阅者
4. **背压控制**：慢订阅者不阻塞快订阅者
5. **Channel 路由**：Envelope 根据 type 和 session 类型自动分配到对应 channel

### 6.2 EventBus 接口

```go
// internal/biz/event_bus.go

type EventBus interface {
    Publish(ctx context.Context, envelope Envelope)
    Subscribe(opts SubscribeOptions) (<-chan Envelope, func())
}

type SubscribeOptions struct {
    SessionID   string
    TeamID      string
    Channel     string   // "chat" | "monitor" | "team" | "graph" | "system"
    FilterKey   string
    EventTypes  []string
    LevelFilter string   // Monitor 日志级别过滤："ERROR|WARN"
    BufferSize  int
}

type Envelope struct {
    ID                 string
    Type               string
    Author             string
    SessionID          string
    TeamID             string
    RequestID          string
    InvocationID       string
    ParentInvocationID string
    Branch             string
    FilterKey          string
    Tag                string
    Timestamp          string
    Version            int
    Channel            string   // 路由目标 channel

    Content     *EnvelopeContent
    ToolCall    *EnvelopeToolCall
    StateDelta  *EnvelopeStateDelta
    Transfer    *EnvelopeTransfer
    Error       *EnvelopeError
    Usage       *EnvelopeUsage
    Extensions  map[string]string
    Actions     *EnvelopeActions
    Trace       *EnvelopeTrace
    Metadata    map[string]any
}
```

### 6.3 EventBus 实现

```go
// internal/biz/event_bus.go

type eventBus struct {
    mu          sync.RWMutex
    subscribers map[uint64]*subscriber
    nextID      uint64
}

type subscriber struct {
    ch    chan Envelope
    opts  SubscribeOptions
}

func NewEventBus() EventBus {
    return &eventBus{
        subscribers: make(map[uint64]*subscriber),
    }
}

func (b *eventBus) Publish(ctx context.Context, env Envelope) {
    if env.Channel == "" {
        env.Channel = routeChannel(env)
    }
    b.mu.RLock()
    defer b.mu.RUnlock()
    for _, sub := range b.subscribers {
        if !b.matchSubscriber(sub.opts, env) {
            continue
        }
        select {
        case sub.ch <- env:
        default:
            select {
            case <-sub.ch:
                sub.ch <- env
            default:
            }
        }
    }
}

func (b *eventBus) Subscribe(opts SubscribeOptions) (<-chan Envelope, func()) {
    bufSize := opts.BufferSize
    if bufSize <= 0 {
        bufSize = 128
    }
    ch := make(chan Envelope, bufSize)
    id := atomic.AddUint64(&b.nextID, 1)
    b.mu.Lock()
    b.subscribers[id] = &subscriber{ch: ch, opts: opts}
    b.mu.Unlock()
    unsubscribe := func() {
        b.mu.Lock()
        delete(b.subscribers, id)
        b.mu.Unlock()
    }
    return ch, unsubscribe
}

func (b *eventBus) matchSubscriber(opts SubscribeOptions, env Envelope) bool {
    if opts.SessionID != "" && opts.SessionID != env.SessionID {
        return false
    }
    if opts.TeamID != "" && opts.TeamID != env.TeamID {
        return false
    }
    if opts.Channel != "" && opts.Channel != env.Channel {
        return false
    }
    if opts.FilterKey != "" && !matchFilterKey(opts.FilterKey, env.FilterKey) {
        return false
    }
    if len(opts.EventTypes) > 0 {
        found := false
        for _, t := range opts.EventTypes {
            if t == env.Type {
                found = true
                break
            }
        }
        if !found {
            return false
        }
    }
    if opts.LevelFilter != "" && env.Type == "log" {
        level, _ := env.Metadata["level"].(string)
        if !matchLevelFilter(opts.LevelFilter, level) {
            return false
        }
    }
    return true
}
```

### 6.4 FilterKey 匹配规则

对齐 trpc-agent-go `event.Event.Filter()` 的前缀匹配语义：

```go
func matchFilterKey(subscriberKey, eventKey string) bool {
    if subscriberKey == "" || eventKey == "" {
        return true
    }
    subscriberKey += "/"
    eventKey += "/"
    return strings.HasPrefix(subscriberKey, eventKey) ||
           strings.HasPrefix(eventKey, subscriberKey)
}
```

## 七、EventProjector 事件投影器

### 7.1 设计思路

EventProjector 是 trpc `event.Event` 到项目层 `Envelope` 的唯一转换点。它承担：

1. **类型映射**：trpc ObjectType → Envelope type
2. **内容提取**：从 `model.Response.Choices` 提取文本/推理/工具调用
3. **副作用触发**：StateDelta 持久化、Usage 记录、ToolCall 记录
4. **消息落库**：将用户/助手消息写入 Session

### 7.2 EventProjector 接口

```go
// internal/agent/event_projector.go

type EventProjector struct {
    stateApplier  SessionStateApplier
    usageRecorder UsageRecorder
    toolRecorder  ToolCallRecorder
    messageStore  MessageStore
    eventBus      EventBus
}

type ProjectMeta struct {
    SessionID          string
    RequestID          string
    InvocationID       string
    ParentInvocationID string
    TeamID             string
    Branch             string
    FilterKey          string
}

type ProjectResult struct {
    Envelope    Envelope
    SideEffects []SideEffect
}

type SideEffect struct {
    Type string // "state_persist" | "usage_record" | "tool_record" | "message_append"
    Data any
}

func (p *EventProjector) Project(ctx context.Context, ev *event.Event, meta ProjectMeta) *ProjectResult {
    env := p.buildEnvelope(ev, meta)
    p.triggerSideEffects(ctx, ev, env, meta)
    return &ProjectResult{Envelope: env}
}

func (p *EventProjector) ProjectAndPublish(ctx context.Context, ev *event.Event, meta ProjectMeta) {
    result := p.Project(ctx, ev, meta)
    p.eventBus.Publish(ctx, result.Envelope)
}
```

### 7.3 buildEnvelope 核心逻辑

```go
func (p *EventProjector) buildEnvelope(ev *event.Event, meta ProjectMeta) Envelope {
    env := Envelope{
        ID:                 ev.ID,
        InvocationID:       ev.InvocationID,
        ParentInvocationID: ev.ParentInvocationID,
        Author:             ev.Author,
        Branch:             ev.Branch,
        FilterKey:          ev.FilterKey,
        Tag:                ev.Tag,
        Timestamp:          ev.Timestamp.Format(time.RFC3339Nano),
        Version:            ev.Version,
        SessionID:          meta.SessionID,
        RequestID:          meta.RequestID,
    }

    if ev.Response == nil {
        env.Type = "state_delta"
        return env
    }

    switch {
    case ev.IsRunnerCompletion():
        env.Type = "runner_completion"
    case ev.IsError():
        env.Type = "error"
        env.Error = &EnvelopeError{
            Type:    ev.Response.Error.Type,
            Message: ev.Response.Error.Message,
        }
    case ev.ContainsTag(event.TransferTag):
        env.Type = "transfer"
    default:
        env.Type = p.inferTypeFromResponse(ev.Response)
    }

    if len(ev.Response.Choices) > 0 {
        choice := ev.Response.Choices[0]
        env.Content = &EnvelopeContent{
            Text:      choice.Message.Content,
            Reasoning: choice.Message.ReasoningContent,
            IsPartial: ev.Response.IsPartial,
        }
        if len(choice.Message.ToolCalls) > 0 || len(choice.Delta.ToolCalls) > 0 {
            tcs := choice.Message.ToolCalls
            if len(tcs) == 0 {
                tcs = choice.Delta.ToolCalls
            }
            if len(tcs) > 0 {
                tc := tcs[0]
                env.ToolCall = &EnvelopeToolCall{
                    ID:            tc.ID,
                    Name:          tc.Function.Name,
                    ArgumentsJSON: tc.Function.Arguments,
                    Status:        "calling",
                }
                env.Type = "tool_call"
            }
        }
    }

    if len(ev.StateDelta) > 0 {
        for key, value := range ev.StateDelta {
            env.StateDelta = &EnvelopeStateDelta{
                Operation: "set",
                Path:      key,
                ValueJSON: string(value),
            }
            break
        }
    }

    if len(ev.Extensions) > 0 {
        env.Extensions = make(map[string]string)
        for k, v := range ev.Extensions {
            env.Extensions[k] = string(v)
        }
    }

    if ev.Actions != nil {
        env.Actions = &EnvelopeActions{
            SkipSummarization: ev.Actions.SkipSummarization,
        }
    }

    if ev.Response.Usage != nil {
        env.Usage = &EnvelopeUsage{
            PromptTokens:     ev.Response.Usage.PromptTokens,
            CompletionTokens: ev.Response.Usage.CompletionTokens,
            TotalTokens:      ev.Response.Usage.PromptTokens + ev.Response.Usage.CompletionTokens,
        }
    }

    if ev.ExecutionTrace != nil {
        env.Trace = &EnvelopeTrace{
            AgentName:    ev.ExecutionTrace.RootAgentName,
            InvocationID: ev.ExecutionTrace.RootInvocationID,
            StepCount:    len(ev.ExecutionTrace.Steps),
        }
    }

    return env
}
```

### 7.4 事件循环重构

重构后的事件循环从 200+ 行简化为：

```go
func runEventLoop(ctx context.Context, events <-chan *event.Event, projector *EventProjector, meta ProjectMeta) {
    for ev := range events {
        projector.ProjectAndPublish(ctx, ev, meta)
    }
}
```

所有副作用（WS 写入、消息落库、用量记录）由 EventBus 的订阅者处理，事件循环本身只做投影+发布。

### 8.2 WebSocket 连接管理

```go
type wsConn struct {
    conn          *websocket.Conn
    sessionID     string
    mu            sync.Mutex
    subscriptions map[string]*subscription
    cancel        context.CancelFunc
    eventCh       <-chan biz.Envelope
    unsub         func()
}

type subscription struct {
    channel string
    filters map[string]string
}

func (s *WSServer) handleWebSocket(w http.ResponseWriter, r *http.Request) {
    token := r.URL.Query().Get("token")
    if token == "" {
        token = r.Header.Get("Authorization")
        token = strings.TrimPrefix(token, "Bearer ")
    }
    if token == "" {
        if cookie, err := r.Cookie("access_token"); err == nil && cookie.Value != "" {
            token = cookie.Value
        }
    }
    sessionID := r.URL.Query().Get("session_id")
    lastEventID := r.URL.Query().Get("last_event_id")

    if !s.authenticate(token, sessionID) {
        http.Error(w, "unauthorized", http.StatusUnauthorized)
        return
    }

    conn, err := s.upgrader.Upgrade(w, r, nil)
    if err != nil {
        return
    }

    ctx, cancel := context.WithCancel(r.Context())
    wc := &wsConn{
        conn:          conn,
        sessionID:     sessionID,
        subscriptions: make(map[string]*subscription),
        cancel:        cancel,
    }

    s.registerConn(wc)
    defer s.unregisterConn(wc)

    s.sendConnected(wc, lastEventID)

    go s.readPump(ctx, wc)
    s.writePump(ctx, wc)
}
```

### 8.3 读泵（上行消息处理）

```go
func (s *WSServer) readPump(ctx context.Context, wc *wsConn) {
    defer wc.cancel()
    wc.conn.SetReadLimit(1 << 20)
    wc.conn.SetReadDeadline(time.Now().Add(60 * time.Second))
    wc.conn.SetPongHandler(func(string) error {
        wc.conn.SetReadDeadline(time.Now().Add(60 * time.Second))
        return nil
    })

    for {
        _, msg, err := wc.conn.ReadMessage()
        if err != nil {
            return
        }
        var up UpstreamMessage
        if json.Unmarshal(msg, &up) != nil {
            continue
        }
        switch up.Type {
        case "user_message":
            s.handleUserMessage(ctx, wc, up)
        case "cancel":
            s.handleCancel(ctx, wc, up)
        case "enqueue_message":
            s.handleEnqueueMessage(ctx, wc, up)
        case "subscribe":
            s.handleSubscribe(ctx, wc, up)
        case "unsubscribe":
            s.handleUnsubscribe(ctx, wc, up)
        case "ping":
            s.sendPong(wc)
        }
    }
}
```

### 8.4 写泵（下行消息推送）

```go
func (s *WSServer) writePump(ctx context.Context, wc *wsConn) {
    ticker := time.NewTicker(30 * time.Second)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            return
        case env, ok := <-wc.eventCh:
            if !ok {
                return
            }
            wc.conn.SetWriteDeadline(time.Now().Add(10 * time.Second))
            msg := DownstreamMessage{
                Direction: "server_to_client",
                Channel:   env.Channel,
                Envelope:  env,
            }
            data, _ := json.Marshal(msg)
            wc.mu.Lock()
            err := wc.conn.WriteMessage(websocket.TextMessage, data)
            wc.mu.Unlock()
            if err != nil {
                return
            }
        case <-ticker.C:
            wc.conn.SetWriteDeadline(time.Now().Add(10 * time.Second))
            if err := wc.conn.WriteMessage(websocket.PingMessage, nil); err != nil {
                return
            }
        }
    }
}
```

### 8.5 动态订阅处理

```go
func (s *WSServer) handleSubscribe(ctx context.Context, wc *wsConn, up UpstreamMessage) {
    payload := up.Payload.(map[string]any)
    channel, _ := payload["channel"].(string)
    if channel == "" {
        return
    }

    filters, _ := payload["filters"].(map[string]any)
    subFilters := make(map[string]string)
    for k, v := range filters {
        subFilters[k] = fmt.Sprintf("%v", v)
    }

    wc.subscriptions[channel] = &subscription{
        channel: channel,
        filters: subFilters,
    }

    s.resubscribeEventBus(ctx, wc)
}

func (s *WSServer) resubscribeEventBus(ctx context.Context, wc *wsConn) {
    if wc.unsub != nil {
        wc.unsub()
    }

    opts := biz.SubscribeOptions{
        SessionID:  wc.sessionID,
        BufferSize: 128,
    }

    ch, unsub := s.eventBus.Subscribe(opts)
    wc.eventCh = ch
    wc.unsub = unsub

    go func() {
        channels := make(map[string]bool)
        for ch := range wc.subscriptions {
            channels[ch] = true
        }
        for env := range ch {
            if !channels[env.Channel] {
                continue
            }
            if sub, ok := wc.subscriptions[env.Channel]; ok {
                if !matchSubFilters(sub.filters, env) {
                    continue
                }
            }
            select {
            case <-ctx.Done():
                return
            default:
            }
        }
    }()
}
```

## 十、Monitor 日志统一接入

### 10.1 现状问题

当前 Monitor 日志走独立端口（`:8001`），与 Agent 事件完全割裂。问题：

1. 独立端口增加运维复杂度（防火墙、负载均衡）
2. 无法与 Agent 事件关联
3. 前端需要维护两个连接
4. 无过滤能力（无法只看 ERROR 级别）

### 10.2 新设计：Monitor 日志作为 Envelope

Monitor 日志统一为 Envelope 格式，通过 WS `channel: monitor` 传输：

```go
func publishTeamMonitor(ctx context.Context, bus event.Bus, level, msg, sessionID string) {
    if bus == nil || strings.TrimSpace(msg) == "" {
        return
    }
    env := NewEnvelope(EnvelopeTypeLog, "team-runner", sessionID)
    env.Metadata = map[string]any{"level": level, "source": "team-runner"}
    env.Content = &EnvelopeContent{Text: msg}
    bus.Publish(ctx, env)
}
```

**关键设计**：`sessionID` 参数必须传入，因为 EventBus 按 `session_id` 路由事件到 WS 客户端。空 `sessionID` 会导致日志事件无法送达任何订阅者。

### 10.3 Monitor 事件来源

| 来源 | metadata.source | 说明 |
|------|----------------|------|
| Runner 生命周期 | `runner` | Agent 启动/完成/错误 |
| Tool 执行 | `tool` | 工具调用开始/结束/错误 |
| LLM 调用 | `llm` | 模型请求/响应/重试 |
| 系统事件 | `system` | 内存/连接/配置变更 |
| 自定义 | `custom` | 业务层注入的日志 |

## 十二、事件持久化与重放

### 12.1 内存缓冲区

```go
// internal/biz/event_buffer.go

type EventBuffer struct {
    mu      sync.RWMutex
    buffers map[string]*ringBuffer
    maxSize int
}

func NewEventBuffer(maxSizePerSession int) *EventBuffer {
    return &EventBuffer{
        buffers: make(map[string]*ringBuffer),
        maxSize: maxSizePerSession,
    }
}

func (b *EventBuffer) Append(sessionID string, env Envelope) {
    b.mu.Lock()
    buf, ok := b.buffers[sessionID]
    if !ok {
        buf = newRingBuffer(b.maxSize)
        b.buffers[sessionID] = buf
    }
    b.mu.Unlock()
    buf.Append(env)
}

func (b *EventBuffer) Replay(sessionID string, afterEventID string) []Envelope {
    b.mu.RLock()
    buf, ok := b.buffers[sessionID]
    b.mu.RUnlock()
    if !ok {
        return nil
    }
    return buf.ReplayAfter(afterEventID)
}
```

### 12.2 WS 重连重放

```
1. 客户端重连时携带 last_event_id
   WS /v1/ws?session_id=sess-uuid&last_event_id=evt-100
2. 服务端从 EventBuffer 查询并重放
3. 先发送 replay_start → 重放事件 → replay_end
4. 重放期间实时事件缓冲，重放完成后发送
```

### 12.3 重放同步屏障

重放与实时事件流之间需要同步，避免事件乱序。实现方式：

```go
type wsConn struct {
    // ...
    replayDone chan struct{}   // 重放完成后关闭
}

func (s *WSServer) handleWS(...) {
    // ...
    if lastEventID != "" && s.eventBuffer != nil {
        wc.replayDone = make(chan struct{})
        go func() {
            defer close(wc.replayDone)
            s.replayEvents(wc, sessionID, lastEventID)
        }()
    }
    go s.eventPump(wc, eventCh)
}

func (s *WSServer) eventPump(wc *wsConn, eventCh <-chan Envelope) {
    if wc.replayDone != nil {
        <-wc.replayDone    // 阻塞直到重放完成
    }
    for env := range eventCh {
        // 正常转发实时事件
    }
}
```

**关键设计**：`eventPump` 在 `replayDone` 通道关闭前阻塞，确保重放事件全部发送完毕后才开始转发实时事件，避免两者交错。

### 13.1 Chat 场景

```
用户消息
  → Runner.Run()
    → LLM 调用 → text_delta × N → text_done
    → Tool 调用 → tool_call → tool_result
    → text_delta × N → text_done
```

### 13.2 Team 场景

```
用户消息
  → Team Runner.Run()
    → Coordinator Agent
      → tool_call: transfer_to_agent(agent_b)
        → Agent B → text_delta × N → text_done
        → transfer back
      → tool_call: transfer_to_agent(agent_c)
        → Agent C → text_delta × N → text_done
    → Coordinator 汇总 → text_done
  → runner_completion
```

**Team 事件投影**：Team Runner 的事件循环同样使用 `EventProjector.ProjectAndPublish()` 将 trpc 事件投影为 Envelope 并发布到 EventBus，与 Chat 场景共享同一套投影逻辑。这确保了 Team 成员的流式消息（text_delta/tool_call 等）通过 EventBus 路由到 WS 客户端，前端 `useTeamStream` 可正常接收。

### 13.4 Channel 场景

| `trpc_turn.go` 事件循环 | `EventProjector` + `EventBus` | 投影逻辑抽取，事件循环简化 |
| 独立 SSE Server（`:8001`） | 删除 | 统一走 WS 传输 |
