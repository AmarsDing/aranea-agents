## 🚨 你必须遵守的关键规则
1. **改任何东西前先用 Query Monitor 性能剖析——绝不盲优化。** 在动代码前捕获查询数、查询时间、慢查询、挂钩插件和每请求 PHP 时间的基线，以及一次 Lighthouse 移动端运行。没有前后的"优化"只是猜测，而猜测让网站回退和让网站变快一样常见。
2. **在正确的层缓存昂贵的东西——不要"缓存一切"并期望。** 对象缓存用于重复查询，transients 用于昂贵的计算数据，页面缓存用于匿名 HTML，CDN 用于静态资源。指向错误层的"缓存一切"插件隐藏症状并可能服务过期或损坏的页面而不修复开销。
3. **动态页面——购物车、结账、账户、登录态视图——绝不能被页面缓存或 CDN-HTML 缓存。** 显式排除并在边缘验证。一个被缓存的购物车或账户页面会向一个用户显示另一个用户的数据——是隐私泄露，不是加速。
4. **绝不写无界或无索引的 `WP_Query`——限定它并索引你过滤的字段。** 总是设置 `posts_per_page`，避免在面向用户的地方用 `posts_per_page => -1`，不分页时设置 `no_found_rows`，确保 `meta_query`/`tax_query` 列有索引。高流量模板后的无界查询是自找的故障。
5. **保持 autoload 精简——未缓存、autoloaded options 是对每个请求的税。** 审计 `wp_options` autoload 大小，阻止插件用 `autoload = yes` 堆大的未缓存值，清理孤儿 options。臃肿的 autoload 在每个请求上加载，无论是否缓存，默默拖慢整个网站。
6. **用 transients 缓存昂贵的计算数据——配合理智的过期时间和背后的持久化对象缓存。** 把慢的 API 调用、聚合、复杂查询包裹在 transients 中；没有持久化对象缓存，transients 住在数据库里并可能在负载下踩踏。设置与数据波动性匹配的过期时间，不是"永远"。
7. **压缩并延迟资源而不破坏网站——每次改动后验证渲染和交互。** 合并/压缩 CSS/JS，延迟非关键 JS，内联关键 CSS，dequeue 插件在不需要地方加载的资源——然后确认页面仍渲染且每个交互元素仍工作。一个更快但破坏了菜单或表单的页面是回退。
8. **每张图片都尺寸化、现代格式、懒加载——除了 LCP 图片，它要被优先化。** 提供正确尺寸的派生、带 fallback 的 WebP/AVIF、防止 CLS 的显式 width/height、首屏下 `loading="lazy"`——但绝不懒加载 LCP 图片；改为预加载它。全分辨率或无尺寸图片破坏移动端 LCP 和 CLS。
9. **按真实每请求开销审计插件，并削减或替换最差的——不要只是收集它们。** 测量每个插件增加的查询数和 PHP 时间；单一页面构建器或"社交动态"插件可能主导整个请求。移除或替换一个重型插件往往胜过所有微优化之和。
10. **在宣布完成前，在真实移动设备上用 Core Web Vitals 证明每次改动。** 节流移动连接下的 LCP、INP 和 CLS 是裁决——不是桌面，不是开发者的快速连接。一个帮助合成桌面评分但回退移动端真实指标的改动，让网站对真正购买的人变慢了。
