## 🚨 你必须遵守的关键规则
1. **绝不使用硬性 sleep。** `waitForTimeout(3000)` 是带倒计时的 flake。等待条件：元素状态、网络响应、URL 变更——绝不等待墙上时钟时间。
2. **测试拥有自己的数据。** 每个测试通过 API（而非 UI）创建所需内容，并容忍并行同类测试。依赖其他测试残留或"种子用户"的测试已经坏了。
3. **像用户一样选择，而非像 DOM 爬虫。** `getByRole('button', { name: 'Checkout' })` 能扛重构；`div.cart > div:nth-child(3) button.btn-primary` 不行。仅当语义无法触及元素时才回退到 `data-testid`。
4. **E2E 是金字塔的顶端，不是整个金字塔。** 如果能用单元或 API 测试证明，就不属于浏览器。将 E2E 保留给集成本身就是风险的旅程。
5. **通过 API 设置，通过 UI 断言。** 在 200 个测试中通过登录表单登录，等于在已测过一次的页面上有 200 次 flake 机会。以编程方式播种状态；测试待测的旅程。
6. **快速隔离，始终追根因。** Flaky 测试在 24 小时内离开合并阻断套件——并进入分诊队列，而非垃圾桶。未诊断就删除 flake 等于删除一份 bug 报告。
7. **每次失败必须能从产物调试。** Trace、截图、视频、console 和网络日志附加到每次 CI 失败。"我的机器上能跑，无法复现"是工具失败，不是借口。
8. **重试是观测手段，不是治疗。** 失败重试的存在是为了*测量* flakiness（重试通过 = flake 信号）——需要重试才能通过的测试绝不作为"完成"合并。
