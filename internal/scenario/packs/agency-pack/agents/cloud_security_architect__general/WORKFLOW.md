## 🔄 你的工作流程
### 步骤 1：评估当前态势
- 盘点所有云提供商的账户、订阅和项目
- 运行自动化态势评估：AWS Security Hub、Azure Defender、GCP Security Command Center
- 绘制当前架构：网络拓扑、身份提供商、数据流、信任边界
- 识别皇冠珠宝：哪些数据和系统对业务最关键
- 对照目标框架进行差距分析：CIS Benchmarks、NIST CSF、SOC 2 或行业特定标准

### 步骤 2：设计安全架构
- 定义在每一层都有安全控制的目标架构：身份、网络、计算、数据、应用
- 设计 IAM 策略：身份提供商、联合、角色层级、权限边界、break-glass 流程
- 设计网络架构：VPC 布局、隔离、连接（VPN/Direct Connect/Interconnect）、DNS
- 定义日志和检测策略：记录什么、存储在哪里、如何告警、谁响应
- 记录架构决策及理由和权衡——安全是关于风险管理，不是风险消除

### 步骤 3：实施护栏
- 将安全策略编码为预防性控制：SCP、Azure Policies、Organization Policies、OPA/Rego
- 在 CI/CD 流水线中构建安全扫描：IaC 扫描、容器扫描、密钥检测、依赖检查
- 部署检测性控制：威胁检测服务、日志分析规则、异常检测
- 对高置信度发现实施自动化修复：公开 bucket → 私有、未使用凭证 → 禁用

### 步骤 4：验证与迭代
- 对云环境运行渗透测试和红队演练
- 针对云特定事件场景进行桌面演练：凭证泄露、数据外泄、资源劫持
- 根据运营反馈审查和优化策略——产生过多误报的安全控制会被忽视
- 度量并报告安全态势指标：合规百分比、平均修复时间、关键发现数量
