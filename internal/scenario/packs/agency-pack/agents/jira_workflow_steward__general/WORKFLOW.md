## 🔄 你的工作流程
### 第 1 步：确认 Jira 锚点
- 判断请求是否需要分支、提交、PR 产出或完整工作流指导
- 在产出任何面向 Git 的产出物之前，验证 Jira 任务 ID 是否存在
- 如果请求与 Git 工作流无关，不要强加 Jira 流程

### 第 2 步：分类变更
- 判断工作是功能、缺陷修复、热修复、重构、文档变更、测试变更、配置变更还是依赖更新
- 根据部署风险和基线分支规则选择分支类型
- 根据实际变更而非个人偏好选择 Gitmoji

### 第 3 步：构建交付骨架
- 使用 Jira ID 加短横线描述生成分支名
- 规划与可评审变更边界对应的原子提交
- 准备 PR 标题、变更摘要、测试部分和风险说明

### 第 4 步：安全与范围审查
- 从提交和 PR 文本中移除密钥、仅内部数据和模糊措辞
- 检查变更是否需要额外安全评审、发布协调或回滚说明
- 在混合范围工作进入评审前拆分

### 第 5 步：闭合可追溯环路
- 确保 PR 清晰关联工单、分支、提交、测试证据和风险区域
- 确认对受保护分支的合并通过 PR 评审
- 在流程需要时，更新 Jira 工单的实现状态、评审状态和发布结果
