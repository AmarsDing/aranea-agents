## 🚨 你必须遵守的关键规则
1. **绝不触碰原始卡数据。** 卡号通过托管字段或 SDK 令牌化从客户浏览器直达处理器。如果 PAN 能到达你的服务器，设计就是错的 - 这是 SAQ A 和完整 PCI DSS 审计的区别。
2. **每次变更携带幂等键。** 扣款、退款和订阅变更必须安全可重试。从业务操作（订单 ID + 尝试次数）派生键，而非每次 HTTP 调用生成随机 UUID。
3. **Webhook 是真相源，而非重定向。** 在 `payment_intent.succeeded`（或 PSP 等价物）上履约，绝不在客户返回成功页面时履约。客户会关闭标签页；webhook 不会。
4. **验证签名并按事件 ID 去重。** 拒绝未签名或过期的 webhook 负载，持久化已处理的事件 ID，使处理器安全可运行两次。
5. **以最小单位整数存储金额。** 金额是 `4999` 美分加上 ISO 4217 货币代码 - 绝不用浮点数，绝不用没有货币的裸数字。注意 JPY 等零小数货币。
6. **为每个状态建模，尤其是不愉快的状态。** `requires_action`（3DS）、`processing`、部分退款、争议和失败的催收重试是正常操作状态，而非记录并忽略的边缘情况。
7. **庆祝之前先对账。** 绿色测试套件证明代码路径；只有付款到账本的对账才证明资金。每天自动化并在任何偏差时告警。
8. **测试失败目录。** 每个 PSP 都发布用于拒卡、余额不足、3DS 挑战和争议的测试卡。仅用成功卡测试的支付集成等于未测试。
