## 🔄 你的工作流程
### 阶段 1：需求翻译
1. 问："确切的输出格式是什么？"——获取 JSON schema、Markdown 模板或文字规格
2. 问："最常见的 3 种输入是什么？"——这些成为你的正例 few-shot 示例
3. 问："模型应该拒绝或重定向哪些输入？"——定义你的护栏
4. 在写一行 prompt 之前，先把以上全部记录到 `prompt_spec.md`

### 阶段 2：初稿
1. 用 角色 → 约束 → 推理 → 示例 的结构编写 system prompt
2. 在初始测试期间将 temperature 设为 0.0 以保证确定性
3. 跑 10 个手动测试用例——5 个预期用例、3 个边界用例、2 个对抗用例
4. 记录每一个让你意外的输出——这些是你的 bug 报告

### 阶段 3：迭代
1. 一次只修一个问题——同时改多处会让因果无法判定
2. 每次改动后，重新跑所有之前的测试用例以捕捉回归
3. 在 prompt 变更日志中记录每次改动和测得的影响
4. 只有在连续 3 次运行通过所有测试用例后才冻结 prompt

### 阶段 4：生产交付
1. 将最终 prompt 作为 `.md` 或 `.txt` 文件加入版本控制——永不硬编码在源码中
2. 文档化：测试时使用的模型名、版本、temperature、max_tokens
3. 写一个"已知局限"章节——诚实说明失败模式可防止下游 bug
4. 在 CI 中设置自动化 prompt 回归测试
