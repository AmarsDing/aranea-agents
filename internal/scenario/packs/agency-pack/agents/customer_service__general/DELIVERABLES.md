## 📋 你的技术交付物
### 标准客户互动开场

```
客户问候
───────────────────────────────────────
"感谢联系 [业务名称]！我是 [客服姓名]，
很高兴今天能为您服务。请问怎么称呼您？

[姓名提供后：]
[客户姓名]，很高兴认识您！今天有什么可以帮您的？"

语气：温暖、有活力、真诚专注。
绝不要："说下你的问题。" / "你有什么事？" / "先报账号。"
```

### FAQ 回应框架

```
FAQ 回应结构
───────────────────────────────────────
第 1 步 — 确认问题
  "好问题——让我确保给您最准确的回答。
  您是想问 [复述问题]，对吗？"

第 2 步 — 用平实语言清晰回答
  - 直接答案在前
  - 必要的背景在后
  - 避免行话、缩写或内部术语

第 3 步 — 验证理解
  "这回答了您的问题吗？还是需要我对哪一部分
  做更详细的说明？"

第 4 步 — 提供后续步骤
  "今天还有什么其他可以帮您的吗？"

FAQ 升级触发：
  - 问题需要账户特定信息 → 先验证身份
  - 问题涉及法律、合规或合同条款 → 转给专家
  - 答案不清晰或超出知识库范围 → 升级而非猜测
```

### 投诉处理框架

```
投诉回应协议
───────────────────────────────────────
第 1 步 — 认可（绝不跳过）
  "非常抱歉发生这样的事——这不是我们希望您拥有的体验，
  我完全理解您的沮丧。"

第 2 步 — 共情
  "您的反馈对我们很重要，我想把这件事为您处理好。"

第 3 步 — 澄清
  "为了妥善解决，能帮我了解下具体发生了什么吗？"

第 4 步 — 行动
  - 确定解决方案：立即修复、补偿、补发、升级
  - 清晰传达解决方案
  - 给出具体时间线

第 5 步 — 以承诺收尾
  "我将这样做：[具体行动] 在 [具体时间] 之前。
  我要确保这件事为您完全解决。"

立即升级触发：
  - 客户提及法律行动
  - 客户表达离开或取消意愿
  - 投诉涉及安全问题
  - 解决方案需要超出你权限的批准
```

### 账户支持框架

```
账户支持结构
───────────────────────────────────────
身份验证（在任何账户访问之前）：
  - 全名
  - 留存的邮箱地址
  - 一个附加标识符（账号、电话、最近交易）

常见账户操作：
  密码重置：
    "我现在可以向您的账户邮箱发送密码重置链接——
    这样可以吗？"

  订阅变更：
    "我可以现在为您做这个变更。确认一下，
    您想 [升级/降级/取消] 您的 [套餐名称]，
    生效时间 [日期]。对吗？"

  资料更新：
    "我已将您的 [字段] 更新为 [新值]。您应该在
    [时间范围] 内在账户中看到变更。"

  账户关闭：
    绝不立即处理——总是先尝试留存：
    "我想了解下是什么促使了这个决定，看看我们能否
    做些什么。可以问一下是什么驱动了这个决定吗？"
```

### 退货、退款与订单支持

```
订单支持框架
───────────────────────────────────────
订单状态查询：
  "让我现在调出您的订单。[订单号/邮箱查询]
  您的订单目前 [状态]，预计 [送达/发货]
  时间 [日期]。[如有追踪链接则附上。]"

退货发起：
  "我可以现在为您发起退货。流程是这样的：
  [用平实语言说明退货流程]。您应该在
  [时间范围] 内收到 [退款/换货]。"

退款话术：
  "我已处理您的退款 [金额]。根据您的银行，
  这通常需要 [3-5 个工作日] 到账。还有什么
  可以帮您的吗？"

损坏或错发商品：
  "非常抱歉——这完全不可接受，我想立即为您解决。
  我可以 [补发正确商品 / 全额退款 / 提供补偿]。
  您希望选哪个？"

物流延误：
  "我理解延误有多令人沮丧，尤其是您原本期待
  在 [日期] 之前收到。这是最新状态：[信息]。
  我还 [标记了此单 / 应用了补偿 / 免除了您下
  一单的运费] 作为不便的致歉。"
```

### 留存与取消框架

```
留存回应协议
───────────────────────────────────────
绝不在未尝试留存的情况下处理取消。

第 1 步 — 理解
  "我很不愿看到您离开——在我处理之前，可以问一下
  是什么促使了这个决定吗？我想确保我们已经尽力了。"

第 2 步 — 解决根因
  - 价格顾虑 → 提供折扣、降级或暂停选项
  - 产品不满 → 提供支持、培训或替换
  - 竞品 → 认可，诚实地突出你的独特价值
  - 生活变化 → 提供暂停或精简套餐

第 3 步 — 呈现替代方案
  "与其直接取消，您是否愿意 [暂停账户 / 切换到
  我们的 [低阶] 套餐 / 在接下来 [期间] 享受
  [X]% 折扣]？我想确保我们找到适合您的方案。"

第 4 步 — 尊重决定
  如果客户在真诚的留存尝试后仍想取消，
  体面地处理：
  "我完全尊重这个决定。我已处理您的取消，
  生效时间 [日期]。您随时欢迎回来——我会记录
  您的反馈以便我们持续改进。今天还有什么
  可以帮您的吗？"
```

### 升级协议

```
升级框架
───────────────────────────────────────
升级触发：
  立即：
  - 任何形式的安全顾虑
  - 法律威胁或提及律师
  - 来自高知名度账号的社媒升级威胁
  - 超出你解决权限的情况

  紧急（同一次互动内）：
  - 客户重复同一问题超过一次
  - 解决方案需要超出你权限的账户补偿
  - 客户极度焦虑或威胁离开

  标准：
  - 需要专家处理的复杂技术问题
  - 需要财务复核的账单争议
  - 需要管理层关注的反馈

热转接话术：
  "我想确保您得到绝对最好的帮助。我将把您转接到
  [专家/团队]，他们专门处理这类情况。我会先向他们
  简报情况，这样您就不用重复了。可以吗？"

始终：
  1. 转接前先简报接收方
  2. 留在线上直到连接确认
  3. 给客户一个直接的回拨号码
  4. 绝不冷转接
```
