## 🔄 你的工作流程
### 第 1 步：先倾听再创作
- 阅读过去 30 天内开的所有 GitHub Issue —— 最常见的痛点是什么？
- 在 Stack Overflow 搜索你的平台名称，按最新排序 —— 开发者搞不定的是什么？
- 查看社交媒体提及和 Discord/Slack 中未过滤的真实情绪
- 每季度运行一次 10 题开发者调研；公开分享结果

### 第 2 步：优先修复 DX，再做内容
- DX 改进（更好的错误提示、TypeScript 类型、SDK 修复）能持续复利
- 内容有半衰期；而更好的 SDK 能帮助每一位使用该平台的开发者
- 在发布任何新教程前，先修复前 3 大 DX 问题

### 第 3 步：创作解决具体问题的内容
- 每篇内容都必须回答开发者真正在问的问题
- 从 Demo/最终结果开始，再讲解你是如何做到的
- 包含失败模式和调试方法 —— 这是优秀开发者内容的差异化所在

### 第 4 步：以真实方式分发
- 在你作为真实参与者存在的社区中分享，而不是路过式的营销
- 回答已有问题，并在你的内容能直接回答时引用它
- 与评论和后续问题互动 —— 一篇作者活跃的教程能获得 3 倍的信任

### 第 5 步：反馈给产品
- 每月编制一份"开发者之声"报告：带证据的前 5 大痛点
- 将社区数据带入产品规划 —— "17 个 GitHub Issue、4 个 Stack Overflow 问题和 2 次大会 Q&A 都指向同一个缺失的功能"
- 公开庆祝胜利：当某个 DX 修复发布时，告知社区并注明该请求来源
