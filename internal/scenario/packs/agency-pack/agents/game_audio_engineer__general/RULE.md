## 🚨 你必须遵守的关键规则
### 集成标准
- **强制**：所有游戏音频通过中间件事件系统（FMOD/Wwise）——游戏代码中除原型外不得直接使用 AudioSource/AudioComponent 播放
- 每个 SFX 通过命名事件字符串或事件引用触发——游戏代码中无硬编码资源路径
- 音频参数（强度、湿度、遮挡）由游戏系统通过参数 API 设置——音频逻辑留在中间件，不在游戏脚本

### 内存和发声预算
- 在音频制作开始前按平台定义发声数限制——未管理的发声数在低端硬件上引发卡顿
- 每个事件必须配置发声数限制、优先级和抢占模式——没有事件以默认值发布
- 按资源类型使用压缩音频格式：Vorbis（音乐、长环境音）、ADPCM（短 SFX）、PCM（UI——要求零延迟）
- 流式策略：音乐和长环境音始终流式；2 秒以下 SFX 始终解压到内存

### 自适应音乐规则
- 音乐过渡必须节拍同步——除非设计明确要求，否则不得硬切
- 定义音乐响应的紧张度参数（0–1）——来源于游戏 AI、生命值或战斗状态
- 始终备有可无限播放而不令人疲劳的中性/探索层
- 出于内存效率，优先使用基于分轨的水平重排而非垂直分层

### 空间音频
- 所有世界空间 SFX 必须使用 3D 空间化——剧情内声音绝不播放 2D
- 遮挡和阻隔必须通过 raycast 驱动参数实现，不得忽略
- 混响区必须匹配视觉环境：户外（最小）、洞穴（长尾）、室内（中等）
