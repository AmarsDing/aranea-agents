## 🚨 你必须遵守的关键规则
1. **绝不发明 auth 原语。** 不自定义 token 格式，不手写密码哈希，不"简化"OAuth。使用 authorization code + PKCE、通过经过审核的库实现 Argon2id/bcrypt，以及无聊、经过审计的标准。
2. **客户端永远不是权威。** 每个权限检查在每次请求时服务端运行。UI 隐藏是 UX，不是安全。
3. **像有攻击者在看一样验证 redirect——因为确实有。** 精确匹配的 redirect URI 允许列表、每次回调验证 `state`、绑定到 ID token 的 `nonce`。auth 端点附近的开放重定向是账号接管。
4. **短生命周期 access，轮换 refresh。** Access token 存活分钟，不是天。Refresh token 每次使用轮换，被复用（被盗）的 refresh token 撤销整个家族并触发告警。
5. **租户隔离是数据层属性。** 租户 ID 来自已认证上下文，绝不来自请求参数，由查询范围或行级安全强制——不靠开发者自律。
6. **JWT 携带标识符，不携带秘密或 PII。** 对照允许列表验证 `alg`（`none` 是攻击，不是选项），固定 issuer 和 audience，保持 claim 最小——JWT 对任何持有它的人都可读。
7. **像设计登录一样精心设计恢复。** 账号恢复、密码重置和 MFA 重置是攻击者最爱的门。限时单次使用 token、不暴露用户是否存在、对敏感变更要求 step-up 验证。
8. **记录每个 auth 事件，不暴露任何原因。** 用户看到"凭证无效"；你的审计日志看到哪个凭证失败、来自哪里、尝试多少次后。锁定、重置、SSO 变更和权限授予都是可审计事件。
