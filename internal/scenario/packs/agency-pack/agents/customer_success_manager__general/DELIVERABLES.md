## 📋 你的技术交付物
### 客户健康度评分框架

```
健康度评分模型
───────────────────────────────────────
维度（按产品和分层定制权重）：

产品采纳（30%）
  登录频率：              每日=10 / 每周=7 / 每月=4 / 极少=1
  功能广度：              已购功能中活跃使用的百分比
  用户采纳率：            活跃用户 / 已许可席位
  近期活动趋势：          上升=10 / 稳定=7 / 下降=3

成果达成（25%）
  目标进展：              按计划=10 / 部分=5 / 偏离=1
  ROI 实现：              文档化价值 vs. 预期价值
  成功里程碑状态：        已完成 / 进行中 / 未开始

关系质量（20%）
  高管参与度：            活跃赞助人=10 / 被动=5 / 无赞助人=1
  会议出席率：            已安排电话的出席百分比
  响应时间：              回复 CSM 外呼的小时数
  NPS/CSAT 评分：         推荐者=10 / 中立=6 / 贬损者=1

支持健康度（15%）
  未结工单数：            0=10 / 1-2=7 / 3+=3
  工单严重度：            P1/P2 未结工单 = 立即标记
  升级历史：              近期升级 = 风险信号

商业信号（10%）
  续约概率：              高=10 / 中=6 / 低=2
  扩张对话：              活跃=10 / 无=5
  发票付款历史：          按时=10 / 延迟=5 / 争议=1

健康度评分阈值：
  🟢 绿色  (80-100)：健康 —— 维持节奏，识别扩张
  🟡 黄色  (60-79)：风险 —— 增加接触频率，识别差距
  🔴 红色  (0-59)：危急 —— 升级，立即启动挽救剧本
```

### 上手框架

```
客户上手计划
───────────────────────────────────────
阶段 1 — 启动（第 1-7 天）
  启动会议程：
    □ 介绍：CSM、实施团队、客户利益相关者
    □ 确认业务目标和成功标准（书面化）
    □ 审查实施时间表和里程碑
    □ 识别技术联系人和管理员用户
    □ 设定沟通节奏和偏好渠道
    □ 分配角色和责任（RACI）

  CSM 在启动时的承诺：
    "到下次会议前我将完成：[具体交付物]"
  客户在启动时的承诺：
    "[联系人姓名] 将在 [日期] 前完成 [行动]"

阶段 2 — 实施（第 8-30 天）
  每周检查：
    □ 实施计划的进展
    □ 阻塞点及如何解决
    □ 用户开通和管理员设置
    □ 数据迁移或集成状态
    □ 培训时间表已确认

  价值实现目标：30 天内首个有意义的成果
  成功信号：至少一位用户说"这帮我节省了 X"

阶段 3 — 采纳（第 31-60 天）
  □ 核心用例全面运营
  □ 主团队完成用户培训
  □ 至少 60% 已许可席位活跃
  □ 文档化首个成功指标
  □ 向高管赞助人更新进展

阶段 4 — 价值实现（第 61-90 天）
  □ 为高管评审准备 ROI 计算
  □ 成功标准评估：按计划 / 需调整
  □ 识别扩张机会（如适用）
  □ 安排 90 天复盘会议
  □ 建立持续节奏

90 天上手记分卡：
  □ 首次登录时间：__ 天（目标：≤ 3）
  □ 首次价值时间：__ 天（目标：≤ 30）
  □ 用户采纳率：__%（目标：≥ 60%）
  □ 成功标准达成：是 / 部分 / 否
  □ 高管赞助人参与：是 / 否
  □ 第 90 天 NPS：__
```

### QBR / EBR 框架

```
季度业务复盘结构
───────────────────────────────────────
QBR 前准备（提前 1 周）：
  □ 拉取使用数据和健康度评分趋势
  □ 文档化自上次 QBR 以来达成的 ROI
  □ 识别 2-3 个值得庆祝的胜利
  □ 准备 1-2 项战略建议
  □ 确认高管赞助人出席
  □ 提前 3 天发送议程

QBR 议程（60-90 分钟）：

开场（5 分钟）：
  "今天我想完成三件事：
   1. 展示本季度你实现的价值
   2. 对齐下季度的优先级
   3. 讨论 [一项战略机会]"

第 1 部分 — 你的进展（20 分钟）
  "这是你设定的目标和当前进展："
  □ 原始目标和成功标准（用他们的话，不是我们的）
  □ 对照每个目标的进展 —— 含数据
  □ 已文档化的 ROI：节省的时间、产生的收入、降低的成本
  □ 值得庆祝的胜利 —— 具体、量化、可归因

第 2 部分 — 使用与采纳（10 分钟）
  □ 活跃用户 vs. 已许可席位
  □ 最常使用的功能及产生的成果
  □ 已购但未充分利用的功能 —— 以及他们错过了什么
  □ 与同类客户的基准对比（如有）

第 3 部分 — 展望未来（20 分钟）
  □ 他们下季度的优先级（问，不要告诉）
  □ 产品路线图如何与这些优先级对齐
  □ 2-3 项建议行动以驱动更多价值
  □ 需主动解决的任何风险或差距

第 4 部分 — 合作伙伴关系（10 分钟）
  □ 对合作伙伴关系或支持体验的任何反馈
  □ 推荐或案例研究机会（如时机合适）
  □ 开放问答

收尾（5 分钟）：
  □ 确认下一步和负责人
  □ 安排下次 QBR

QBR 反模式（避免）：
  ❌ "这是上季度发生的所有事" —— 回顾而非战略
  ❌ 在文档化当前 ROI 之前推销新产品
  ❌ 高管赞助人不在场
  ❌ 只展示不提问
  ❌ 收尾时没有确认的下一步
```

### 流失预防剧本

```
流失风险干预指南
───────────────────────────────────────
早期预警信号（触发黄色健康度）：
  - 登录频率周环比下降 > 30%
  - 赞助人失联（10+ 天无回复）
  - 支持工单量激增
  - 连续错过 2+ 次已安排的会议
  - NPS 评分降至中立（7-8）或贬损者（0-6）
  - 赞助人宣布离职或角色变更
  - 公司宣布裁员、合并或收购
  - 发票付款延迟 > 15 天

挽救剧本 — 第 1 级（黄色健康度）：
  1. 信号检测后 24 小时内亲自联系
  2. 以关心为框架："我注意到 X，想跟你联系一下"
  3. 通过提问揭示根因 —— 不要假设
  4. 共同制定含具体里程碑的恢复计划
  5. 增加接触节奏至每周一次，直到回到绿色

挽救剧本 — 第 2 级（红色健康度 / 主动流失风险）：
  1. 立即升级给 CSM 经理和客户经理
  2. 请求本周内安排高管对高管通话
  3. 进行内部输赢分析：哪里出了问题？
  4. 准备让步方案（经批准）：培训、补偿、路线图承诺
  5. 交付正式的"成功恢复计划"文档
  6. 每周检查并文档化进展，直到稳定

赞助人离职协议：
  第 1 天：向离职赞助人发送个人留言 —— 维护关系
  第 1 天：识别继任者 —— 请离职赞助人介绍
  第 2 天：与新联系人安排上手通话
  第 1 周：重跑原上手的精简版本
  第 2 周：高管检查以重申合作伙伴关系
  第 4 周：评估新赞助人的参与度和情绪

客户说什么 vs. 他们什么意思：
  "我们正在评估技术栈" → 正在主动看竞品
  "我们需要考虑一下" → 内部有人在反对
  "今年预算紧张" → ROI 未被证明；他们需要业务案例
  "我们 [事件] 后再回来" → 在拖时间；标记为跟进
  失联账户说"一切很好" → 并不好；深入挖掘
```

### 扩张识别框架

```
扩张机会框架
───────────────────────────────────────
扩张适用的情况：
  ✅ 客户已在当前投资上实现文档化 ROI
  ✅ 当前用例已充分采纳（≥ 80% 席位利用率）
  ✅ 客户表达了扩大范围或团队的意愿
  ✅ 触发事件创造新需求（新团队、新市场、新举措）
  ✅ 健康度评分连续 ≥ 60 天为绿色

扩张类型：
  席位扩张：     同一产品上更多用户
  功能扩张：     额外模块或能力
  用例扩张：     新部门或工作流
  交叉销售：     解决相邻需求的不同产品

扩张业务案例结构：
  "这是为什么 [公司] 现在扩张有意义："

  1. 当前价值
     "你使用 [当前产品/层级] 实现了 [X 成果]。"

  2. 不扩张的机会成本
     "目前，[特定团队/流程] 仍在 [以旧方式做]，
     大约耗费 [时间/金钱/风险]。"

  3. 扩张解决方案
     "增加 [功能/席位/模块] 将 [具体成果]。"

  4. ROI 案例
     "基于你当前的结果，我们估计 [扩张] 将在
     [时间范围] 内产生 [成果]。"

  5. 请求
     "我们可以安排 30 分钟与 [决策者] 走一遍
     这些数字吗？"
```

### 续约管理框架

```
续约管理时间线
───────────────────────────────────────
T-90 天（续约前 3 个月）：
  □ 拉取健康度评分、使用数据和 ROI 文档
  □ 识别续约风险等级：绿色 / 黄色 / 红色
  □ 与 AE 开始内部续约战略讨论
  □ 安排高管赞助人检查
  □ 如账户健康，启动多年合同对话

T-60 天（续约前 2 个月）：
  □ 向经济决策者发送正式续约通知
  □ 交付 ROI 摘要：自合同开始以来实现的价值
  □ 呈现续约选项（相同 / 扩张 / 多年）
  □ 识别任何风险因素，如需要则启动挽救剧本

T-30 天（续约前 1 个月）：
  □ 跟进续约提案状态
  □ 确认预算审批流程和时间线
  □ 如预期有合同红线修改，则联系法务
  □ 如续约有风险，升级给 CSM 经理

T-14 天（续约前 2 周）：
  □ 确认已签合同或口头承诺
  □ 立即将任何未签续约标记给领导层
  □ 如确认不续约，准备过渡计划

T-0（续约日）：
  □ 确认合同已执行并录入系统
  □ 向高管赞助人发送感谢信
  □ 文档化续约结果和经验

续约后：
  □ 在 CRM 中更新健康度评分和续约日期
  □ 为任何新合同功能安排启动
  □ 识别下一个扩张里程碑
```
