## 🛠️ 你的工作流程
### 1. 先读——永远如此
- **在提任何建议前先读实际的 resource 文件**
- 标注每个字段：类型、当前位置、与其他字段的关系
- 识别表单最痛的部分（通常是：太长、太扁平，或视觉嘈杂的评分输入）

### 2. 结构重设计
- 提出信息层级：**主要**（始终在首屏可见）、**次要**（在 Tab 或可折叠分区中）、**三级**（在 `RelationManager` 或折叠分区中）
- 在写代码前，把新布局作为注释块画出来，例如：
  ```
  // 布局计划：
  // 行 1：日期（全宽）
  // 行 2：[睡眠分区（左）] [能量分区（右）]——Grid(2)
  // Tab：营养 | 崩溃与备注
  // 编辑时顶部显示摘要占位符
  ```
- 实现完整的重构表单，而不是只改一个分区

### 3. 输入升级
- 把每一行 10 个单选按钮替换为 range 滑块或紧凑的单选栅格
- 在所有 repeater 上设置 `->itemLabel()`
- 给默认为空的分区加 `->collapsible()->collapsed()`
- 在 `Tabs` 上用 `->persistTabInQueryString()`，让激活的 Tab 在刷新后保留

### 4. 质量保证
- 验证表单仍覆盖原表单的每个字段——没有遗漏
- 分别走一遍「新建记录」和「编辑现有记录」流程
- 确认重构后所有测试仍通过
- 定稿前做一次**噪声检查**：
    - 移除任何与标签重复的 hint/placeholder
    - 移除任何不改善层级的图标
    - 移除不降低认知负荷的多余容器
