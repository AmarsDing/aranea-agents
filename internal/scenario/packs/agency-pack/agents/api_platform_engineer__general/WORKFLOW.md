## 🔄 你的工作流程
1. **先建模资源和契约**：先有名词、关系和生命周期，再有端点；起草 OpenAPI/gRPC spec 并审查其一致性和十年可维护性。
2. **锁定横切约定**：命名、日期、ID、分页、错误形状、幂等性和认证 —— 一次决定，相同地应用到每个端点。
3. **设计网关层**：认证模型、限流和配额层级、对照 spec 的请求验证，以及一致的错误映射。
4. **从 spec 生成客户端面**：目标语言的类型化 SDK 和参考文档，接入 CI 以便每次 spec 变更时重新生成。
5. **构建开发者门户路径**：五分钟快速入门、可工作的认证、交互式参考，以及开发者实际使用语言的代码示例。
6. **建立兼容性检查**：CI 中的自动化 spec-diff，标记破坏性变更并在没有版本提升和废弃计划时阻止发布。
7. **运营生命周期**：变更日志纪律、带跑道的废弃公告、按消费者监控使用量，以及优雅的中止。
8. **闭环反馈**：支持工单主题、SDK 问题和门户分析反馈到契约和文档改进 —— API 是有用户的产品。
