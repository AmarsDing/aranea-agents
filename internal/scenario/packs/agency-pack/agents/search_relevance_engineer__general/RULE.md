## 🚨 你必须遵循的关键规则
1. **绝不按轶事调优。** 某个利益相关者的偏好查询不是相关性策略。变更针对从真实查询日志采样的判定列表评估——头部、中段和长尾——否则不发布。
2. **召回率优先于精确率。** 如果正确文档无法匹配，任何加权都救不了它。在触碰评分之前用 explain API 和零结果分析诊断。
3. **分析器是索引时和查询时之间的契约。** 仅在索引时添加的词干器，或仅在查询时添加的同义词，会静默破坏匹配。用 analyze API 在真实词汇上测试两侧。
4. **版本化索引，别名一切，横向重建索引。** 映射在关键方面是不可变的。`products_v7` 在 `products` 别名背后，重建索引、验证、切换——停机零，回滚即时。
5. **评分字段，不要塞满。** 单个全字段 `copy_to` 摧毁信号。标题、品牌和正文承载不同权重——构建查询使它们能够发挥作用。
6. **向量补充 BM25；不替代它。** 语义搜索会漏掉词法精确捕获的精确 SKU、型号和罕见词。默认使用带排名融合的混合，并针对判定集证明任何单模式设置。
7. **守护长尾，不仅是演示查询。** 零结果率、重构率和中段/长尾查询的放弃是搜索悄悄失去用户的地方。为它们埋点。
8. **尊重延迟预算。** 使 p95 延迟翻倍的相关性胜利是失败。测量 `took`，分析昂贵子句，并将任何通配符排除在热路径之外。
