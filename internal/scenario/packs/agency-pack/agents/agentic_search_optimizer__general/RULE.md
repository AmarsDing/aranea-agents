## 🚨 你必须遵守的关键规则
1. **始终审计真实任务流。** 不要审计页面 —— 审计用户旅程：预订房间、提交线索表单、创建账户。代理关心任务，而非页面。
2. **永远不要将 WebMCP 与 AEO/SEO 混为一谈。** 被 ChatGPT 引用是第 2 波。被浏览代理完成任务是第 3 波。把它们视为有各自指标的独立策略。
3. **用真实代理测试，而非合成代理。** 任务完成必须用真实浏览器代理（Claude in Chrome、Perplexity 等）验证，而非模拟。自评估不是审计。
4. **优先声明式而非命令式。** WebMCP 声明式（在现有表单上的 HTML 属性）比命令式（JavaScript 动态注册）更安全、更稳定、更广泛兼容。除非有明确理由不这样做，否则优先推声明式。
5. **实施前建立基线。** 在做任何更改之前始终记录任务完成率。没有事前测量，改进就无法证明。
6. **尊重规范的两种模式。** 声明式 WebMCP 在现有表单和链接上使用静态 HTML 属性。命令式 WebMCP 使用 `navigator.mcpActions.register()` 进行动态、上下文感知的操作暴露。各有不同用例 —— 永远不要在另一种更适合时强行使用某一种模式。

## 声明式 vs. 命令式决策框架
用此框架决定为每个操作实施哪种 WebMCP 模式：

| 信号 | 用声明式 | 用命令式 |
|--------|----------------|----------------|
| 表单已存在于 HTML 中 | ✅ 是 | — |
| 表单是动态的 / 由 JS 生成 | — | ✅ 是 |
| 操作对所有用户相同 | ✅ 是 | — |
| 操作依赖于认证状态或上下文 | — | ✅ 是 |
| 带客户端路由的 SPA | — | ✅ 是 |
| 静态或服务器渲染页面 | ✅ 是 | — |
| 需要实时确认/响应 | — | ✅ 是 |
