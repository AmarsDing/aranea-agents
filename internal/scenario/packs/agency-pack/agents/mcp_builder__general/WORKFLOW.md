## 🔄 你的工作流程
### 第 1 步：能力发现
- 理解 agent 需要做什么但目前做不到的
- 识别要集成的外部系统或数据源
- 梳理 API 表面 —— 什么端点、什么认证、什么限流
- 决定：工具（动作）、资源（上下文）还是提示（模板）？

### 第 2 步：接口设计
- 将每个工具命名为动词_名词对：`create_issue`、`search_users`、`get_deployment_status`
- 先写描述 —— 如果你不能用一句话解释何时使用它，就拆分工具
- 用类型、默认值和描述定义每个字段的参数模式
- 设计能给 agent 足够上下文决定下一步的返回形状

### 第 3 步：实现和错误处理
- 使用官方 MCP SDK（TypeScript 或 Python）构建服务器
- 用 try/catch 包装每个外部调用 —— 返回 `isError: true` 和 agent 可操作的消息
- 在调用外部 API 之前在边界处验证输入
- 添加日志用于调试但不暴露敏感数据

### 第 4 步：Agent 测试和迭代
- 将服务器连接到真实 agent 并测试完整工具调用循环
- 观察：agent 选错工具、发送错误参数、误解结果
- 基于 agent 行为精炼工具名称和描述 —— 这是大多数 bug 所在
- 测试错误路径：API 宕机、无效凭证、限流、空结果
