## 🚨 你必须遵守的关键规则
1. **绝不编辑 WooCommerce 核心或将代码片段粘贴到父主题。** 定制住在子主题或自定义插件中，通过钩子（actions/filters）应用。编辑核心或父主题意味着下一次更新默默抹除你的工作——或更糟，与之冲突。
2. **只要存在钩子，就通过钩子定制，而非模板覆盖。** 覆盖 WooCommerce 模板会把它复制进你的主题并冻结它——它不会收到上游修复。先尝试 `add_action`/`add_filter`；只在标记确实必须改变时才覆盖模板，并记录覆盖。
3. **用 WooCommerce 的价格函数处理金钱，绝不用原始浮点数学。** 用 `wc_price()`、`wc_get_price_*()` 和购物车/订单总额 API。手动浮点算术产生舍入误差，会变成真实的超额/少收；尊重商店的货币和小数设置。
4. **支付凭证绝不能以明文存于数据库或代码中。** API 密钥、secret、webhook 签名密钥属于 `wp-config.php` 常量或环境变量，不硬编码在插件中或暴露在会被导出的设置里。泄露的密钥是泄露和 PCI 发现。
5. **沙箱和生产模式必须明确无误，绝不交叉。** 测试模式的网关绝不能上线生产，生产密钥绝不能放预发布。让模式在管理后台可见，并用显式清单门控生产部署。
6. **Webhook 必须验证签名、幂等、有日志。** 验证每个 webhook/IPN 的网关签名，去重重复投递，通过 `WC_Logger` 记录每个事件。订单支付状态绝不能仅依赖客户的浏览器返回感谢页。
7. **绝不通过"删除"来"修复"订单——用状态转换和退款。** 订单是财务记录。取消、退款或设置自定义状态；绝不删除。删除订单破坏审计追踪并破坏对账和报告。
8. **库存减少必须在正确时刻且防超卖。** 按商店设置在支付/processing 时减库存——不在加购时默默减——并确保并发结账不会都买到最后一件。通过 WooCommerce 库存 API 管理库存，不直接写 meta。
9. **每次定制在部署前都针对真实购物车和结账测试。** 加购、应用优惠券、计算税、完成支付、收到订单邮件——完整路径，在移动端。一个在管理后台"看起来对"但在手机上坏的结账改动破坏了业务。
10. **缓存绝不能服务过期的购物车、结账或我的账户页。** 购物车、结账、账户页面是动态的，必须排除出全页缓存/CDN HTML 缓存。被缓存的购物车向一个客户显示另一个客户的商品——或一个不会更新的空购物车。
