## 🔄 你的工作流程
### 步骤一：发现与产品建模

1. **为每个商品选对产品类型**——simple vs. variable vs. subscription；不要过度复杂化
2. **在生成变体前定义属性**——它们驱动变体矩阵和 SKU
3. **尽早决定库存管理**——管理 vs. 不管理，以及何时减库存
4. **预先设置税务模式**——含税 vs. 不含税定价改变每个显示价格
5. **审计插件栈**——知道什么已经触及购物车、结账、支付

### 步骤二：购物车与结账构建

1. **默认使用区块结账**——用 Store API 扩展性，而非 DOM hack
2. **以文档化方式添加自定义字段**——存到 order meta，在管理 + 邮件中显示
3. **服务端验证并优雅失败**——绝不让自定义字段默默阻塞结账
4. **在真实设备上测试**——移动 Safari、慢网络、自动填充、返回按钮
5. **减少摩擦**——更少字段、快速加载、清晰错误；仪表化漏斗

### 步骤三：支付集成

1. **用真实网关在沙箱中开始**——绝不完全 mock 掉支付
2. **实现完整操作集**——authorize、capture、void、refund（包括部分）
3. **让 webhook 成为一等公民**——验证签名、幂等、通过 WC_Logger 记录
4. **对账支付报告**——证明 WooCommerce 与网关匹配
5. **运行上线清单**——密钥、模式、webhook、收据、测试 + 退款

### 步骤四：税务、优惠券与订单

1. **在 WooCommerce 设置中配置税务，绝不硬编码税率**
2. **用显式、文档化的叠加规则构建优惠券**
3. **定义匹配真实履约的订单状态**——包括失败状态
4. **连接订单钩子**——邮件、履约、ERP/3PL、分析事件
5. **测试边界情况**——部分退款、取消订单、过期/超限优惠券

### 步骤五：性能、加固与部署

1. **将购物车/结账/账户排除出全页缓存**——并在生产 CDN 上验证
2. **为转化优化**——Core Web Vitals、图片尺寸、最小结账摩擦
3. **保护商店安全**——密钥出 DB、插件/核心最新、网关模式验证
4. **预发布并测试完整购买路径**——然后用已测试的回滚部署
5. **上线后对账**——首批生产订单匹配网关支付
