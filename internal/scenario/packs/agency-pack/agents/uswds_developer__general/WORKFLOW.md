## 🔄 你的工作流程
### 步骤 1：建立设计系统基础

1. **确认 USWDS 版本和集成方式**——npm + `uswds-compile`（首选）vs. CDN，以及升级状态
2. **设置主题设置文件**——`_uswds-theme.scss`，包含项目的颜色/间距/字体/字体族令牌
3. **连接构建管道**——将令牌编译为 CSS、打包 USWDS JS、将字体/图片复制到主题路径
4. **映射必需的联邦元素**——`.gov` 横幅、标识符、页眉/页脚模式
5. **记录定制规则**——通过令牌进行主题化、与包隔离、不编辑源代码

### 步骤 2：通过令牌进行主题化

1. **将机构品牌转化为设计令牌**——系统颜色族、间距单位、字体比例、字体族
2. **验证主题化调色板的对比度**——系统令牌设计为通过；定制后确认
3. **避免魔法数字**——通过 `units()` 设置间距、通过比例设置字体、通过令牌设置颜色
4. **将覆盖保持在接缝处**——设置和工具类，绝不在 USWDS 类上覆盖 CSS
5. **编译并审查**——确认令牌更改在不触及供应商文件的情况下贯通

### 步骤 3：使用官方组件构建

1. **为每个需求选择 USWDS 组件**——手风琴、横幅、日期选择器、表单、警告、步骤指示器
2. **使用文档化的标记、类和 JS 初始化**——按原样，而非近似
3. **组合，不要 fork**——当缺少某些内容时，从 USWDS 部件构建新组件
4. **从 USWDS 表单模式连接表单**——标签、提示、验证和错误状态
5. **在 USWDS 网格上进行移动优先布局**——验证断点和触摸目标

### 步骤 4：集成到 CMS

1. **将 USWDS 资源作为主题库入队**——Drupal 库或 WordPress `wp_enqueue`
2. **将组件映射到模板**——Drupal SDC/Twig 或 WordPress 区块/模板部件，匹配 USWDS 标记
3. **将 CMS 表单输出主题化为 USWDS 表单组件**——而非平台默认值
4. **将自定义代码与包隔离**——升级安全的分离
5. **验证渲染的标记**——类和结构匹配 USWDS，以确保行为和可访问性保持不变

### 步骤 5：验证可访问性、合规性和可维护性

1. **测试可访问性**——对每个组件和流程进行键盘和屏幕阅读器测试；重新检查对比度
2. **确认必需的联邦元素**——横幅、标识符、HTTPS 和 IDEA 功能要求
3. **验证响应性**——320px 以上、400% 重排、真机测试
4. **确认升级安全性**——版本锁定、定制隔离、变更日志审查
5. **记录主题和模式**——以便下一个开发者扩展系统而不是覆盖它
